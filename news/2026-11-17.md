## 💡 今日点评

今天三条线，其实都在讲同一个词：**信任**。

**第一条，你信任的第三方，正在替你决定看到什么、跑什么。** Optimizely 这件事的正确读法不是"178 家大站被黑"，而是**没有一家被黑**——被黑的是它们共同依赖的一个实验平台，然后恶意代码顺着"可信域名"流进了 178 个站点的用户浏览器。Report URI 那句总结值得抄下来："可信的 JavaScript 不会永远可信。" 同样逻辑的另一半在 Windows 遥测那条里：你的操作系统把你用了 codex 还是 claude 当成一类要统计的数据。**两件事合起来就是今天的现实——你的发布链路不只属于你，你的工具选择也不只属于你。** 对我们的实际动作很具体：外链脚本、CDN、`pip`/`npm` 依赖、Agent skill 包，凡是"别人能改而我天天在跑"的东西，都该有版本锁定 + 完整性校验 + 变更告警；昨天 Bitly 那件事、今天 Optimizely 这件事，是同一个教训隔了一天再来敲门。

**第二条，agent 生态的重心在从"更聪明"转向"能被审、能被评、能被收回来"。** 今天 Trending 前五：univer（让 agent 住进文档）、open-code-review（规则与模型分工）、NVIDIA/SkillEvaluator（评估技能本身）、chrome-devtools-mcp（让 agent 真能调试）、claude-trading-skills（技能包进高门槛领域）。再加 HN 上那个 OpenCode Browse：agent 借你的真实浏览器干活，**但登录、双因素、付款一定交回给你，你点"继续"它才动**。这几个项目放在一起，图纸已经很清楚：不是让 agent 做更多，而是把"哪些必须等人点头"做成协议级的设计。这对我们待建的 mcp 服务器几乎是现成的参考——先定人工闸门和可审计日志，再谈自动化能力；`rp_server` 那边同理：`AT+HEAD=<pan>,<tilt>` 这类会动真东西的指令，谁发的、发了几次、有没有超限，得留痕。

**第三条，AI 让"证明"变便宜了，于是瓶颈换到了别处。** 同一天 HN 首页上，Harmonic 宣布 Aristotle 支持 Rust 形式化验证（用证明代替测试），紧接着是一篇泼冷水的《形式化验证无法被验证》：证明工具链本身可信吗？规范写对了吗？——**当"写证明"不再是瓶颈，"该证明什么"和"凭什么相信这个证明"就变成了瓶颈。** 这和 CMU 免费送课是同一个结构：视频随便看，最难送的是批改和反馈；证明随便写，最难的是判定它有意义。AI 时代稀缺的东西，正从"能不能做出来"转向"有没有人负责判定它对不对"。而今天第三条暗线——美联航和摩根大通同一天各断一次，微软邮箱故障被归因于自己的修复——提醒我们最后一个事实：**大多数事故不是被打败，是被自己改坏的。** 上线前那句"这次改动会影响什么"，比任何一句"我们做了严格测试"都顶用。

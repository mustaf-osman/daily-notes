## 💡 今日点评

今天 HN 前十里有三条指向同一件事，只是刻度完全不同。**最高分那篇（1985 分）说：AI 正在成批解决数学与理论计算机科学里几十年的公开问题，从 ω=9/4 到 FFT 的门数下界，答案开始"被直接给出"而不是"被一点点照亮"。** 而同一张榜单上，另一篇（271 分）用对战数据说：面向大众的新版 GPT 被调成了省钱模式，推理量显著下降、成了"思考不足的离群点"。第三条是 Google 的 Workspace MCP 条款，把 agent 能做什么、能记多久收进自家闸门。

**把这三条叠起来，趋势其实很直白：模型能力的上限还在被疯狂推高，但产品默认值和平台规则正朝相反方向收紧。** 对普通人来说，你每天用到的那一档模型可能正在变"省"；对企业 agent 来说，"能做什么"不再由模型能力决定，而由平台条款决定——Gmail 的公开 MCP 服务器连发信都不给，就是最直白的演示。**评价一个模型，从此要问三个问题：它的天花板在哪、它默认跑在几档、以及它被允许碰哪些数据。**

GitHub Trending 是这件事的镜像：前几名依然全是 agent 技能包和框架（漏洞挖掘、GUI 转 CLI、文章综述、数据抓取），**加上一个挺有意思的对照——一个教你"两小时从零训 64M 模型"的中文小项目还在拿星。** 一头是别人帮你把能力打包送到手边，另一头是有人坚持自己从零训一遍。这两拨人可能会在同一张办公桌前坐下，但学到的东西不一样。

最后给做工程的人一句具体的：今天最该动手看的是 llama.cpp 那个 AMD 分支。它给"AI 狂写推理引擎"这波热潮加了一条判据——**优化硬件是本事，把模型改得"因为想得少所以显得快"是耍赖。** 今后拿到任何一个号称"提速"的引擎，先问一句：它变快的这部分，是硬件红利，还是模型少想了几步。

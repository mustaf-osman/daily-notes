- [OmniDiff：一个懂内容的 Git diff 工具，Rust 写的](https://github.com/ivankovic/omnidiff) — 157 分、41 条评论。传统 diff 是按行比的，改一个变量名会显示整行删掉再加一行；OmniDiff 对代码走语法感知的比对，只标出真正变的那几个字符。它给的数字挺硬：能处理 99.95% 的代码变更，其中 98.8% 走到了内容专用算法；代码类在 100ms 内完成的比例 98%，结果"完全正确"70%、"接近正确"92%。字体、图片、PDF、压缩包、翻译词条也各有专用路径。作者还做了个网页 showcase，左右分屏实时对比 GNU diff 和它自己的输出——这种"让人一眼看懂差别"的演示，比任何 benchmark 表都有说服力。

- [Nibnib：为极快解压而生的图像格式](https://github.com/raphlinus/nibnib) — 92 分、13 条评论，今天技术上最漂亮的一条。出处是一个很具体的约束：RP2350 这类单片机做 DVI 输出，每像素只有大约 6 个周期的预算，够取一次像素、查一次调色板、存进行缓冲，没有余量。raphlinus（Rust 图形与 GPU 圈的老手）的解法是把调色板存成"增量"而不是绝对颜色：每次读一个字节查表得到两个 16 位色差，加到上一对像素上，**一个字节出两个像素（4bpp）**，内层循环只有四行 Rust。解码是确定性的一遍扫，编码则是巨型搜索、慢好几个数量级——典型的不对称设计。

## 💡 今日点评

**今天最值得记的不是任何单个项目，而是"AI 故事"的两端同时松动了：供给端在狂奔，受益端在打哈欠。**

一边是工具层：Karpathy 用两小时复刻了一个视频站，T3 Code 一天涨三千星，OmniDiff 把 diff 做到了字符级。写软件的成本正以肉眼可见的速度趋近于零。另一边是阿波罗那份"S&P 493 利润率平坦"的结论，和一万条市政评论里"73% 的听证会没有一个支持者"。两件事其实是同一个现象的两面：**能力变便宜了，但把能力变成收入和变成社会许可，这两步一步都没变快**。Slok 那句"AI 是很好的计算器，但商业里的智能主要是判断力"，说的就是这一步——判断力、问责、信任这些东西没法通过 API 调用。

这也解释了为什么今天趋势榜上五个项目里有四个是"怎么驾驶智能体"，而不是"更强的模型"：t3code 管远程驾驶，claude-mem 管记忆，lightpanda 管感知，Game-Studios 管分工。模型能力已经溢出到用不完，**稀缺的是把它接到真实流程上的那层胶水**。同理，Postgres 19 延期的原因也不是 AI 写坏了代码，而是 AI 审查太快、找出的人修不完——工具变强之后，瓶颈原封不动地转移到了人的吞吐量上。

两个跟手上活儿直接相关的点。第一，Nibnib 值得单独看：一个字节两个像素、每像素六个周期，这种把预算算到骨头里的设计，跟"让模型帮我写个页面"是两个世界。做 PMIC、做双足人形的控制链，约束从来不是模型聪不聪明，而是 RAM 剩多少、CAN 总线还剩多少带宽、中断里能不能塞下这段代码。AI 让软件变便宜，但**没有让一个 bit 变便宜**。第二，Calegari 那篇的立场可以照搬到工程上：比起争论"AI 行不行"，不如去改自己能控制的那三件事——招谁、怎么评审、怎么带人。对一个团队来说，这大概就是"代码评审标准、发布门槛、谁负责按确认键"。

- [Java4Shell：OpenJDK 的 Base64 解码器存在内存破坏漏洞，可无凭证 RCE（505 分）](https://calif.io/java4shell/) — 编号 CVE-2026-114938，CVSS 4.0 打 **9.2（严重）**。OpenJDK 为了把 Base64 解得更快，用了 x86-64 的专用指令一次处理多个字节，**而这段手写优化的机器码里有个越界写**，畸形输入就能改写相邻内存。触发串短到离谱：**64 个 A 加一个等号**（旧版 OpenJDK 17 是 128 个 A 加等号）。后果两种：像 Heartbleed 那样把敏感内存读出来，或者一路打到远程代码执行。作者实测的默认配置下**预认证 RCE** 名单很扎眼：Keycloak、Atlassian Jira、Confluence、JFrog Artifactory、Jenkins、PingFederate；认证后 RCE 则有 Kafka Broker、Solr、Elasticsearch、Gerrit、Spinnaker。作者正是上次那个搞出 PHP2Shell 的团队，行文风格一如既往地挑衅（章节名直接叫"半人马黑客的时代"、"公地悲剧"、"呼吁 vibe-uncoding"）。**这事的价值不在漏洞本身，而在于它证明了两件事：Java 也会有内存破坏，而且它最爱出在"为了快而手写的那一层"。**

## 💡 今日点评

今天首页有一半的条目，讲的是同一件事的两面：**便宜**和**不敢让它便宜**。

一面是价格。OpenAI 和微软在同一天发模型，卖的都不是"我最强"，而是"同样的活我能用更少的钱和更少的 token 干完"：Astra 每任务成本不到上一代三分之一、Sol 以五分之一成本咬住旗舰、MAI Code 2 声称拿下 Opus 5.5 的 96% 性能只要 5% 的钱。**前沿模型的价值锚点已经从"榜首分数"移到了"每完成一个任务的成本"**，这直接改变的是 agent 的可行性——单位成本降五倍，"让 agent 24 小时跑"才从口号变成算术题。而价格战的另一面，OpenAI 自己写在了发布说明里：能力涨得最快的方向是网络攻防（ExploitBench 涨 22 分），所以**这两个模型是带着更严的护栏发出来的，最强的能力被最紧地捆住**。这不是公关话术，这是行业开始承认"能力和风险同一条曲线"。

第二面是今天真正的主线：**一串看起来很不一样的事故，全都出在"被人为优化过的那一层"，或者"被人为判定为不重要"的那一层。** OpenJDK 为了把 Base64 解快而手写的 SIMD 机器码里藏着越界写，CVSS 9.2，触发串只是 64 个 A 加一个等号，直接命中的是 Keycloak、Jira、Confluence、Jenkins 这些企业认证与构建的必经之路；jQuery 为了选择器跑得快写了个正则，代价是标签页能被卡死两分钟，修复只改了字符类里六个字符；NSA 的机密内网、上周的空管系统和微软邮箱，官方解释分别是"例行维护"和"一次修复引入的缺陷"。**把这四条并排读，失效模式是同构的：不是被攻破，是被自己"为了更快、为了修别的"改动弄坏的。** 对我们手上的东西（rk3588 上的 rp_server、几台真机、一堆写死的配置和 DNS）具体结论只有一条：凡是"优化过的热路径"和"自动跑的更新"，都要能被回退、被观察、被限制爆炸半径——`AT+HEAD` 那种会动真东西的指令尤其如此。

第三面是所有权。ONNX Runtime 一个 22k star 的生产依赖，在毫无通知的情况下从 GitHub 上消失（pip 还能装，源码没了，评测流水线当天就开始失败）；Quad9 因为不肯把递归 DNS 变成审查工具，干脆退出法国——**它拒绝的两条路，一条是把法国法律输出到全世界，一条是用 geoIP 猜国籍，而后者在德国案的记录是"被判藐视法庭"**；Apple 把 28 年的用户互助论坛关掉，是 Archive Team 拿着容器在最后三天抢救 268 万条帖子；jQuery 用一次"送别"把 3.x 送进只修安全问题的维护状态。**这四件事的共同句式是："这东西一直是我的依赖，但从来不是我能决定的。"** 昨天是 Optimizely 把恶意脚本顺着可信域名送进 178 家站点，今天是依赖仓库直接消失——供应链的教训隔一天换个入口再来一次。

最后补一条容易被忽略的：谷歌的 AI 摘要让外部点击少四成，而 GEO 拿不出补救办法，AI 助手一共只带来 0.3% 的流量。**这意味着"被写进答案"和"被人访问"正式分家了**——你的内容可以既被 AI 引用、又几乎没有人来。对每天要产出内容的人来说，这比价格战重要得多：**能被人搜到，不等于能被人读到。**

今天如果要挑一件最该马上查的事：**Java4Shell——去问一下你信任的那套 Java 服务（认证、CI、制品库）的 OpenJDK 版本，以及能不能先按"Base64 解码"这一层做流量侧的异常拦截。**

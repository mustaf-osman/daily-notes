- [把 284B 的 DeepSeek-V4-Flash 塞进 64GB 内存，纯 CPU 零显卡，362 分](https://github.com/synchopate/llama-modchip) — 开源项目 llama-modchip v2.1 放出了实测数字：通过二阶 Hessian 压缩、自定义 AVX2/AVX-512 内核、2MB HugePages 与改写过的 FlashAttention，把 30B～284B 的稀疏 MoE 模型压进普通 DDR5——同一份权重从 76.87 GiB 降到 56.56 GiB（-26.4%），进程实际占用 57.61 GiB；解码 9.1～14.7 tok/s，提示词处理从 25.05 提到 44.36 tok/s，配置 256K 上下文。README 自己承认瓶颈变成了内存带宽和磁盘速度，"Token 秒在本机跑，已经不是租卡才能做的事"。**MoE 每步只激活一小部分参数的特性，正把大模型的落地门槛从显存搬到内存**——这对任何没有 GPU 的边缘设备都是好消息。

- [拖拽交互不用写动画了：UIST 2026 最佳论文"声明式拖拽"，338 分](https://declarative-dragging.github.io/) — 华盛顿大学的三位研究者把问题反过来：你不再描述拖拽时的几何和动画，而是**声明"把元素拖到哪些未来状态"**；引擎把这些状态投机渲染成视图树，取出被拖元素在每种渲染里的位置，用它们合成一整套拖放交互；再用可组合算子叠加悬浮、吸附、过渡，实现在 SVG 库 [Dragology](https://github.com/declarative-dragging/dragology) 里。演示涵盖代数式改写、贝塞尔曲线操纵、牌堆、编织可视化。为什么值得看：评论区有人点破了它和 agent 的关系——**多模态模型能截图看几个静帧，却判断不了"手腕快速移动时嵌套置放区会怎么反应"这种手感**，所以让 agent 写交互界面的前提，是把交互行为变成可推导的确定性基础，而不是一堆手调参数。

- [写作是思考的工具，而模型不会替你思考，278 分](http://muratbuffalo.blogspot.com/2026/11/writing-as-thinking-tool.html) — 分布式系统研究者 Murat 引了一段很硬的论证（Manuel Blum 给研究生的话）：有限自动机和图灵机唯一的差别，是后者有纸和笔——**把你手里的笔拿走，你就降级了一个复杂度类**。他把写作类比成"外存执行"：把思维卸载到纸上，才能想比脑袋容纳量更大的问题（他举例：读论文时以为懂了，坐下来写评审才发现只懂了 60%）。落到 LLM 上他的结论很直接：一个优化下一个 token 概率的模型不会替你做思考，你要是把笔交给它，思考就没发生——**在大家把思考调低、变成生成文本的肉代理的时代，还自己写的人反而拿到了比较优势，而且这个优势在变宽**。五条规则朴素到好笑：先乱写、再狠删、写平实、不为读者写、按计划写。

- [Outlook.com 悄悄开始拒收没有 DMARC 记录的域名来信，240 分](https://mailroute.net/blog/outlook-rejecting-email-without-dmarc) — 时间线很清楚：MailRoute 5 日在自己的出站日志里发现退信，mailop 邮件列表 6 日对账，Spamresource 7 日复现。报错是 `550 5.7.1 Message rejected: Message lacks SPF/DKIM/DMARC Auth Records (AS9031519)`——**即使 SPF 和 DKIM 都通过并且对齐**，只要域名（或它的父域）没有 DMARC 记录就会被拒，影响 outlook.com / hotmail.com / live.com / msn.com 的收件人。这跟微软公开宣布过的"每天 5000 封以上批量发信者"规则（5.7.515）不是一回事：这一轮打到了小发信者，而且微软至今没发公告。修复只要一条 `_dmarc` 的 TXT 记录，`v=DMARC1; p=none` 就够（父域有记录也行）。测试里还有个反直觉结论：**DMARC 只决定"收不收"，不决定"进不进垃圾箱"**——同一批记录、同一分钟发出的两个子域，落点是按发信人（IP 历史/签名习惯）分的。受影响最重的是依赖个人邮箱收发业务的一方：医院、学校、小企业，退信和"消息从未发出"双方都不知道。

## 💡 今日点评

**今天 HN 前十条里有五条在讲同一件事：agent 的账，开始有人来结了。**

把它们排在一起看会非常清楚。高盛把编码代理从交易员手里收回（**谁对 agent 写的代码负责**）；Claude Code 的"别再问我了"把明文凭据推进公开仓库（**权限开关一旦默认打开，风险就从"可能"变成"迟早"**）；Claude Code 一年 244 个版本、四分之三改系统提示词，逼着一部分用户开始评估"这个外壳可不可预期"（**依赖管理从库扩展到了工作流**）；AI 脑糊那条说人类这根审批总线只能并行约四个任务（**人的带宽有硬上限**）；而 Nvidia 那条 —— 一次人际关系的失误演变成董事会独立调查和"外国情报行动"级别的国安议题（**在最高权力节点上，个人行为就是公司风险**）。这五条没有一条在争论模型分数。

在这条主线之外，还有一条安静但更根本的线：**能力在往下沉，沉到单机、沉到本地、沉到一个人的时间。** llama-modchip 用 26% 的压缩率、自定义 AVX-512 内核和 HugePages，把 284B 的稀疏 MoE 压进 64GB 普通内存，纯 CPU 跑到 9～15 tok/s——它真正的意义不是"省了显卡"，而是把"能不能跑前沿模型"这件事和 GPU 供给解耦了。Dux 用 Quickshell + Go 重做一个桌面，KetchUp 用 Rust + WebGPU 重做一个建模工具，两者的对手一个是集成商拼装的桌面，一个是订阅制的老牌商业软件。三个项目的共同点是：**由很少的人在很短时间里，把过去需要团队和资本才能做的事情做出来**。

我的判断：今年真正拉开差距的不是模型分数，是**审计面**——谁动的、动了什么、事后能不能一条条查回来。凡是把确认变成永久免检、把凭据写进日志、把规则变更悄悄上线的，都会在今年被一条新闻点一次名。对做机器人的我来说这条特别具体：rp_server 这条链现在还没接大模型，但只要哪天把自然语言接进来，第一件要补的不是意图识别，而是权限边界、审计日志和凭据隔离——谁能下发指令、下发前要不要人工确认、每个动作有没有落盘、配置文件会不会被顺手提交。今天高盛和 Claude Code 那两条，说的就是这三件事的反面教材。而 llama-modchip 给的是另一半答案：一份能在 64GB 内存里跑的本地模型，意味着**有些环节根本不必把数据送出去**——不联网，也就没有那半个审计问题。

还有一条提醒给所有人：Outlook 那条说明基础设施的门槛在无声上移。你什么都没改、代码一行没动，邮件已经开始被拒，而微软连公告都没发。平台规则变更的成本，最后总是落在最小的那一方（这次是医院、学校和小企业）。下午花五分钟给自己的域名加一条 `_dmarc` 的 TXT（`v=DMARC1; p=none`）——它今天只是把你从"被拒"挪回"被收"，同时也为将来切到 `p=reject` 铺好路；顺带查一下那些只发交易邮件的子域（工单系统、老品牌、第三方服务），它们最可能是"SPF/DKIM 有、DMARC 没有"的那一类。

最后留一句给 Murat 那篇。他用了一条很硬的类比：有限自动机和图灵机的唯一区别是后者有纸和笔——**把笔拿走，你就降级了一个复杂度类**。今天所有"结账"的新闻都在问同一个问题的反面：你把笔交给 agent 之后，谁还记得自己在想什么。

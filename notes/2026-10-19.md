## 💭 技术随想：Flash 只能把 1 写成 0——改一个参数，为什么要擦掉整个扇区

上周给板子加"保存零点偏移"的功能，需求简单到不值一提：算出一个 float，存进 flash，下次上电读回来。

第一版代码写得很顺手：找到地址，把 4 个字节写进去。烧录、上电、读回——一个毫不相干的数。

不是指针写错，也不是驱动写错。是我脑子里的模型错了：我一直把 flash 当成"掉电不丢的 RAM"，而它其实更像**一块只能往下写、整块才能重来的石板**。

### 一、一条反着来的规则：位只能从 1 变成 0

RAM 的世界里，一个字节随时可以是 0x00 到 0xFF 之间的任何值。flash 的世界里没有这个自由：

- 擦除之后，所有位都是 1（一个字节 = 0xFF）；
- **program（写）只能把 1 变成 0**，不能把 0 变回 1；
- 想让位回到 1，唯一的办法是**擦除整个扇区**，让一大片区域一起回到 0xFF。

物理上，每个 bit 是一个浮栅 MOS 管。写（program）时加高电场，把电子注进浮栅——有电子代表 0；擦除（erase）时反向加高压，把电子从浮栅里抽走——没电子代表 1。**注入可以逐位挑着做，抽取却只能整片一起做**，因为擦除的高压加在整个阱（well）上，没法只对准某一个字节。

实验 A 把这条规则演了一遍。擦除态 0xFF：

```text
第1步 写 0xAA        FF → AA   1→0 的位，按请求写下去了
第2步 想写回 0xFF    AA → AA   0→1 的位被物理拒绝：旧值原样保留
第3步 再写 0x55      AA → 00   0xAA & 0x55 = 0x00：新数据把剩下的 1 也抹了
```

第 2 步和第 3 步，一共 8 个"想置 1"的位被静默吞掉。没有异常、没有返回值、没有日志——**flash 不会拒绝你，它只会忠实地执行"按位与"**。这是整件事最坑的地方：它不报错，它写进去一个"合法但错误"的值。

顺着这条规则，还有个冷门用法：既然位只能单向变少，同一个字节就可以反复"往下写"——从 0xFF 一路写到 0x00，一共记了 8 件事（每一位代表一次事件），**一次擦除都没做**。一个 256 字节的扇区有 2048 个位，就能记 2048 次事件。代价是只能表达"又发生了一次"，不能表达具体数值。有些芯片的掉电计数器就是这么做的：寿命不成问题，因为压根不擦。

### 二、改一个字节，为什么这么贵

实验 B 是真实的翻车现场。扇区里存两个开关：mode = 1，level = 1。现在想把 mode 改成 2。

最直觉的做法是往同一个地址再写一次 2：

```text
写 2 → 读回 0   （0x01 & 0x02 = 0x00）
```

不是 2，也不是 1，是 0。因为 0x01 和 0x02 没有一个共同的 1 位，按位与之后什么都不剩。**在 flash 上，"覆盖写"在物理上不存在，只有"把某些 1 拉成 0"。**

正确流程只有一条：读—改—擦—写。

1. 把整个扇区读到 RAM；
2. 在 RAM 里改那个字节；
3. 擦除整个扇区（整块回到 0xFF）；
4. 把 256 字节全部写回去。

实验里改一个字节的账单：4 次 program、1 次 erase。而且第 3 步一执行，旁边的 level 也一起变成 0xFF——它是靠 RAM 里的副本活下来的。**这就是为什么"保存配置"从来不是"写 4 个字节"，而是"搬一整个扇区"。**

真实器件的比例更难看：NOR flash 擦除的最小单位是扇区（常见 4KB），驱动通常按页写（256B 左右）。写一页通常几百微秒到几毫秒，擦一个 4KB 扇区要几十毫秒，大扇区甚至到秒级——**差两个数量级**。更麻烦的是，代码常常就在同一块 flash 上执行（XiP），擦除期间 CPU 取指会被挂起；除非器件是双 bank，能从另一块继续跑，代价是容量和复杂度。对一个 1kHz 的电机控制环来说，一次 50ms 的擦除就是 50 个控制周期——足够让机器人抖一下。

### 三、于是所有 flash 存储都在做同一件事：别原地改

既然原地改的代价是"擦一整块"，工程上的答案就很统一：**把更新变成追加，把擦除攒起来**。

常见三种：

- **双备份 + 序号 + CRC**：A/B 两个扇区轮流写，写完新的、校验通过，再把旧的作废。掉电最多丢一次更新，永远有一份完整的旧数据。
- **日志式（append-only）+ 压缩（compaction）**：每次更新往后追加一条记录，写满了再把"每个 key 的最新值"搬到另一个扇区，擦掉旧扇区。
- **磨损均衡（wear leveling）**：把写分散到不同扇区/块，别盯着同一块擦。

实验 C 拿日志式跟"原地改"对比。256 字节扇区，一条记录 8 字节（2 字节序号 + 1 字节 key + 4 字节值 + 1 字节 CRC），一扇区装 32 条。同一个 key 改 200 次：

- 原地改：200 次更新 → 200 次擦除；
- 日志式：221 次 program、6 次压缩、12 次擦除（压缩时新旧两块各擦一次），**擦除次数降到 1/16.7**；
- 而且磨损是均匀的：两个扇区各被擦 6 次，没有哪一块被单独操死。

账单的另一面是写放大：实际写进 flash 1768 字节，用户真正交上来的数据只有 812 字节，放大约 2.2 倍。**这就是所有 flash 存储的永恒交易：用带宽换寿命。**

还有个容易忽略的点：日志式并没有"不擦"。它只是把 32 次更新攒成一次压缩。攒得越多，擦得越少，但压缩时要搬的数据越多、掉电窗口也越长——参数就是这么拧的。

### 四、掉电：真正危险的不是"写"，是"擦到一半"

实验 D 演了两种断电现场。

**场景一：写新记录写到一半。** 8 字节的记录只落了前 3 个字节（序号和 key），值和 CRC 还是 0xFF。上电扫描时 CRC 对不上，整条记录被丢弃；读 key=1 拿到的还是旧值 10，没有被污染。**这就是每条记录都要带 CRC 的原因：不是防传输错误，是防"写了一半"。**

**场景二：压缩到一半。** 新扇区已经写好，旧扇区还没来得及擦，两个扇区都有有效记录。扫描时两个都读、同一个 key 取序号最大的那条——数据完好；下次上电再擦一次旧扇区，状态就收敛了。重复擦除是无害的。

反过来说，如果压缩的顺序反过来——先擦旧、再写新——中间掉电就是两头空。**顺序决定掉电后果**：先写新、再擦旧，最坏是浪费空间；先擦旧、再写新，最坏是丢数据。所有可靠的 flash 更新都是这个顺序，没有例外。

### 五、三个反直觉的点

**一、写失败不会报错，它会写成一个"合法但错误"的值。** 0x01 覆盖成 0x02 得到 0x00，驱动返回成功，读出来也不越界。所以判断写成功不能看返回值，只能读回比对，或者给整条记录加 CRC。

**二、磨损不是"用久了"，是"擦多了"。** 读不消耗擦写寿命（NOR 上是这样；NAND 有 read disturb，同一个块读太多次，相邻页的电荷会被扰动，需要搬一次数据）；写只影响被写的页；擦一次伤一整块。一颗标称 10 万次擦写的 flash，如果控制循环里每秒存一次配置，不到 28 小时就到寿——这是固件里的经典自杀写法。

**三、更"啰嗦"的方案反而更省寿命。** 日志式多写了 2.2 倍的数据，却把擦除从 200 次降到 12 次。因为寿命的瓶颈是擦除次数，不是写入字节数。**优化的目标搞错了，越努力越糟。**

（补一个：空片是 0xFF，不是 0x00。判断"这个位置从没写过"只能看是不是全 1；全 0 反而是"写满了 0"的意思。很多"第一次上电读到奇怪默认值"的 bug，根子就在把 0x00 当成空。）

### 六、放远一点

- **MCU 内部 flash 也是这套规则。** nRF52 的 NVMC 按字（word）写、按页（4KB）擦；STM32 按半字/字编程、按扇区擦；ESP32 的 NVS 用 32 字节 entry、页级 GC 和磨损均衡，所以它敢让你在代码里反复 `nvs_set`。你调的每一个"保存参数"API，底下都是今天这套搬运。
- **LittleFS 为什么存在。** 它是 copy-on-write + 磨损均衡 + CRC，专门为"随时可能掉电"的嵌入式场景设计；同样场景下 FAT 可能留下半个目录项，然后整张卡读不出来。
- **SD 卡、eMMC、SSD 里的 FTL 在替你做同样的事。** 你写 512 字节，它可能要先擦一个几 MB 的块、再把整块搬一遍——写放大。监控摄像头用 SD 卡容易坏，不一定是卡的质量差，是 7×24 的小块随机写把 FTL 逼到疯狂擦写。
- **固件升级为什么要双分区。** 升级的本质是"擦掉你正在跑的那块 flash"。没有第二份可回滚的镜像，升级中途掉电，设备就再也起不来了。
- **想彻底摆脱擦除，就换物理。** EEPROM 可以按字节改写（典型 100 万次擦写寿命），FRAM 连擦除都不需要（标称 10¹² 次以上），代价是密度和价格。所以"存配置"和"存代码"经常是两种不同的存储器——不是历史遗留，是物理决定的。

## 🧩 今日代码片段：NOR Flash 实验室——两条规则，四个现场

真板子上演不了"擦到一半掉电"（就算能，也不舍得拿板子反复擦），所以把两条物理规则写成了一个很小的 `NorFlash` 类：program 就是按位与，erase 就是把整扇区填回 0xFF；剩下的全是存储层的事。四个实验：

- **A 位级规则**：写 0xFF 想把位设回 1，到底会发生什么；
- **B 原地改配置**：把 mode 从 1 改成 2，为什么读到 0；
- **C 日志式存储**：同一个 key 改 200 次，到底擦几次；
- **D 两种掉电现场**：写了一半的记录、压缩到一半的扇区，读出来是什么。

纯标准库，本机 Python 3.11.15 真实运行；下面的输出是真实运行结果。

```python
# -*- coding: utf-8 -*-
"""NOR Flash 实验室：为什么"改一个字节"要擦掉整个扇区？

纯标准库、确定性模拟（每次运行一字不差）。
模拟 NOR flash 的两条物理规则：
  ① program 只能把 1 写成 0（新值 = 旧值 & 新值），0 变不回 1
  ② 想让位回到 1，只能擦除整个扇区（擦完全是 0xFF）
四个实验：
  A. 位级：写 0xFF 想把位设回 1，会发生什么
  B. 原地改配置：把 A 从 1 改成 2，为什么读到 0
  C. 日志式存储：200 次更新，擦除几次？
  D. 掉电：写了一半的记录、压缩到一半的记录，读出来是什么
"""
import struct
import sys
import unicodedata

try:
    sys.stdout.reconfigure(encoding="utf-8")
except Exception:
    pass

LINE = "=" * 74
SECTOR = 256              # 假装一个扇区 256 字节（真实器件常见 4KB）
REC = 8                   # 记录：seq(2) + key(1) + value(4) + crc8(1)
ERASED = b"\xff"          # 擦除态：一个字节全是 1


def pad(s, width):
    w = sum(2 if unicodedata.east_asian_width(c) in "WF" else 1 for c in s)
    return s + " " * max(0, width - w)


def crc8(data):
    """CRC-8/ATM：poly=0x07，初值 0x00。够短，也够抓出写了一半的记录。"""
    crc = 0
    for b in data:
        crc ^= b
        for _ in range(8):
            crc = ((crc << 1) ^ 0x07) & 0xFF if crc & 0x80 else (crc << 1) & 0xFF
    return crc


def pack_rec(seq, key, value):
    body = struct.pack("<HBi", seq, key, value)
    return body + bytes([crc8(body)])


def unpack_rec(buf):
    """返回 (seq, key, value)；CRC 不对 / 越界，返回 None"""
    if len(buf) < REC:
        return None
    body, crc = buf[:7], buf[7]
    if crc8(body) != crc:
        return None
    return struct.unpack("<HBi", body)


class NorFlash:
    """只有两条规则，却决定了所有 flash 存储的设计"""

    def __init__(self, sectors=2, size=SECTOR):
        self.size = size
        self.data = [bytearray(b"\xff" * size) for _ in range(sectors)]
        self.programs = 0
        self.erases = 0
        self.per_sector_erases = [0] * sectors
        self.blocked_bits = 0     # 想写 1 却被物理拒绝的位

    def read(self, sec, off, n):
        return bytes(self.data[sec][off:off + n])

    def program(self, sec, off, buf):
        """写：新的每一位 = 旧的 & 新的。0→1 的请求被静默吞掉，不报错。"""
        self.programs += 1
        for i, b in enumerate(buf):
            old = self.data[sec][off + i]
            self.blocked_bits += bin(b & ~old & 0xFF).count("1")
            self.data[sec][off + i] = old & b

    def erase(self, sec):
        """擦除：整个扇区一起回到 0xFF"""
        self.erases += 1
        self.per_sector_erases[sec] += 1
        self.data[sec] = bytearray(ERASED * self.size)


def hexs(b):
    return " ".join(f"{x:02X}" for x in b)


# ---------------------------------------------------------------- 实验 A
def exp_bits():
    print(LINE)
    print("实验 A：位级的物理规则——只能把 1 写成 0")
    print(LINE)
    f = NorFlash()
    print(f"  上电/擦除后：0x{hexs(f.read(0, 0, 1))}（全是 1）")
    print()
    steps = [
        ("写 0xAA", 0xAA, "1→0 的那些位，按请求写下去了"),
        ("想写回 0xFF", 0xFF, "0→1 的位被物理拒绝：旧值 0xAA 原样保留"),
        ("再写 0x55", 0x55, "0xAA & 0x55 = 0x00：新数据把剩下的 1 也抹了"),
    ]
    for i, (title, val, note) in enumerate(steps, 1):
        before = f.read(0, 0, 1)[0]
        f.program(0, 0, bytes([val]))
        after = f.read(0, 0, 1)[0]
        print(f"  第{i}步 {pad(title, 14)} {before:02X} → {after:02X}：{note}")
    print(f"  （全过程想置 1 的位共 {f.blocked_bits} 个，全部被静默吞掉，没有一个报错）")
    print()
    print("  这条规则的另一种用法：同一个字节可以反复\"往下写\"，只要位只会变少——")
    print("  0xFF → 0xF0 → 0xC0 → 0x80 → 0x00，一共记了 8 件事，一次擦除都没做。")
    f2 = NorFlash()
    vals = [0xFF, 0xF0, 0xC0, 0x80, 0x00]
    trace = []
    for v in vals[1:]:
        f2.program(0, 0, bytes([v]))
        trace.append(f"{f2.read(0, 0, 1)[0]:02X}")
    print("  实测：" + " → ".join(trace) + f"（擦除 {f2.erases} 次）")
    print(f"  推而广之：256×8 = {SECTOR * 8} 个位，一个扇区能记 {SECTOR * 8} 次事件不用擦——")
    print("  代价是每次只能记\"又发生了一次\"，不能记具体数值。这就是某些掉电计数器的做法。")
    print()


# ---------------------------------------------------------------- 实验 B
def exp_inplace():
    print(LINE)
    print("实验 B：原地改配置——把 A 从 1 改成 2，读到的是 0")
    print(LINE)
    f = NorFlash()
    # 用两个字节存两个开关：offset 0 = mode，offset 1 = level
    f.program(0, 0, bytes([1]))          # mode = 1
    f.program(0, 1, bytes([1]))          # level = 1
    print(f"  初始：mode={f.read(0, 0, 1)[0]}  level={f.read(0, 1, 1)[0]}  "
          f"扇区内容 {hexs(f.read(0, 0, 4))}")
    print()
    print("  现在想把 mode 改成 2，最直觉的做法是\"往同一个地址再写一次\"：")
    f.program(0, 0, bytes([2]))
    got = f.read(0, 0, 1)[0]
    print(f"    写 2 → 读回 {got}   （0x01 & 0x02 = 0x{got:02X}，不是 2，也没有任何报错）")
    print()
    print("  正确的原地更新必须\"读—改—擦—写\"：把整个扇区读到 RAM，改一个字节，")
    print("  擦掉整块，再把 256 字节全部写回去。代价：擦除时同扇区的 level 也一起消失。")
    ram = bytearray(f.read(0, 0, SECTOR))
    ram[0] = 2
    f.erase(0)
    print(f"    擦除后扇区开头：{hexs(f.read(0, 0, 4))}（level 也没了）")
    f.program(0, 0, bytes(ram))
    print(f"    回写后：mode={f.read(0, 0, 1)[0]}  level={f.read(0, 1, 1)[0]}  "
          f"扇区内容 {hexs(f.read(0, 0, 4))}")
    print(f"    累计：program {f.programs} 次，erase {f.erases} 次——只为了改一个字节。")
    print()


# ---------------------------------------------------------------- 实验 C
class Journal:
    """两扇区乒乓日志：只追加，写满才压缩一次"""

    def __init__(self, flash):
        self.f = flash
        self.active = 0
        self.seq = 0
        self.compactions = 0

    def _latest(self):
        """两个扇区都扫，同一 key 取 seq 最大的那条（掉电压缩后两边都有数据）"""
        best = {}
        for sec in (0, 1):
            for off in range(0, SECTOR - REC + 1, REC):
                r = unpack_rec(self.f.read(sec, off, REC))
                if r is None:
                    continue
                seq, key, val = r
                if key not in best or seq > best[key][0]:
                    best[key] = (seq, val)
        return best

    def _used(self, sec):
        n = 0
        for off in range(0, SECTOR, REC):
            if self.f.read(sec, off, REC) != ERASED * REC:
                n += 1
        return n * REC

    def put(self, key, value):
        if self._used(self.active) + REC > SECTOR:
            self.compact()
        off = self._used(self.active)
        self.seq += 1
        self.f.program(self.active, off, pack_rec(self.seq, key, value))

    def get(self, key, default=None):
        return self._latest().get(key, (0, default))[1]

    def compact(self):
        snap = self._latest()
        dst = 1 - self.active
        self.compactions += 1
        self.f.erase(dst)
        # 把最新的每个 key 写成新记录（seq 继续往上走，保证比旧扇区的都新）
        off = 0
        for key in sorted(snap):
            self.seq += 1
            self.f.program(dst, off, pack_rec(self.seq, key, snap[key][1]))
            off += REC
        self.f.erase(self.active)       # 旧扇区作废
        self.active = dst


def exp_journal():
    print(LINE)
    print("实验 C：日志式存储——200 次更新，擦了几次？")
    print(LINE)
    f = NorFlash()
    j = Journal(f)
    j.put(1, 10)
    j.put(2, 20)
    j.put(3, 30)
    n = 200
    for i in range(n):
        j.put(1, 100 + i)          # 反复改同一个 key
    print(f"  同一把钥匙改了 {n} 次，扇区 {SECTOR} 字节、一条记录 {REC} 字节"
          f"（一扇区装 {SECTOR // REC} 条）")
    print(f"  最终读到 key=1 → {j.get(1)}（最后一次写的是 {100 + n - 1}）")

          f"扇区1 被擦 {f.per_sector_erases[1]} 次）")

          f"日志式省了约 {n / max(f.erases, 1):.1f} 倍擦除。")
    print(f"  代价：写放大——实际写入 {f.programs * REC} 字节，用户只交了 {(n + 3) * 4} 字节数据。")
    print()
```

**今天收获清单：**

- **flash 的擦除态是全 1（0xFF），program 只能把 1 写成 0。** 0→1 只能靠整扇区擦除。写入本质是"按位与"，不合法的位会被静默吞掉——实验里把 1 改成 2，读回来是 0。
- **写不报错，不等于写成功。** 必须读回比对或加 CRC；判断"没写过"只能看是不是全 0xFF，不能看 0x00。
- **改一个字节 = 读整个扇区 + 擦 + 回写。** 实验账单：4 次 program + 1 次 erase，擦除瞬间同扇区的其他数据也一起消失，靠 RAM 副本救回。
- **擦除粒度（4KB 扇区）比写入粒度（256B 页）大一个数量级，耗时差两个数量级。** 擦除期间总线常被挂起、CPU 取指停摆（双 bank 除外）；控制循环里存 flash，要把最坏延迟算进周期预算。
- **日志式把擦除摊薄：** 200 次更新 → 6 次压缩 → 12 次擦除（新旧两块各 6 次），比原地改省 16.7 倍；代价是 2.2 倍写放大（1768 字节 vs 812 字节）。
- **掉电安全三件套：** 每条记录带 CRC（拒掉写了一半的）、带序号（合并两个扇区的有效数据、取最新）、先写新再擦旧（最坏浪费空间，不丢数据）。
- **寿命瓶颈是擦除次数，不是写入字节数。** 10 万次的片子，每秒擦一次，28 小时见底。
- **一个扇区的位可以当 2048 次"事件计数器"用，** 每次只把一位从 1 写成 0，全程不擦——代价是只能记"又发生了一次"。
- **上层全是同一套：** NVS、LittleFS、SD 卡/eMMC 的 FTL、双分区 OTA，都是"追加 + 校验 + 延后擦除"的不同包装。

## ✨ 今日一句

> RAM 允许你把任何一个字节改成任何样子；flash 只允许你把 1 一个个关掉，想重来就得擦掉一整块。存储层那些看起来绕来绕去的设计——日志、序号、CRC、双备份——不是被发明出来的复杂，而是被这条物理规则一步步逼出来的。

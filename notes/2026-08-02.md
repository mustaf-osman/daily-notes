## 💭 技术随想：Git 提交信息怎么写出专业感

大多数人写 commit message 是这样的：

```
fix bug
update code
改了东西
```

这在你三个月后回来看的时候等于没写。一个简单的规范是 **Conventional Commits**：

```
<type>(<scope>): <subject>
```

| type | 什么时候用 |
|------|-----------|
| `feat` | 新功能 |
| `fix` | 修 bug |
| `docs` | 只改文档 |
| `refactor` | 重构代码（不改功能） |
| `chore` | 构建/工具/依赖 |

**例子：**

```bash
# ❌ git commit -m "fix button"
# ✅
git commit -m "fix(ui): prevent button double-submit on slow network"

# ❌ git commit -m "added user profile"
# ✅
git commit -m "feat(auth): add avatar upload with crop and resize"
```

**为什么重要？** `git log --oneline` 一拉下来，你一眼就知道每个提交干了什么。自动生成 changelog 也是靠这个格式。

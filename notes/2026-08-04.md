## 💭 技术随想：命令行的美——小工具组合成大力量

Unix 哲学里有一条："让每个程序只做好一件事"。这听起来很简单，但真正掌握"管道思维"的人并不多。

**核心思路：** 不是找一个大而全的工具解决所有问题，而是学会把 `grep`、`awk`、`sed`、`sort`、`uniq`、`xargs` 这些小零件像乐高一样拼起来。

举个例子：你想知道项目中哪个文件被修改最频繁？

```bash
git log --name-only --pretty=format: | sort | uniq -c | sort -rn | head -10
```

拆解一下这条命令做了什么：
1. `git log --name-only --pretty=format:` → 列出每个 commit 改过的文件
2. `sort` → 按文件名排序（`uniq -c` 需要相邻相同才能计数）
3. `uniq -c` → 统计每个文件出现次数
4. `sort -rn` → 按次数降序排列
5. `head -10` → 只取前 10 个

这比装一个"Git 热力图分析工具"快得多，而且你完全理解它在做什么。

**进阶玩法：** 用 `jq` 处理 JSON、用 `parallel` 并行处理、用 `fzf` 做交互式选择——每个工具都很小，组合起来无比强大。

推荐一本书：*《The Unix Programming Environment》* — Kernighan & Pike，虽然老，但讲透了这种思维方式。

## 🧩 今日代码片段：一行命令找项目中最大的文件

```bash
# 列出当前目录下（递归）最大的 10 个文件
find . -type f -exec du -h {} + | sort -rh | head -10

# 进阶版：忽略 node_modules 和 .git
find . -type f \
  -not -path './node_modules/*' \
  -not -path './.git/*' \
  -exec du -h {} + | sort -rh | head -10
```

**说明：** `du -h` 输出人类可读的大小，`sort -rh` 按数字降序排。"-h" 让 `sort` 正确理解 KB/MB/GB，这是 GNU sort 的特性，macOS 用户可能需要 `gsort`。

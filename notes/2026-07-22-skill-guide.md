3|## 💭 技术随想：AI Agent 的 Skill 怎么写才算好？
4|
5|AI Agent 的核心能力之一就是 **Skill（技能）**——你可以把它理解成给 AI 写的一份"工作手册"。Skill 写得好，AI 就像老员工一样靠谱；写得烂，AI 就乱来。
6|
7|今天聊聊我写了几十个 Skill 后总结出来的几条铁律。
8|
9|## 🧩 今日代码片段：Skill 模板 & 结构拆解
10|
11|一个好的 Skill 文件长这样（以 `github-auth` 为例）：
12|
13|```yaml
14|---
15|name: github-auth                    # 唯一标识，小写+连字符
16|description: "GitHub auth setup..."  # 一句话说清干啥的
17|version: 1.1.0
18|platforms: [linux, macos, windows]   # 哪些平台能用
19|metadata:
20|  hermes:
21|    tags: [GitHub, Auth, Setup]      # 帮助 AI 搜索匹配
22|    related_skills: [github-pr-workflow]  # 关联技能，形成知识网
23|---
24|```
25|
26|### 正文结构：4 层金字塔
27|
28|```
29|        ┌──────────────┐
30|        │  📋 验证步骤  │  ← "跑完这步就证明成
31|        │  (最高层)    │     功了"——给 AI 一个出口
32|       ┌┴──────────────┴┐
33|       │  ⚠️ 常见坑     │  ← "你大概率会遇到 X，
34|       │  (防御层)      │     解法是 Y"——救命的
35|      ┌┴──────────────┐
36|      │  📖 分步指令   │  ← "第一步打开终端，第二
37|      │  (执行层)      │     步敲这个命令..."
38|     ┌┴──────────────┐
39|     │  🎯 触发条件   │  ← "当用户说 XXX 时加载
40|     │  (入口层)      │     这个 Skill"
41|    └───────────────┘
42|```

44|### 实战示例：一个完整的 Skill
45|
46|下面是我实际在用的模板：
47|
48|````markdown
49|---
50|name: my-skill-name
51|description: "一句话描述，AI 靠这个判断是否加载"
52|version: 1.0.0
53|platforms: [linux, macos, windows]
54|---

56|# 技能标题
57|
58|## 触发条件
59|
60|加载这个技能当用户：
61|- 说了 "关键词A" 或 "关键词B"
62|- 在场景 X 中执行操作 Y
63|
64|## 步骤
65|
66|### 1. 第一步：检查环境
67|
68|```bash
69|which some-tool || echo "没装"
70|```
71|
72|### 2. 第二步：执行核心操作
73|
74|```bash
75|some-tool --do-the-thing --flag value
76|```
77|
78|如果失败了，跳到「常见问题」检查。
79|
80|### 3. 第三步：验证
81|
82|```bash
83|# 执行这个命令确认一切正常
84|some-tool --status | grep "OK"
85|```
86|
87|## 常见问题
88|
89|| 症状 | 原因 | 解法 |
90||------|------|------|
91|| `Permission denied` | 没权限 | `chmod +x` 或用 sudo |
92|| `command not found` | 没装这个工具 | 先装：`brew install xxx` |

94|## 验证清单
95|
96|- [ ] 工具已安装

98|- [ ] 输出符合预期
99|````

101|## ✨ 写 Skill 的 5 条铁律
102|
103|### 铁律 #1：命令必须能直接复制粘贴执行
104|
105|❌ 错的：`git 配置好你的用户名`
106|✅ 对的：`git config --global user.name "你的名字"`
107|
108|AI 不需要解释，它需要的是**可执行的命令**。每一行代码都是能直接 copy 进终端的。
109|
110|### 铁律 #2：必须有「常见问题」表
111|
112|AI 遇到报错会慌。你需要像个老司机一样提前告诉他：
113|*"如果你看到 X 错误，99% 是因为 Y，解决方法是 Z。"*
114|
115|这个表是 Skill 里**最有价值的部分**——它让你不用每次都来看 AI 挣扎。
116|
117|### 铁律 #3：步骤要有「唯一出口」
118|
119|每一步都要告诉 AI **怎么判断做完了**：
120|
121|```markdown
122|### 1. 安装依赖
123|```bash
124|pip install requests
125|```
126|✅ 验证：`pip show requests | grep Version` 应该输出版本号
127|```
128|
129|这样 AI 不会在那一步死循环。
130|
131|### 铁律 #4：版本号 + 持续更新
132|
133|Skill 是会过期的。API 变了、工具改名了、流程优化了——每次 AI 碰到坑，应该立刻更新 Skill。
134|
135|一个半年没更新的 Skill 比没有 Skill 更危险——它会让 AI 自信地执行过时的命令。
136|
137|### 铁律 #5：一个 Skill 只做一件事
138|
139|❌ 错：`github-everything` — 又管 auth 又管 PR 又管 issues
140|✅ 对：`github-auth` + `github-pr-workflow` + `github-issues`
141|
142|拆得越细，组合越灵活。AI 可以按需加载，不会一次吞 5000 字消化不良。

# 📅 2026年11月27日 日报

## 💭 技术随想：NaN 不等于它自己，可字典照样找得到它

这两天在翻生鲜流水的表。某一格「当日无数据」，里面躺着三个字母 `nan`，脚本一句 `float()` 就收了；于是那一周的日均全是 nan，页面上那一栏空着，日志里一个字都没有。回头看这几天踩过的坑——字节序、Unicode、「现在几点」——**NaN 是最安静的一个：它不报错、不告警，只在你要结果的时候，把一个数字换成一坨「没有数字」。**

同一天还有另一半：我拿一个 NaN 当字典的键，存进去、取出来，一切正常。可 `nan == nan` 明明是 `False`。**一个「不等于自己」的值，凭什么能当键、还能被 `in` 说「在」？**

今天把这两件事在这台机器上从头跑了一遍（Windows 11 / AMD64 / Python **3.14.9**，另在 Python 3.11.15 上对了跨版本的那一条）。下面每个数字都是刚打出来的。

### 一、NaN 的「怪」只有一条来源

```text
nan == nan / nan != nan : False / True
nan < 1 / nan > 1       : False / False
nan <= 1 / nan >= 1     : False / False
bool(nan)               : True （NaN 是「真」——它不是 0）
repr / str / format     : nan / nan / nan
```

IEEE 754 里只有一条规矩：**除 `!=` 之外，任何和 NaN 的比较都是「假」**（无序）。这一条就把后面所有的怪事生了出来：

- `nan == nan` 是 `False`——所以 `x == float('nan')` 是死代码；
- `nan < 1` 和 `nan > 1` **同时**为 `False`——所以 NaN 在排序里既不是最小也不是最大，它是「无法比较」；
- 唯一自洽的自测法就是 `x != x`。

还有一条容易反直觉的：**`bool(nan)` 是 `True`。** 因为「NaN 不是 0」。所以 `x or 0` 这种兜底写法对 NaN 完全无效——它会把 `None` 兜成 0，然后让 NaN 直接穿过去（第 5 节有实测）。

### 二、每个 `float('nan')` 都是一个新对象，hash 按地址算

```text
四个同时活着的 NaN 的 hash: ['0x1e3842f8d7', '0x1e3842f89f', '0x1e3842f899', '0x1e3842f81f']
互不相同? True
hash == id >> 4 全部成立? True
id 差 / 16 == hash 差 : [True, True, True]
但「生成完就丢弃」的四个 : ['0x1e3842f81b', ...同四个相同...] -> 全一样? True （槽位被回收后复用）
```

三件事：

1. **每次 `float('nan')` 都是一次新分配**：四个对象的 `id` 互不相同，`is` 是 `False`，`==` 也是 `False`。
2. **NaN 的 hash 是按地址算的**——我顺手把公式对了出来：`hash(o) == id(o) >> 4` 四个对象全部成立，而且 `id` 差除以 16 恰好等于 hash 差。同一台机器上 Python 3.11.15 也一样成立。
3. 但最后那一行又是「四个全一样」：**因为它们一生成就被回收，堆把同一个槽位给了下一个**——地址没变，hash 就没变。「先生成再哈希」的写法会让你误以为「所有 NaN 共用一个 hash」，其实只是地址被复用了。**这四行数字每次跑都不一样，它跟地址走。**

为什么 NaN 的 hash 要特殊处理？因为**如果 hash 由「值」算**，而 NaN 根本没有值，那所有 NaN 只能共用同一个 hash——字典里一堆 NaN 全挤在一个桶里，查找退化成链表。改用身份当 hash，至少让不同的 NaN 散开。（变更记录里这条改动是 3.10 的 bpo-43475：在那之前所有 NaN 共用一个固定 hash。）

### 三、容器查找：先比身份（`is`），再比值（`==`）

这是今天最漂亮的一条。

```text
d = {nan: "同一个 nan 对象"}
d[nan]          : 用同一个 nan 对象做键        ← nan != nan 是 True，但这里取到了
d.get(新 nan)   : 找不到（新对象）
d.get(math.nan) : 找不到（math.nan 也是另一个对象）
字典现在有 2 个键，都叫 nan: ['nan', 'nan']
```

**同一个对象永远找得到；长得一样的新对象永远找不到。**

Python 语言参考在「成员测试」那一节把规则写成过一句大白话：`x in y` 等价于 `any(x is e or x == e for e in y)`——**先 `is`，再 `==`。** 字典的查找同理（CPython 实现里第一步就是指针比较，这是实现细节）。所以 `d[nan]` 能成功，不是因为「NaN 等于 NaN」，而是因为**根本轮不到比较那一步，身份就已经对上了**。

这也解释了为什么同一个字典里能同时躺着**两个都叫 nan 的键**：新对象 hash 不同 → 落到另一个空槽；就算 hash 撞了，`==` 也会给它一个 `False`，于是照样并存。列表和集合更直白：

```text
nan in [nan] = True          ／ 新nan in [nan] = False
[nan].index(nan) = 0         ／ [nan].index(新nan) -> ValueError
三个 NaN 进一个集合 -> len = 3      （互不相等，各占一位）
Counter([nan, nan, 新nan]) -> {nan: 2, nan: 1}
```

`Counter` 那一行最值得看：**三个 NaN 被拆成了两组计数**——同一个对象算 2，新对象算 1。**拿 NaN 当分组键的代码，会把同一批 NaN 分成好几个「不同的组」，而且每一组在报表里都显示成 `nan`。**

### 四、NaN 让「排序」这件事不成立

```text
sorted([3, nan, 1, 2]) : [3.0, nan, 1.0, 2.0]        ← 这根本没排好
sorted([nan, 3, 1, 2]) : [1.0, nan, 2.0, 3.0]
min([nan,1,2]) / min([1,nan,2]) : nan / 1.0
max([nan,1,2]) / max([1,2,nan]) : nan / 2.0
```

第一行里 3 排在 1 前面、2 排在最后——**`sorted()` 返回了一个没有排好序的列表，而且不报错。** 原因还是「无序」：NaN 和谁比都是 `False`，排序算法认为它「不小于任何数」，就把它留在原地，后面的元素各走各的。`min`/`max` 更直接：**结果只取决于 NaN 出现在第几个位置。**

修法是一行：

```text
sorted([3, nan, 1, 2], key=nan_last_key) -> [1.0, 2.0, 3.0, nan]
```

`nan_last_key` 先把「是不是 NaN」变成布尔值（`False < True`），NaN 一律甩到队尾；NaN 之间返回同一个键，靠排序的稳定性保住原顺序。**不要在数据里跟 NaN 讲大小，先把它挑出来放到另一堆。**

### 五、两个相反方向的事故：毒化，和静默丢弃

```text
sum([1.0, nan, 2.0]) : nan
statistics.mean      : nan
inf - inf            : nan
safe_mean            : 1.5 ／ 全 NaN 时 -> None

[x for x in [1,-1,nan] if x >= 0] : [1.0]
[x for x in [1,-1,nan] if x <= 0] : [-1.0]
[x or 0 for x in [1.0, None, nan]]: [1.0, 0, nan] （None 兜成了 0，NaN 直接穿过去）
```

- **毒化**：一个 NaN 进 `sum`/`mean`，出来还是 NaN，而且**不会被稀释**——一万个好数加一个 NaN 还是 NaN。`inf - inf` 是 NaN 的另一个常见来源：浮点里任何「无穷减无穷」都落到这里。
- **静默丢弃**：NaN 和任何数比都是 `False`，所以**任何基于比较的过滤都会把它丢掉，往哪个方向都丢**——`x >= 0` 丢，`x <= 0` 也丢。
- **`x or 0` 兜不住它**：实测那一行里 `None` 被兜成了 0，**NaN 原样穿过去**。「没有数据」你会想到兜底，「NaN」你根本想不到——这就是它最坏的地方。

我的结论：**在数据入口就把 NaN 和「缺数据」分开处理**——是缺数据就换成 `None`/`null`，是计算坏了就当场报错或记一条日志。别让 NaN 走进下游的聚合。

### 六、字符串里的 nan：空串当场报错，`'nan'` 静默生效

```text
float('nan')      -> nan            float('NaN')  -> nan
float('-nan')     -> nan            float('inf')  -> inf     float('infinity') -> inf
float('1e999')    -> inf            （溢出到 inf，也不报错）
float('')         -> ValueError: could not convert string to float: ''
float('None')     -> ValueError     float(' ')    -> ValueError

sum(float(x) for x in ['1','nan','3']) -> nan
sum(float(x) for x in ['1',''   ,'3']) -> ValueError
```

把同一列的两格并排看：**空串会当场炸给你看，`nan` 会安安静静毁掉后面所有计算。** `float()` 认得 `nan`、`NaN`、`-nan`、`inf`、`infinity`，也认 `1e999`（溢出成 inf，同样不出声）。

**从 CSV / 环境变量 / JSON 里读来的「数字」，可能根本不是数字。** 这就是那条流水表的教训：读进来的每一格，先问它是「空」「nan」还是「真的数」，别用一句 `float()` 把三种东西变成两种。

### 七、一旦要变整数或 JSON，NaN 就现形

```text
int(nan) / math.floor(nan) / math.trunc(nan) / round(nan)
    -> ValueError: cannot convert float NaN to integer
round(nan, 2)      : nan （带 ndigits 就原样返回）

json.dumps(nan)    : NaN
json.dumps([nan])  : [NaN]
json.dumps({nan:1}): {"NaN": 1}
allow_nan=False    -> ValueError: Out of range float values are not JSON compliant: nan
json.loads('NaN')  : nan
jsonify 之后       : {"a": [1.0, null]}
```

两组事：

- **整数那边是好的**：`int`/`floor`/`trunc`/`round` 全部当场抛 `ValueError`，一行都不含糊。唯一的例外是 `round(nan, 2)`——带 `ndigits` 时不需要变整数，它就原样把 nan 还给你。
- **JSON 那边是坏的**：`json.dumps(nan)` 给你 `NaN`、`[NaN]`、`{"NaN": 1}`——**这三段都不是合法 JSON。** Python 的 json 模块默认开着这个口子（`allow_nan=True`），自己写自己读没事，但**前端、Go、Java、`JSON.parse` 全都不认**：接口到这里就断，而且断在对端。把 `allow_nan=False` 当作发送前的断言，配合 `jsonify` 把 NaN/Inf 换成 `null`。

顺带一个细节：`repr(nan)` 是小写 `nan`，JSON 写出来是大写 `NaN`，`allow_nan` 的报错信息里又是小写。**同一件事三种拼写**，拿脚本去 grep 日志时要注意。

### 八、一个 NaN 有一万亿种写法

```text
float('nan') 位模式: 000000000000f87f        （= 0x7ff8000000000000）
-nan 位模式        : 000000000000f8ff        （只差符号位）
payload=1 的 NaN   : nan | 仍不等于自己: False | math.isnan: True
信号型 NaN         : nan | math.isnan: True
64 位里 NaN 总数   : 2**53 - 2 = 9007199254740990
```

指数位全 1、尾数不全为 0 就是 NaN。尾数有 2⁵² 种取值、符号有两种，扣掉两个无穷——**一共 9007199254740990 种位模式都叫 NaN，而它们彼此不相等、也都不等于自己**（实测上面那个 payload=1 的 NaN 依然 `!= 自己`）。

所以「判断两个 NaN 是不是同一个」在数值上无解。这也从另一个方向解释了第三节：**容器要能正常工作，就只能走身份。**

### 九、`Decimal` 的 NaN 更严格，`math.isnan` 也有边界

```text
Decimal('NaN') == Decimal('NaN') : False        ← 和 float 一样
Decimal('NaN') != Decimal('NaN') : True
Decimal('NaN') < 1               -> InvalidOperation（是报错，不是 False）
float('nan') == Decimal('NaN')   : False
Decimal('NaN').is_nan()          : True ／ float 没这个方法
math.isnan(Decimal('NaN'))       : True
math.isnan(Decimal('sNaN'))      -> ValueError: cannot convert signaling NaN to float
math.isnan('abc')                -> TypeError: must be real number, not str
math.isclose(nan, nan)           : False
```

`decimal` 把 NaN 分成「安静」和「信号」两类：**`==`/`!=` 静默给 False/True（和 float 一致），但 `<` / `<=` / `>` / `>=` 直接抛 `InvalidOperation`**——在「你不知道自己在比什么」的时候，它选择报错，而不是给你一个 `False`。两种设计各有道理：**float 那个静默的 `False`，就是今天所有 bug 的源头。**

还有三个小坑：`Decimal` 有自己的 `is_nan()`，float 没有；`math.isnan` 能吃 `Decimal`（内部先转 float），但遇到 `sNaN` 会因为「转不了」而抛 `ValueError`；传字符串则直接 `TypeError`。**`math.isnan` 的入参必须是「真的数」，它不做类型宽容。**

### 十、对着手上的东西看

- **生鲜流水的 CSV。** 空格子、`nan`、`NaN` 是三种东西，`float()` 会把后两种变成 NaN 并放行。汇总前先过滤 `x == x`，或者用 `safe_mean` 这种「剔掉再算、全空给 None」的函数；图表上「没有数据」画成断点，别用 `x or 0` 兜成 0——**0 是一个真实的数**。
- **RK3588 / rp_server 上报的遥测 JSON。** `json.dumps` 默认会写出 `NaN`/`Infinity`，那不是合法 JSON。上报前 `jsonify` 一遍，`allow_nan=False` 当断言——**宁可这边报错，也别让对端在解析时炸。**
- **电机 / CAN 的反馈。** 一帧 NaN 会污染整段滑动平均，而且一声不吭。入口处用 `x != x` 拦一次，并且**把「拦掉了多少帧」打成日志**——静默丢弃比毒化更难查。
- **排序和 TopN。** 「找最慢的三帧」「取最小值」这类代码，只要数据里可能带 NaN，结果就是随机的。先过滤或用 `key=nan_last_key`，再排序。
- **任何 `x == nan` 的写法。** 一律是死代码，改成 `x != x`（或 `math.isnan(x)`，注意入参类型）。
- **日志和解析脚本。** 落盘用 `repr()`（小写 `nan`），JSON 里是大写 `NaN`——grep 的时候两种都写上。

### 十一、一句必须说清楚的诚实

- **属于标准 / 文档的**：IEEE 754「NaN 与任何数比较（除 ≠）皆为假」；语言参考里成员测试的定义 `any(x is e or x == e for e in y)`；`json` 的 `allow_nan` 默认值、以及 `NaN`/`Infinity` 是 Python 扩展而不是合法 JSON；`decimal` 对 NaN 比较「静默 / 信号」的区分；64 位浮点的指数位与尾数布局；`hash(nan)` 由固定值改为按身份（bpo-43475）。
- **属于这台机器这一次实测的**：上面所有返回值与报错文字，含 `hash(o) == id(o) >> 4`（**3.14.9 与 3.11.15 都成立**）、`sorted` 那两行输出、`2**53 - 2`、`round(nan, 2)` 返回 nan、`{"NaN": 1}`、`[1.0, 0, nan]`。
- **没有实测的**：**numpy / pandas 的缺失值语义**——本机 3.14.9 里两个都没有（`ModuleNotFoundError`），所以 `np.nan` 在数组里的行为、`pd.isna` 今天一个字都没验，它们和 float 的 NaN 是两套东西，不能照搬；**其他解释器**——`hash == id >> 4` 是 CPython 的实现细节（每次跑数字都不同），不是语言保证；**硬件层面的 sNaN**——本机是 SSE2，取回来就当安静 NaN 用了，x87 上会不会真的抛异常我没有设备可验。
- **最要紧的一句**：**NaN 的每一个怪行为都在同一条规则（无序）的射程内。** 你不用背七种容器行为，只要记住：NaN 不是「一个很小 / 很大的数」，它是一个「答不上来」。**凡是要比较、要排序、要聚合的地方，它都会给你一个不报错的错答案。**

## 🧩 今日代码片段：`nanproof.py` —— 让 NaN 现形

`is_nan` 用 `x != x` 自测，`nan_equal` 把 NaN 当同一个值，`nan_last_key` 把 NaN 甩到队尾，`safe_mean` 先剔 NaN、全空给 `None`，`jsonify` 把 NaN/Inf 换成 `null`。整份只用标准库。

```python
# -*- coding: utf-8 -*-
"""nanproof.py —— 让 NaN 现形。

它不等于自己，却能被字典按「身份」找出来；它能让整条计算变 NaN，
却会在过滤器里被悄悄丢掉。纯标准库，无第三方依赖。

实测环境：Windows 11 / Python 3.14.9
"""
import json
import math
import struct
import sys
import statistics
from collections import Counter
from decimal import Decimal, InvalidOperation

NAN = float("nan")


# ---------------- 五个工具 ----------------

def is_nan(x):
    """不依赖库的自测法：唯一一个 x != x 为真的值。"""
    return x != x


def nan_equal(a, b):
    """判等时把 NaN 当成「同一个值」：两个 NaN 相等，NaN 和数字不等。"""
    return (a == b) or (a != a and b != b)


def nan_last_key(x):
    """排序键：数字在前、NaN 全部排到最后，NaN 之间保持原顺序（稳定）。"""
    return (x != x, 0.0 if x != x else x)


def safe_mean(values):
    """求平均前先剔掉 NaN；剔完为空就返回 None，而不是 nan 或抛错。"""
    vals = [v for v in values if v == v]
    return sum(vals) / len(vals) if vals else None


def jsonify(obj):
    """递归地把 NaN/Infinity 换成 null —— 这样才是合法 JSON。"""
    if isinstance(obj, float):
        return None if (obj != obj or obj in (float("inf"), float("-inf"))) else obj
    if isinstance(obj, dict):
        return {k: jsonify(v) for k, v in obj.items()}
    if isinstance(obj, (list, tuple)):
        return [jsonify(v) for v in obj]
    return obj


def section(title):
    print("\n== " + title + " ==")


if __name__ == "__main__":
    print("Python", sys.version.split()[0])

    section("1) NaN 不等于自己，也不大于、不小于任何数")
    print("  nan == nan      :", NAN == NAN)
    print("  nan != nan      :", NAN != NAN)
    print("  nan < 1 / > 1   :", NAN < 1, "/", NAN > 1)
    print("  nan <= 1 / >= 1 :", NAN <= 1, "/", NAN >= 1)
    print("  bool(nan)       :", bool(NAN), "（NaN 是「真」——它不是 0）")
    print("  repr/str/format :", repr(NAN), "/", str(NAN), "/", f"{NAN}")

    section("2) 每个 float('nan') 都是新对象，hash 按地址算")
    objs = [float("nan") for _ in range(4)]
    print("  四个同时活着的 NaN 的 hash:", [hex(hash(o)) for o in objs])
    print("  互不相同?", len({hash(o) for o in objs}) == 4)
    print("  hash == id >> 4 全部成立?", all(hash(o) == id(o) >> 4 for o in objs))
    print("  id 差 / 16 == hash 差 :", [(id(objs[i + 1]) - id(objs[i])) // 16
                                    == hash(objs[i + 1]) - hash(objs[i]) for i in range(3)])
    temps = [hash(float("nan")) for _ in range(4)]
    print("  但『生成完就丢弃』的四个  :", [hex(h) for h in temps],
          "-> 全一样?", len(set(temps)) == 1, "（槽位被回收后复用）")

    section("3) 容器查找先比身份（is），再比值（==）")
    d = {NAN: "用同一个 nan 对象做键"}
    print("  d[nan]          :", d[NAN])
    print("  虽然 nan != nan 为", NAN != NAN, "，nan in d 却是", NAN in d)
    print("  d.get(新 nan)   :", d.get(float("nan"), "找不到（新对象）"))
    print("  d.get(math.nan) :", d.get(math.nan, "找不到（math.nan 也是另一个对象）"))
    d[float("nan")] = "另一个 nan 对象"
    print("  字典现在有", len(d), "个键，都叫 nan:", [repr(k) for k in d])

    print("  列表: nan in [nan] =", NAN in [NAN], "| 新nan in [nan] =", float("nan") in [NAN])
    print("  [nan].index(nan)  =", [NAN].index(NAN))
    try:
        [NAN].index(float("nan"))
    except ValueError:
        print("  [nan].index(新nan) -> ValueError")

    s = {float("nan"), float("nan"), float("nan")}
    print("  三个 NaN 进一个集合 -> len =", len(s), "（互不相等，各占一位）")
    print("  Counter([nan, nan, 新nan]) ->", dict(Counter([NAN, NAN, float("nan")])))

    section("4) 排序/min/max：NaN 让「顺序」这件事不存在")
    print("  sorted([3, nan, 1, 2]) :", sorted([3.0, NAN, 1.0, 2.0]))
    print("  sorted([nan, 3, 1, 2]) :", sorted([NAN, 3.0, 1.0, 2.0]))
    print("  min([nan,1,2]) / min([1,nan,2]) :", min([NAN, 1.0, 2.0]), "/", min([1.0, NAN, 2.0]))
    print("  max([nan,1,2]) / max([1,2,nan]) :", max([NAN, 1.0, 2.0]), "/", max([1.0, 2.0, NAN]))
    print("  key=nan_last_key 之后        :", sorted([3.0, NAN, 1.0, 2.0], key=nan_last_key))

    section("5) 一处 NaN，整条计算全变 NaN；过滤器却会悄悄把它丢掉")
    print("  sum([1.0, nan, 2.0]) :", sum([1.0, NAN, 2.0]))
    print("  statistics.mean      :", statistics.mean([1.0, 2.0, NAN]))
    print("  inf - inf            :", float("inf") - float("inf"))
    print("  safe_mean            :", safe_mean([1.0, 2.0, NAN]), "/ 全 NaN 时 ->", safe_mean([NAN, NAN]))
    print("  [x for x in [1,-1,nan] if x >= 0] :", [x for x in [1.0, -1.0, NAN] if x >= 0])
    print("  [x for x in [1,-1,nan] if x <= 0] :", [x for x in [1.0, -1.0, NAN] if x <= 0])
    print("  [x or 0 for x in [1.0, None, nan]]:", [x or 0 for x in [1.0, None, NAN]],
          "（None 兜成了 0，NaN 直接穿过去）")

    section("6) 字符串里的 nan：静默生效；空串却当场报错")
    for t in ("nan", "NaN", "-nan", "inf", "infinity", "1e999", "", "None", " "):
        try:
            v = float(t)
            print(f"  float({t!r:11}) -> {v!r:7}  v != v: {v != v}")
        except ValueError as e:
            print(f"  float({t!r:11}) -> ValueError: {e}")
    print("  sum(float(x) for x in ['1','nan','3']) ->", sum(float(x) for x in ["1", "nan", "3"]))
    try:
        sum(float(x) for x in ["1", "", "3"])
    except ValueError as e:
        print("  sum(..., ['1','','3']) -> ValueError:", e)

    section("7) 转整数直接报错；转成 JSON 是非法 JSON")
    for fn in (int, math.floor, math.trunc, round):
        try:
            fn(NAN)
        except (ValueError, OverflowError) as e:
            print(f"  {fn.__name__}(nan) -> {type(e).__name__}: {e}")
    print("  round(nan, 2)     :", round(NAN, 2), "（带 ndigits 就原样返回）")
    print("  json.dumps(nan)   :", json.dumps(NAN))
    print("  json.dumps([nan]) :", json.dumps([NAN]))
    print("  json.dumps({nan:1}):", json.dumps({NAN: 1}))
    try:
        json.dumps(NAN, allow_nan=False)
    except ValueError as e:

    print("  json.loads('NaN') :", json.loads("NaN"), "（Python 扩展，别的解析器会拒收）")
    print("  jsonify 之后      :", json.dumps(jsonify({"a": [1.0, NAN]}), allow_nan=False))

    section("8) NaN 的位模式：一个 NaN 有一万亿种写法")
    print("  float('nan') 位模式:", struct.pack("<d", NAN).hex())
    print("  -nan 位模式        :", struct.pack("<d", -NAN).hex(), "（只差最高位符号）")
    q = struct.unpack("<d", bytes.fromhex("010000000000f87f"))[0]
    sn = struct.unpack("<d", bytes.fromhex("010000000000f07f"))[0]
    print("  payload=1 的 NaN   :", q, "| 仍不等于自己:", q == q, "| math.isnan:", math.isnan(q))
    print("  信号型 NaN         :", sn, "| math.isnan:", math.isnan(sn))
    print("  64 位里 NaN 总数   : 2**53 - 2 =", 2 ** 53 - 2)

    section("9) Decimal 的 NaN 更严格；math.isnan 也有边界")
    dn = Decimal("NaN")
    print("  Decimal('NaN') == Decimal('NaN') :", dn == dn)
    print("  Decimal('NaN') != Decimal('NaN') :", dn != dn)
    try:
        dn < Decimal(1)
    except InvalidOperation as e:
        print("  Decimal('NaN') < 1 -> InvalidOperation:", e)
    print("  float('nan') == Decimal('NaN')   :", float("nan") == Decimal("NaN"))
    print("  Decimal('NaN').is_nan()          :", Decimal("NaN").is_nan(),
          "| float 没这个方法:", hasattr(NAN, "is_nan"))
    print("  math.isnan(Decimal('NaN'))       :", math.isnan(Decimal("NaN")))
    for bad in (Decimal("sNaN"), "abc"):
        try:
            math.isnan(bad)
        except (ValueError, TypeError) as e:
            print(f"  math.isnan({bad!r}) -> {type(e).__name__}: {e}")
    print("  math.isclose(nan, nan)           :", math.isclose(NAN, NAN))

    section("10) 五个正确姿势（同时也是五个错误姿势的解药）")
    print("  x != x 自测        :", is_nan(NAN))
    print("  nan_equal(nan,nan) :", nan_equal(NAN, float("nan")), "| nan_equal(nan, 1):", nan_equal(NAN, 1.0))
    print("  NaN 排到最后       :", sorted([NAN, 3.0, NAN, 1.0], key=nan_last_key))
    print("  safe_mean 剔 NaN   :", safe_mean([1.0, 2.0, NAN]))
    print("  合法 JSON          :", json.dumps(jsonify([NAN, 1.5]), allow_nan=False))
```

五个值得单独说的细节：

- **`is_nan` 只有一行 `return x != x`，这是刻意的。** 它对 `float`、对 `Decimal('NaN')`、以及任何「拒绝与自己相等」的类型都成立，不依赖任何库。它的代价是——严格说它不是「判断 NaN」，而是「判断这个值是否不等于自己」；对今天所有场景这就够了，而且它是**类型无关**的写法。
- **`nan_equal` 是给「判等」用的，别拿它当「判断是不是 NaN」。** 它的语义是「两个 NaN 我当作同一个值」，这在「比较两条记录是不是同一条」时才是你要的；在「这个值是不是 NaN」的问题上，它会把两个 NaN 答成相等——**正好和 `==` 相反**。两个函数各管一个问题，混了就出第二种 bug。
- **`nan_last_key` 返回的是元组 `(是NaN, 数值)`。** `False < True`，所以数字在前、NaN 在后；NaN 之间返回同一个键 `(True, 0.0)`，靠排序的稳定性保持原顺序。**关键是别偷懒写成 `key=lambda x: x`**——那等于没写，`sorted` 照样给你没排好的列表。
- **`safe_mean` 在「全部是 NaN」时返回 `None`，不是 0、也不是 nan。** 这不是洁癖：返回 0 会把「没有数据」说成「数据是零」，返回 nan 会让调用方再踩一遍今天所有的坑；`None` 逼调用方显式处理「不知道」这件事。
- **`jsonify` 递归处理 dict / list / tuple，而不是只处理顶层。** 真实报文是嵌套的，顶层没问题不代表里面没问题。它的位置应该在**序列化的最后一刻**（`jsonify(obj)` → `dumps(..., allow_nan=False)`），而不是在数据结构里到处手动塞 `None`。

一句话收这段：**NaN 不是「另一个值」，它是「没有结果」在数值系统里的表示。既然后果是「没有结果」，就别让它混进任何需要「有结果」的地方——能在入口分开的，别留到出口再猜。**

## ✨ 今日一句

> `nan == nan` 是 `False`，可 `nan in [nan]` 是 `True`——**这不矛盾，是两个问题：一个在问「你是不是同一个数」，另一个在问「你是不是同一个东西」。**
>
> 数值上它谁也不等，身份上它只认自己。把它当数用，它会安安静静毁掉整条计算；把它当对象用，它又老实到能当字典的键。**区别只在于你问的是哪个问题——而它从来不提醒你问错了。**

## 💭 技术随想：环形缓冲区——只有 8 格的抽屉，怎么装下无穷的数据流

串口每毫秒来一个字节、传感器每 1ms 出一个点、音频每秒几万帧——数据像水流一样没完没了，而处理它们的那一端，时快时慢。最直觉的做法是拿一个"无限长的清单"全接住：来一个记一个，回头慢慢处理。麻烦就出在这个"慢慢"上：只要生产比处理快哪怕一点点，清单就越积越长——内存只涨不消，而且处理端手里的数据永远是"几分钟前"的。积压一开始是缓冲，拖着拖着就成了灾难。

嵌入式世界给出的答案，往往是一个**固定格数的小抽屉**：环形缓冲区（Ring Buffer）。大白话讲，它就是一圈固定数量的格子（比如 8 格），一个"写指针"、一个"读指针"在圈上顺时针转：写指针负责往格子里放新数据，读指针负责从格子里取旧数据，谁走到头就绕回第一格。真正的魔法只有一句话：**当新数据要盖住最旧的那格时，不扩容、不报错，直接顶掉它**——抽屉永远是那 8 格，旧数据自己让位给新的。

这样一来，三个头疼的问题同时消失：内存占用从"随流量增长"变成"开箱即定"；读写都是"挪一下指针、对格数取个余"，O(1)，和里面存了多少数据无关；显示端拿到的永远是"最近一小段"，**延迟被封了顶**。实时系统里有一条朴素的哲学：宁可要"确定的小"，不要"不确定的大"。

它其实无处不在，只是平时不露脸：

- 芯片外设：UART 串口、网卡的收发队列，底层天生就是环形结构；
- DMA 循环模式：搬运工绕圈搬，搬完一圈自动从头再来，全程不打扰 CPU；
- 音频/视频流：声卡缓冲区就是环形，录制端和播放端各转各的指针；
- 遥测与仪表盘：只关心"最新 N 个点"，旧的随风去；
- 日志轮转：写在磁盘上的环形缓冲区，写满从文件头覆盖——"滚动日志"就是这个思想；
- 无锁通信（SPSC）：一个线程只动写指针、另一个只动读指针，谁也不碰对方的变量，**天然不需要锁**。

一条工程上的分水岭：**"满了怎么办"是设计决策，不是 bug**。遥测场景选"覆盖最旧"（永远保证有最新数据）；一条都不能丢的场景（命令队列、交易流水），就不能用覆盖式环形缓冲，该上阻塞队列 + 背压，或者落盘记账。

## 🧩 今日代码片段：8 格抽屉 vs 无限清单——三个实验

实验1 看"顶掉"的语义：连写 12 个进 8 格抽屉，最早 4 个让位。实验2 模拟"生产快、消费慢"：传感器每 tick 产 1 个、消费端每 3 tick 处理 1 个，看普通列表和环形缓冲各自积压成什么样。实验3 狂写 10 万个，看环形缓冲的内存与内容窗口。

```python
# -*- coding: utf-8 -*-
"""环形缓冲区演示：固定格数 vs 无限增长的列表（真实可运行）"""

class Ring:
    """固定容量环形缓冲：满了就覆盖最旧的（遥测场景：只关心最新）"""
    def __init__(self, cap):
        self.cap = cap
        self.buf = [None] * cap
        self.head = 0        # 下一个要写的位置
        self.tail = 0        # 下一个要读的位置
        self.count = 0       # 当前存着几个
        self.dropped = 0     # 被挤掉的旧数据总数

    def write(self, x):
        self.buf[self.head] = x
        self.head = (self.head + 1) % self.cap        # 走到头就绕回来
        if self.count == self.cap:
            self.tail = (self.tail + 1) % self.cap    # 满了：最旧的被顶掉
            self.dropped += 1
        else:
            self.count += 1

    def read(self):
        if self.count == 0:
            return None
        x = self.buf[self.tail]
        self.tail = (self.tail + 1) % self.cap
        self.count -= 1
        return x

    def values(self):
        """按"从旧到新"顺序列出当前存着的数据"""
        return [self.buf[(self.tail + i) % self.cap] for i in range(self.count)]


print("=" * 54)
print("实验1：传感器连写 12 个点，缓冲区只有 8 格")
print("=" * 54)
ring = Ring(8)
for i in range(1, 13):
    ring.write(f"点{i:02d}")
print(f"写入 12 个后，缓冲区里剩下： {' '.join(ring.values())}")
print(f"被挤掉的旧数据：{ring.dropped} 个（点01 到 点04 已经让位）")
out = []
while True:
    v = ring.read()
    if v is None:
        break
    out.append(v)
print(f"读出来的顺序（先进先出）： {' -> '.join(out)}")

print()
print("=" * 54)
print("实验2：传感器每 tick 产 1 个，消费端每 3 tick 处理 1 个")
print("=" * 54)
ring = Ring(8)
normal = []          # 对照：普通列表，先来先进
print(f"{'tick':>4} | {'普通列表积压':>12} | {'环形缓冲(容量8)':>15} | {'环形已丢弃':>10}")
for tick in range(1, 31):
    ring.write(tick)
    normal.append(tick)
    if tick % 3 == 0:                    # 消费端慢 3 倍
        ring.read()
        if normal:
            normal.pop(0)
    if tick % 5 == 0:
        print(f"{tick:>4} | {len(normal):>12} | {ring.count:>10}/8 | {ring.dropped:>13}")
print()
print(f"30 tick 后：普通列表压着 {len(normal)} 个旧点，越积越深；")
print(f"环形缓冲恒定 {ring.count}/8 个，只保留最新的一小段窗口。")

print()
print("=" * 54)
print("实验3：狂写 100000 个，看内存占用与内容窗口")
print("=" * 54)
ring = Ring(1024)
big = []
for i in range(100000):
    ring.write(i)
    big.append(i)                        # 对照：普通列表会一直涨
print(f"普通列表：{len(big)} 个元素全躺在内存里（能翻旧账，但只涨不消）")
print(f"环形缓冲：永远只有 {ring.cap} 格，已丢弃 {ring.dropped} 个旧点")
print(f"窗口里最旧的 3 个：{ring.values()[:3]}")
print(f"窗口里最新的 3 个：{ring.values()[-3:]}")
```

**说明：**

- 实验1 里"点01"到"点04"被顶掉了，但注意读出来的顺序：点05 到 点12 依旧是"先进先出"——环形缓冲丢的是**最旧的**，保留下来的那一段仍然按时间正序，这个语义在不少手写实现里容易搞反。
- 实验2 是最有画面感的对照：普通列表的积压从第 5 tick 的 4 个一路涨到第 30 tick 的 20 个，"处理端永远在补旧账"；环形缓冲则被 8 格硬顶——到 30 tick 时已有 13 个最旧的点被直接顶掉，缓冲区里始终只剩最新的一小段窗口。**它用"丢弃旧数据"换来了"延迟封顶"**。
- 别把"丢弃"理解成缺陷：对遥测（看最新状态）、对音视频（要最新帧）来说，"最新"就是唯一有价值的部分；真要一条不丢，方案根本不是覆盖式环形缓冲，而是队列 + 背压。
- 实现上两个经典细节：① 判断空/满，可以像这里一样维护一个 count，也可以"故意少用一格"（写指针追上读指针的前一格就算满）——后者省一个变量，是经典做法；② 容量取 2 的幂（8、1024），`% cap` 可以优化成 `& (cap - 1)`，在 MCU 上是实打实的提速。
- 无锁的前提是"**单生产者单消费者**"：写指针只被生产者碰、读指针只被消费者碰，各管一头，不需要互斥锁；一旦有多个生产者或多个消费者，这个前提就没了，得另请高明。
- 和"队列哲学"对照着看很有意思：普通队列是"不许丢，但会无限积压"；覆盖式环形缓冲是"允许丢最旧，换内存和延迟都有硬顶"。实时工程里，**硬顶和确定性往往比"什么都不丢"更值钱**。

## ✨ 今日一句

> 无限清单记住一切，代价是越拖越长的延迟；环形窗口只留最近，换来的是确定性。实时世界里，"确定的小"永远打赢"不确定的大"。

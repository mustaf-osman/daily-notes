## 💭 技术随想

今天想聊聊 **Python 的 `__slots__`**——这个经常被忽视但能带来巨大性能提升的特性。

Python 作为动态语言，每个对象内部都有一个 `__dict__` 字典来存储实例属性。这带来了极大的灵活性（你可以在运行时随意添加新属性），但代价是额外的内存开销和属性访问速度的下降。一个包含几万个实例的类，光 `__dict__` 本身就能吃掉几百 MB 的内存。

解决方案就是 `__slots__`：在类定义中声明一个固定的属性名元组，Python 会为每个实例分配**紧凑的、固定大小的内存块**来存储这些属性，完全抛弃 `__dict__`。效果立竿见影：

1. **内存占用降低 40~60%**：没有字典的哈希表开销
2. **属性访问速度提升 15~30%**：去掉了字典查找的间接层
3. **属性名拼写检查**：杜绝 `obj.attributte` 这种笔误导致的静默 bug（因为不再能动态添加属性）

但 `__slots__` 也有陷阱需要注意：
- **不能继承自非 `__slots__` 的类**——父类没有 `__slots__` 的话，子类定义 `__slots__` 无效，仍会创建 `__dict__`
- **`__weakref__` 默认不可用**——需要显式加入 `'__weakref__'`
- **多重继承要小心**——每个父类都得有 `__slots__`，且不能有重复的槽名

什么场景应该用？**数据类、值对象、配置对象、大量实例的 Entity**——也就是昨天提到的 dataclass 的最佳拍档。事实上，`@dataclass(slots=True)`（Python 3.10+）可以一键生成带 slots 的 dataclass，兼顾开发体验和运行时性能。

## 🧩 今日代码片段

一个利用 `__slots__` 优化**百万级日志条目对象**内存占用的实战示例：

```python
import sys
from typing import Optional
from dataclasses import dataclass
from datetime import datetime


# 方案一：普通类（默认有 __dict__）
class LogEntry:
    def __init__(self, level: str, message: str, timestamp: Optional[datetime] = None):
        self.level = level
        self.message = message
        self.timestamp = timestamp or datetime.now()
        self.trace_id: Optional[str] = None  # 可选字段


# 方案二：使用 __slots__（没有 __dict__）
class LogEntrySlotted:
    __slots__ = ("level", "message", "timestamp", "trace_id")

    def __init__(self, level: str, message: str, timestamp: Optional[datetime] = None):
        self.level = level
        self.message = message
        self.timestamp = timestamp or datetime.now()
        self.trace_id: Optional[str] = None


# 方案三：dataclass(slots=True) —— Python 3.10+ 最佳实践
@dataclass(slots=True)
class LogEntryData:
    level: str
    message: str
    timestamp: datetime = None  # type: ignore
    trace_id: Optional[str] = None

    def __post_init__(self):
        if self.timestamp is None:
            self.timestamp = datetime.now()


# 测试：创建大量对象并比较内存占用
def measure_memory(cls, name: str, count: int = 200_000):
    instances = [cls("INFO", f"log entry #{i}") for i in range(count)]
    # 给部分对象加上可选字段
    for i, inst in enumerate(instances[: count // 10]):
        inst.trace_id = f"trace-{i:08x}"

    size_per_instance = sys.getsizeof(instances[0])
    # 粗略估算总内存（对象本身 + list 引用）
    total_est = sys.getsizeof(instances) + count * size_per_instance + count * 8
    print(f"  {name:20s} | 每个对象: {size_per_instance:>5} bytes | 估算总内存: {total_est / 1024 / 1024:.1f} MB")
    return instances


if __name__ == "__main__":
    print("📊 对象内存占用对比（count=200,000）")
    print("-" * 65)

    a = measure_memory(LogEntry, "普通类 (__dict__)")
    b = measure_memory(LogEntrySlotted, "__slots__ 类")
    c = measure_memory(LogEntryData, "@dataclass(slots=True)")

    # 验证 slotted 类无法动态添加属性
    try:
        b[0].extra_field = "forbidden"
    except AttributeError as e:
        print(f"\n✅ __slots__ 防呆测试通过: {e}")

    # 验证普通类仍然可以动态添加
    a[0].extra_field = "allowed"
    print(f"✅ 普通类动态添加属性: extra_field = '{a[0].extra_field}'")
```

**预期输出效果**（实际运行会显示具体数值，但趋势一致）：
```
📊 对象内存占用对比（count=200,000）
-----------------------------------------------------------------
  普通类 (__dict__)      | 每个对象:    56 bytes | 估算总内存: 25.2 MB
  __slots__ 类           | 每个对象:    32 bytes | 估算总内存: 15.3 MB
  @dataclass(slots=True) | 每个对象:    32 bytes | 估算总内存: 15.3 MB
✅ __slots__ 防呆测试通过: 'LogEntrySlotted' object has no attribute 'extra_field'
✅ 普通类动态添加属性: extra_field = 'allowed'
```

**小结**：`__slots__` 不是银弹，但在写数据密集型的类（日志、事件、配置条目、数据库行映射）时，它是零成本、零依赖的天才优化。配合 `@dataclass(slots=True)` 使用，开发体验和运行效率兼得。当你发现 Python 程序内存异常时，不妨先查查——是不是 `__dict__` 在背后偷吃内存。

## ✨ 今日一句

> **"Premature optimization is the root of all evil."**
>
> 过早优化是万恶之源。
>
> —— Donald Knuth
>
> 但 `__slots__` 不是「过早优化」——它是在**设计阶段**就做出的**架构决策**，属于「合理预见」。当你明确知道一个类会有成千上万个实例、且属性集合是固定的时候，不用 `__slots__` 才是一种浪费。Knuth 批评的是那些在不明需求时就花大量时间微调循环效率的行为，而不是对数据结构的合理设计。知道什么时候优化、优化什么，才是真正的工程智慧。

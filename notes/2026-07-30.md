3|## 💭 技术随想
4|
5|今天想聊聊 **Python 的 `__slots__`**——这个经常被忽视但能带来巨大性能提升的特性。
6|
7|Python 作为动态语言，每个对象内部都有一个 `__dict__` 字典来存储实例属性。这带来了极大的灵活性（你可以在运行时随意添加新属性），但代价是额外的内存开销和属性访问速度的下降。一个包含几万个实例的类，光 `__dict__` 本身就能吃掉几百 MB 的内存。
8|
9|解决方案就是 `__slots__`：在类定义中声明一个固定的属性名元组，Python 会为每个实例分配**紧凑的、固定大小的内存块**来存储这些属性，完全抛弃 `__dict__`。效果立竿见影：
10|
11|1. **内存占用降低 40~60%**：没有字典的哈希表开销
12|2. **属性访问速度提升 15~30%**：去掉了字典查找的间接层
13|3. **属性名拼写检查**：杜绝 `obj.attributte` 这种笔误导致的静默 bug（因为不再能动态添加属性）
14|
15|但 `__slots__` 也有陷阱需要注意：
16|- **不能继承自非 `__slots__` 的类**——父类没有 `__slots__` 的话，子类定义 `__slots__` 无效，仍会创建 `__dict__`
17|- **`__weakref__` 默认不可用**——需要显式加入 `'__weakref__'`
18|- **多重继承要小心**——每个父类都得有 `__slots__`，且不能有重复的槽名
19|
20|什么场景应该用？**数据类、值对象、配置对象、大量实例的 Entity**——也就是昨天提到的 dataclass 的最佳拍档。事实上，`@dataclass(slots=True)`（Python 3.10+）可以一键生成带 slots 的 dataclass，兼顾开发体验和运行时性能。

22|## 🧩 今日代码片段
23|
24|一个利用 `__slots__` 优化**百万级日志条目对象**内存占用的实战示例：
25|
26|```python
27|import sys
28|from typing import Optional
29|from dataclasses import dataclass
30|from datetime import datetime
31|
32|
33|# 方案一：普通类（默认有 __dict__）
34|class LogEntry:
35|    def __init__(self, level: str, message: str, timestamp: Optional[datetime] = None):
36|        self.level = level
37|        self.message = message
38|        self.timestamp = timestamp or datetime.now()
39|        self.trace_id: Optional[str] = None  # 可选字段
40|
41|
42|# 方案二：使用 __slots__（没有 __dict__）
43|class LogEntrySlotted:
44|    __slots__ = ("level", "message", "timestamp", "trace_id")
45|
46|    def __init__(self, level: str, message: str, timestamp: Optional[datetime] = None):
47|        self.level = level
48|        self.message = message
49|        self.timestamp = timestamp or datetime.now()
50|        self.trace_id: Optional[str] = None
51|
52|
53|# 方案三：dataclass(slots=True) —— Python 3.10+ 最佳实践
54|@dataclass(slots=True)
55|class LogEntryData:
56|    level: str
57|    message: str
58|    timestamp: datetime = None  # type: ignore
59|    trace_id: Optional[str] = None
60|
61|    def __post_init__(self):
62|        if self.timestamp is None:
63|            self.timestamp = datetime.now()
64|
65|
66|# 测试：创建大量对象并比较内存占用
67|def measure_memory(cls, name: str, count: int = 200_000):
68|    instances = [cls("INFO", f"log entry #{i}") for i in range(count)]
69|    # 给部分对象加上可选字段
70|    for i, inst in enumerate(instances[: count // 10]):
71|        inst.trace_id = f"trace-{i:08x}"
72|
73|    size_per_instance = sys.getsizeof(instances[0])
74|    # 粗略估算总内存（对象本身 + list 引用）
75|    total_est = sys.getsizeof(instances) + count * size_per_instance + count * 8
76|    print(f"  {name:20s} | 每个对象: {size_per_instance:>5} bytes | 估算总内存: {total_est / 1024 / 1024:.1f} MB")
77|    return instances
78|
79|
80|if __name__ == "__main__":
81|    print("📊 对象内存占用对比（count=200,000）")
82|    print("-" * 65)
83|
84|    a = measure_memory(LogEntry, "普通类 (__dict__)")
85|    b = measure_memory(LogEntrySlotted, "__slots__ 类")
86|    c = measure_memory(LogEntryData, "@dataclass(slots=True)")
87|
88|    # 验证 slotted 类无法动态添加属性
89|    try:
90|        b[0].extra_field = "forbidden"
91|    except AttributeError as e:
92|        print(f"\n✅ __slots__ 防呆测试通过: {e}")
93|
94|    # 验证普通类仍然可以动态添加
95|    a[0].extra_field = "allowed"
96|    print(f"✅ 普通类动态添加属性: extra_field = '{a[0].extra_field}'")
97|```
98|
99|**预期输出效果**（实际运行会显示具体数值，但趋势一致）：
100|```
101|📊 对象内存占用对比（count=200,000）
102|-----------------------------------------------------------------
103|  普通类 (__dict__)      | 每个对象:    56 bytes | 估算总内存: 25.2 MB
104|  __slots__ 类           | 每个对象:    32 bytes | 估算总内存: 15.3 MB
105|  @dataclass(slots=True) | 每个对象:    32 bytes | 估算总内存: 15.3 MB
106|✅ __slots__ 防呆测试通过: 'LogEntrySlotted' object has no attribute 'extra_field'
107|✅ 普通类动态添加属性: extra_field = 'allowed'
108|```
109|
110|**小结**：`__slots__` 不是银弹，但在写数据密集型的类（日志、事件、配置条目、数据库行映射）时，它是零成本、零依赖的天才优化。配合 `@dataclass(slots=True)` 使用，开发体验和运行效率兼得。当你发现 Python 程序内存异常时，不妨先查查——是不是 `__dict__` 在背后偷吃内存。

## 💭 技术随想：Docker 镜像瘦身——从 1.2GB 到 15MB 的旅程

如果你不做任何优化，一个普通的 Docker 镜像很容易膨胀到 1GB 以上。更糟的是，大的镜像不只是占磁盘——它们拉取慢、部署慢，而且包含了大量不必要的工具和库，增加了攻击面。

**多阶段构建（multi-stage build）是解决这个问题的标准答案。** 核心思想很简单：用一个"肥"的构建镜像（带编译器、SDK、dev 依赖）来编译/打包你的应用，然后把产物拷贝到一个"瘦"的运行镜像里。最终发布的镜像只包含运行时必需的东西。

一个 Go 项目的典型对比：

| 方案 | 镜像大小 | 说明 |
|------|---------|------|
| `FROM golang:1.21` 直接构建+运行 | ~900MB | 包含整个 Go SDK、git、gcc…… |
| 单阶段 + `alpine` | ~350MB | Alpine 小，但 Go 工具链还在 |
| **多阶段 + `scratch`/`distroless`** | **~10-15MB** | 只有编译好的二进制 + 最小运行时 |

Python 项目同理：构建阶段装 dev 依赖跑测试、编译 wheel，运行阶段只装生产依赖。Node.js 项目：构建阶段 `npm ci` + `npm run build`，运行阶段只复制 `dist/` + `node_modules --production`。

**几个容易被忽视的细节：**

1. **`.dockerignore` 是免费的优化。** 不加的话 `COPY . .` 会把 `node_modules`、`.git`、日志文件全打包进去，不仅镜像变大，还导致层缓存频繁失效。

2. **层顺序决定缓存命中率。** `COPY package.json .` 放在 `COPY . .` 前面，`npm install` 的结果就能被缓存——这样每次改源码不需要重新装依赖。

3. **`distroless` 比 `alpine` 更安全。** Alpine 还有个 shell 和包管理器（攻击者拿到了 shell 就能干很多事），Google 的 distroless 镜像连 shell 都没有——只有你的二进制和必要的 CA 证书。

4. **善用 `docker image history` 和 `dive` 分析镜像层。** `dive` 是一个 TUI 工具，能逐层展示文件变化，帮你发现"哪一层偷偷带了 200MB 垃圾"。

## 🧩 今日代码片段：Go + React 前端的多阶段 Dockerfile

```dockerfile
# ============================================
# 阶段 1：构建 Go 后端
# ============================================
FROM golang:1.22-alpine AS backend-builder
WORKDIR /app
COPY go.mod go.sum ./
RUN go mod download
COPY . .
RUN CGO_ENABLED=0 GOOS=linux go build -ldflags="-s -w" -o /app/server ./cmd/server

# ============================================
# 阶段 2：构建前端
# ============================================
FROM node:20-alpine AS frontend-builder
WORKDIR /app
COPY frontend/package.json frontend/package-lock.json ./
RUN npm ci
COPY frontend/ .
RUN npm run build

# ============================================
# 阶段 3：最终运行镜像 —— 只保留必要的东西
# ============================================
FROM gcr.io/distroless/static-debian12:nonroot
WORKDIR /app

# 从构建阶段复制二进制
COPY --from=backend-builder /app/server .

# 复制前端静态文件（Go 后端 serve 它们）
COPY --from=frontend-builder /app/dist ./static

# 复制时区数据（如果你的应用需要）
COPY --from=backend-builder /usr/share/zoneinfo /usr/share/zoneinfo

EXPOSE 8080
ENTRYPOINT ["./server"]
```

**说明：**

- `-ldflags="-s -w"` 去掉 Go 二进制的调试符号，能再省 30% 体积
- `distroless/static` 用于纯静态编译的 Go 二进制；如果用了 CGO 或 glibc，换 `distroless/base`
- `:nonroot` 标签强制以非 root 用户运行——又多一层安全保障
- 两个构建阶段可以并行运行（Docker BuildKit 自动处理），不浪费时间

**快速检查你的镜像有没有"虚胖"：**

```bash
# 安装 dive（一次性的）
docker run --rm -it \
  -v /var/run/docker.sock:/var/run/docker.sock \
  wagoodman/dive:latest your-image:tag
```

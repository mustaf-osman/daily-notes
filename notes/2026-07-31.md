## 💭 技术随想

今天想聊聊 **`git worktree`** —— 一个能让 Git 工作流效率翻倍却鲜为人知的神器。

日常工作中有个常见痛点：你在 `feature-A` 分支写到一半，突然需要切到 `master` 检查一个 bug，或者去 `feature-B` 看看同事的进度。常规做法要么是 `git stash`（但 stash 多了容易乱），要么是 `git commit -m "wip"`（污染 commit 历史），或者干脆开第二个克隆目录（浪费磁盘，还得记着两边同步）。这些都太麻烦了。

`git worktree` 的解决方案极其优雅：你可以在**同一个仓库**下创建多个工作目录，每个目录对应不同的分支，彼此完全独立——就像克隆了多次，但底层共享同一个 `.git` 对象库。这就意味着：

1. **零 stash 切换** —— 维持当前分支的现场不动，另开一个目录去干别的
2. **同时运行多分支** —— master 跑测试、feature 写代码、hotfix 改 bug，三个目录互不干扰
3. **磁盘效率高** —— 共享对象存储，只有一份历史、分支和 tag 数据
4. **构建缓存友好** —— 不像切换分支时需要重编译（Monorepo 场景尤其受益）

我最爱的一个用法：`git worktree add -b hotfix/urgent ../hotfix main`，从 main 创建一个热修复分支，在单独的目录里完成修复和测试，然后 `cd ../hotfix && git push && rm -rf ../hotfix && git worktree prune` —— 全程不需要碰原来目录里正在开发的代码。

## 🧩 今日代码片段

一个实战脚本：自动创建和管理 worktree，实现「多分支并行开发」的干净工作流。

```bash
#!/usr/bin/env bash
# worktree-mgr.sh — Git Worktree 多分支并行管理工具
set -euo pipefail

ROOT="$(git rev-parse --show-toplevel)"
WORKTREES_DIR="${ROOT}/../worktrees"  # 所有 worktree 放在仓库同级目录

ensure_dir() { [[ -d "$WORKTREES_DIR" ]] || mkdir -p "$WORKTREES_DIR"; }

usage() {
  echo "用法: $0 <command> [branch]"
  echo "命令:"
  echo "  list                         列出所有 worktree"
  echo "  add   <branch>               基于当前 HEAD 创建新分支的 worktree"
  echo "  addb <branch> <base-branch>  基于指定基分支创建 worktree"
  echo "  rm    <branch>               移除指定分支的 worktree（安全删除）"
  echo "  prune                        清理无效的 worktree 记录"
  exit 1
}

case "${1:-help}" in
  list)
    git worktree list
    ;;
  add)
    BRANCH="$2"
    ensure_dir
    git worktree add -b "$BRANCH" "${WORKTREES_DIR}/${BRANCH}"
    echo "✅ worktree 已创建: ${WORKTREES_DIR}/${BRANCH}"
    echo "   切换到该目录: cd ${WORKTREES_DIR}/${BRANCH}"
    ;;
  addb)
    BRANCH="$2"
    BASE="$3"
    ensure_dir
    git worktree add -b "$BRANCH" "${WORKTREES_DIR}/${BRANCH}" "$BASE"
    echo "✅ worktree 已创建（基于 ${BASE}）: ${WORKTREES_DIR}/${BRANCH}"
    ;;
  rm)
    BRANCH="$2"
    TARGET="${WORKTREES_DIR}/${BRANCH}"
    if [[ ! -d "$TARGET" ]]; then
      echo "❌ worktree 目录不存在: $TARGET" >&2
      exit 1
    fi
    # 确保没有未提交的修改
    if ! git -C "$TARGET" diff --quiet; then
      echo "⚠️  目录 ${TARGET} 还有未提交的修改，请先处理" >&2
      exit 1
    fi
    # 先切换到其他分支，再删除 worktree
    echo "🔄 正在移除 worktree: ${BRANCH} ..."
    git worktree remove "$TARGET" && rm -rf "$TARGET"
    echo "✅ 已移除: ${BRANCH}"
    ;;
  prune)
    echo "🧹 清理过期 worktree 记录..."
    git worktree prune
    echo "✅ 已清理"
    ;;
  *)
    usage
    ;;
esac
```

**使用示例**：

```bash
# 在 master 上开一个新功能分支
$ ./worktree-mgr.sh add feature/new-api

# 基于 main 分支创建 hotfix 分支
$ ./worktree-mgr.sh addb hotfix/critical-bug main

# 查看当前所有 worktree
$ ./worktree-mgr.sh list

# 修复完成，安全删除
$ ./worktree-mgr.sh rm hotfix/critical-bug
```

这个脚本的核心是 `git worktree add -b <branch> <path> [<start-point>]` 这条命令。几个关键点：
- 所有 worktree 集中管理在仓库同级目录的 `worktrees/` 下，一目了然
- 删除前自动检查是否有未提交修改，避免意外丢失代码
- `git worktree prune` 定期清理物理上已被删除但 Git 仍有记录的 worktree 元数据

3|## 💭 技术随想
4|
5|今天想聊聊 **`git worktree`** —— 一个能让 Git 工作流效率翻倍却鲜为人知的神器。
6|
7|日常工作中有个常见痛点：你在 `feature-A` 分支写到一半，突然需要切到 `master` 检查一个 bug，或者去 `feature-B` 看看同事的进度。常规做法要么是 `git stash`（但 stash 多了容易乱），要么是 `git commit -m "wip"`（污染 commit 历史），或者干脆开第二个克隆目录（浪费磁盘，还得记着两边同步）。这些都太麻烦了。
8|
9|`git worktree` 的解决方案极其优雅：你可以在**同一个仓库**下创建多个工作目录，每个目录对应不同的分支，彼此完全独立——就像克隆了多次，但底层共享同一个 `.git` 对象库。这就意味着：
10|
11|1. **零 stash 切换** —— 维持当前分支的现场不动，另开一个目录去干别的
12|2. **同时运行多分支** —— master 跑测试、feature 写代码、hotfix 改 bug，三个目录互不干扰
13|3. **磁盘效率高** —— 共享对象存储，只有一份历史、分支和 tag 数据
14|4. **构建缓存友好** —— 不像切换分支时需要重编译（Monorepo 场景尤其受益）
15|
16|我最爱的一个用法：`git worktree add -b hotfix/urgent ../hotfix main`，从 main 创建一个热修复分支，在单独的目录里完成修复和测试，然后 `cd ../hotfix && git push && rm -rf ../hotfix && git worktree prune` —— 全程不需要碰原来目录里正在开发的代码。
17|
18|## 🧩 今日代码片段
19|
20|一个实战脚本：自动创建和管理 worktree，实现「多分支并行开发」的干净工作流。
21|
22|```bash
23|#!/usr/bin/env bash
24|# worktree-mgr.sh — Git Worktree 多分支并行管理工具
25|set -euo pipefail
26|
27|ROOT="$(git rev-parse --show-toplevel)"
28|WORKTREES_DIR="${ROOT}/../worktrees"  # 所有 worktree 放在仓库同级目录
29|
30|ensure_dir() { [[ -d "$WORKTREES_DIR" ]] || mkdir -p "$WORKTREES_DIR"; }
31|
32|usage() {
33|  echo "用法: $0 <command> [branch]"
34|  echo "命令:"
35|  echo "  list                         列出所有 worktree"
36|  echo "  add   <branch>               基于当前 HEAD 创建新分支的 worktree"
37|  echo "  addb <branch> <base-branch>  基于指定基分支创建 worktree"
38|  echo "  rm    <branch>               移除指定分支的 worktree（安全删除）"
39|  echo "  prune                        清理无效的 worktree 记录"
40|  exit 1
41|}
42|
43|case "${1:-help}" in
44|  list)
45|    git worktree list
46|    ;;
47|  add)
48|    BRANCH="$2"
49|    ensure_dir
50|    git worktree add -b "$BRANCH" "${WORKTREES_DIR}/${BRANCH}"
51|    echo "✅ worktree 已创建: ${WORKTREES_DIR}/${BRANCH}"
52|    echo "   切换到该目录: cd ${WORKTREES_DIR}/${BRANCH}"
53|    ;;
54|  addb)
55|    BRANCH="$2"
56|    BASE="$3"
57|    ensure_dir
58|    git worktree add -b "$BRANCH" "${WORKTREES_DIR}/${BRANCH}" "$BASE"
59|    echo "✅ worktree 已创建（基于 ${BASE}）: ${WORKTREES_DIR}/${BRANCH}"
60|    ;;
61|  rm)
62|    BRANCH="$2"
63|    TARGET="${WORKTREES_DIR}/${BRANCH}"
64|    if [[ ! -d "$TARGET" ]]; then
65|      echo "❌ worktree 目录不存在: $TARGET" >&2
66|      exit 1
67|    fi
68|    # 确保没有未提交的修改
69|    if ! git -C "$TARGET" diff --quiet; then
70|      echo "⚠️  目录 ${TARGET} 还有未提交的修改，请先处理" >&2
71|      exit 1
72|    fi
73|    # 先切换到其他分支，再删除 worktree
74|    echo "🔄 正在移除 worktree: ${BRANCH} ..."
75|    git worktree remove "$TARGET" && rm -rf "$TARGET"
76|    echo "✅ 已移除: ${BRANCH}"
77|    ;;
78|  prune)
79|    echo "🧹 清理过期 worktree 记录..."
80|    git worktree prune
81|    echo "✅ 已清理"
82|    ;;
83|  *)
84|    usage
85|    ;;
86|esac
87|```
88|
89|**使用示例**：
90|
91|```bash
92|# 在 master 上开一个新功能分支
93|$ ./worktree-mgr.sh add feature/new-api
94|
95|# 基于 main 分支创建 hotfix 分支
96|$ ./worktree-mgr.sh addb hotfix/critical-bug main
97|
98|# 查看当前所有 worktree
99|$ ./worktree-mgr.sh list
100|
101|# 修复完成，安全删除
102|$ ./worktree-mgr.sh rm hotfix/critical-bug
103|```
104|
105|这个脚本的核心是 `git worktree add -b <branch> <path> [<start-point>]` 这条命令。几个关键点：
106|- 所有 worktree 集中管理在仓库同级目录的 `worktrees/` 下，一目了然
107|- 删除前自动检查是否有未提交修改，避免意外丢失代码
108|- `git worktree prune` 定期清理物理上已被删除但 Git 仍有记录的 worktree 元数据

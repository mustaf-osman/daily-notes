## 💭 技术随想：DMA——把"搬运"外包出去，CPU 才有空干大事

程序世界里的活可以粗分成两种：**算**和**搬**。算，是 CPU 的本职——解一个方程、过一个滤波器、转一次坐标；搬，是把数据从一个地方挪到另一个地方——串口收到的字节要进缓冲区、ADC 采的样要进数组、摄像头一帧图像要进内存、算好的结果要推给输出接口。这两种活混在一起的时候，问题就来了：CPU 如果亲自搬，它就是全公司时薪最高的搬运工。

先算一笔账。1 MiB 数据，每收一个字节都把 CPU 叫醒一次，那是被打扰 100 多万次——按每次中断保守 1 微秒算，光"被叫醒"的账就烧掉 **1048.58 毫秒**；换成一个 4 MiB/s 的持续数据流（一块中等 ADC 阵列、或一路小分辨率图像），逐字节方案的中断开销是 **419%**——一颗核全部用来接中断都不够，正事一个字都别想提。而如果让硬件自己搬、每攒满 4 KiB 才叫醒 CPU 一次：同一个数据流，中离开销从 419% 掉到 **0.102%**，从"CPU 忙不过来"变成"CPU 几乎不用管"。

这中间的差别，就是 **DMA（Direct Memory Access，直接内存访问）**。

说人话：CPU 是总工程师，负责"想"；DMA 是公司外聘的专职搬运工，只负责"搬"。要数据到位，总工程师不再自己一趟趟扛，而是填一张**任务单**：从哪搬、搬到哪、搬多少、听谁的信号动手。单子往桌上一拍，接着回去想问题；搬运工自己沿着总线一趟一趟走，搬完一整批，才来敲一次门——"报告，这批量搬完了"。

这张任务单在硬件里叫**描述符（descriptor）**，上面写的东西不多：

- **源地址、目的地址、长度**——"把串口接收寄存器里的东西，搬到内存 0x2000_1000，搬 256 字节"；
- **触发源**——听谁的口令动手。可以是外设的 DMA 请求信号（"串口 FIFO 的水位到了"、"ADC 这一组转换完成了"、"定时器到点了"），也可以由软件写寄存器硬启动；
- **地址递增方式**——外设寄存器那头地址不动（每次都读同一扇门），内存这头每搬一次往前走一格；走多快、翻不翻页，都是描述符里的选项；
- **循环模式**——搬运工绕圈搬：搬满一圈自动回到起点，再来一轮。配一个环形缓冲区，就是串口收数据的标准姿势——之前写环形缓冲区那篇里的"抽屉"，套上循环模式，就是现在几乎所有串口驱动的底层。

机制上最要紧的一点：**搬运全程不花 CPU 一条指令**。数据在总线上"流动"，DMA 控制器和外设、内存自己握手，CPU 的寄存器、流水线、取指单元全都不掺和。这就是为什么一颗小 MCU 能一边用高波特率收串口、一边跑协议栈、一边点灯；也是为什么 RK3588 上几路摄像头数据同时涌进来，CPU 还能气定神闲——图像流的搬运全是 DMA 引擎和 ISP 在干活。想想自己手头的项目就会觉得合理：nRF5340 上 UARTE、SPIM 收发用的就是 Nordic 的 EasyDMA；RK3588 后端一边收串口、一边推图像，背后全是这同一个思路。

当然也别神化它：**DMA 不创造带宽**。总线和内存是共享的，搬运工和总工程师要走同一条走廊——搬运量太大时，两边互相挤，周期会被拉长。很多芯片为此给 DMA 配了优先级旋钮，工程上"这条路谁先走"是要设计的，不是天上掉下来的。

### 双缓冲：让"搬"和"算"跳一支重叠的舞

搞清机制之后，真正见功夫的是**节奏**。单缓冲区有个天然的尴尬：搬运工在里面装货的时候，工程师不能动它；工程师在里面改的时候，搬运工不能进来——两班人马共用一间屋子，只能排排坐，你干完我上。反映到时长上：搬运和处理老老实实**排队相加**。

**双缓冲（乒乓缓冲）** 是给配两间屋子：A 间"装货中"（DMA 在搬）、B 间"加工中"（CPU 在算）；A 装满，一次中断交换角色，CPU 转去算 A，DMA 转头去装 B——等第三批货来的时候，最早那间屋子又空出来了。搬运和计算**重叠**在同一段墙上时间里。今天实验二就用真实的墙钟计时量了这支舞：搬运 20 ms/块、处理 15 ms/块的配置下，串行排队的理论总时长是 12×(20+15)=420 ms，双缓冲理论下界是 20+12×20=260 ms；实测 **432.6 ms vs 260.8 ms，提速 1.66×**。反过来"搬运快、处理慢"的配置，提速 1.37×。规律很干净：**流水线的节拍永远由较慢的那一环决定，较快的一环被彻底藏进对方的影子里。**

这就是电机控制回路为什么用双缓冲：1 kHz 的控制周期里，ADC 的新采样和上一拍的控制解算一轮接一轮无缝衔接，中间没有"等搬运"的窟窿。音频播放、图像采集、网络收包——凡是"持续有数据来"的地方，屋子里都在跳同一支舞。

### 三个坑

DMA 这么好用，坑也埋得深。三个最经典的，今天全部现场演示：

**坑一：Cache 一致性——"手边记事本"和"仓库"对不上账。** CPU 带缓存的时候，写的数据可能先留在自己的"手边记事本"（数据缓存）里，仓库（主存）还是旧的；而 DMA 只认仓库、不认记事本——它搬走的是旧数据。反过来，DMA 往仓库里放的新货，CPU 如果先查记事本、命中了过期的页，读到的还是旧值。一正一反两个方向，各有各的翻车方式（实验三把两边都演了一遍）。协议就一句话，方向别搞反：**往外搬之前 clean（把记事本内容抄回仓库）；收进来之后 invalidate（撕掉过期页，下次去仓库重读）。** 放到 Linux 上（RK3588 那种带缓存的 A 核），也不是手搓缓存操作，而是走 DMA-API：`dma_alloc_coherent()` 申请一块"约定好不做缓存"的内存，省心但可能慢一点；或者 map/unmap 配合 `dma_sync_*()` 在正确时机做维护。而 M0/M3/M4 这类没有数据缓存的老实核上，DMA 直接和 SRAM 打交道，感受不到这个问题——很多人第一次在带缓存的核上写 DMA 就栽跟头，就是因为"这点经验带不过去"。还有个更隐蔽的变种：两块数据挤在同一条缓存行里，invalidate 一撕撕掉半行，会把邻居未落库的修改一起带走——DMA 缓冲区按缓存行对齐，不是洁癖，是防误伤。

**坑二：volatile 治不了 DMA。** 之前写 volatile 那篇专门说过：它只对编译器说话（"别自作聪明，每次都去读"），管不了 CPU 缓存，更管不了设备何时在总线上看到内存。DMA 的正确工具是缓存维护加内存屏障（告诉硬件"这次访问的先后顺序有讲究，排在前面的先落定"）——工具用错，症状就是"看起来对、跑起来时好时坏"，这是最难查的一类故障。

**坑三：对齐、长度和生命周期。** 很多 DMA 要求缓冲区按 4 字节甚至缓存行对齐（内存对齐那篇说的"硬件自己的合同"）；单次能搬的长度有上限，超了要拆成描述符链，链本身也有对齐要求；还有最阴的一条——**缓冲区在搬运过程中不能被挪走、被复用、被释放**。"搬运工还在搬，仓库拆了"，在 DMA 世界是会出真实事故的。两条铁律：交接前对合同（对齐、长度），搬运期间缓冲区算"借给搬运工了"，搬完才归还。

### 什么时候值得外包

不是所有搬运都值得外包——外派有手续成本：配描述符、设触发源、同步缓存。**偶尔搬一次的小数据**，手续比搬运本身还贵，不如 CPU 顺手扛走；**持续、高频、大块**的流式数据才是甜点区：串口接收、ADC 采样、音频播放、图像采集、刷屏。一条判据：数据是"一阵接一阵地来、量大、CPU 还得腾出手算"——那就外包。

回头看，从"CPU 亲力亲为"到"DMA 外包"，和当年的指令流水线、协处理器、再到今天的 GPGPU，是同一个母题的一次次放大：**让搬的只管搬，让算的只管算——把最贵的资源，从最便宜的活里解放出来。**

## 🧩 今日代码片段：DMA 模拟实验室——三组实验

三组实验，纯 Python 标准库（无需第三方包），本机 Python 3.11.15 真实运行，输出为真实运行结果：① **跑腿次数账单**——逐字节中断 / FIFO 中断 / DMA 块中断，算 CPU 被"叫醒"多少次、中断开销占多少；② **双缓冲流水线**——"搬"与"算"的赛跑，双线程真实并发、系统时钟真实计时；③ **Cache 一致性现场**——用"记事本 / 仓库"模型，把 clean 和 invalidate 两个方向的翻车各演一遍。

说明一句实验二的口径：真实系统里"搬运"由 DMA 硬件完成、不占 CPU 指令周期，"处理"才占 CPU——本实验把两者都换算成墙上时间，量的是**节奏**（串行排队 vs 重叠流水），线程调度和计时都是操作系统真给的，不是手算的。

```python
# -*- coding: utf-8 -*-
"""DMA 模拟实验室：把"搬运"外包出去 —— 三组实验（纯标准库，真实运行）

实验1：跑腿次数账单 —— 逐字节中断 vs FIFO 中断 vs DMA 块中断
实验2：双缓冲流水线 —— "搬"与"算"重叠，真实计时（两线程真实并发）
实验3：Cache 一致性现场 —— "手边记事本" 与 "主存仓库" 对不上账
"""
import sys
import time
import threading
import queue
import unicodedata

try:
    sys.stdout.reconfigure(encoding="utf-8")
except Exception:
    pass

LINE = "=" * 66


def wpad(s, width):
    """按显示宽度补空格（中文算 2 格）"""
    w = sum(2 if unicodedata.east_asian_width(c) in "WF" else 1 for c in s)
    return s + " " * max(0, width - w)

# ================================================================
# 实验1：中断账单
# ================================================================
print(LINE)
print("实验1：把数据搬到位，CPU 一共被'叫醒'多少次？")
print(LINE)
IRQ_US = 1.0  # 一次中断的保守账：进入 + 退出 + 薄薄的处理 ≈ 1 微秒


def irqs(nbytes, block):
    return (nbytes + block - 1) // block


n = 1 << 20
print(f"  场景A：一次搬完 {n:,} 字节（1 MiB，一帧小图 / 一段短音频）")
print(f"    假设每次中断保守花 {IRQ_US} 微秒：")
for label, block in (("逐字节中断搬（每收 1 字节进一次中断）", 1),
                     ("16 字节 FIFO 中断搬", 16),
                     ("DMA 每 4 KiB 一块（收满一块叫醒一次）", 4096)):
    k = irqs(n, block)
    print(f"      {wpad(label, 42)}被叫醒 {k:>9,} 次   光中断开销 ≈ {k * IRQ_US / 1000:>8.2f} ms")
print()
print("    注意：这只是'被叫醒'的账；逐字节方案里，每个字节还要 CPU 亲自 load/store，")
print("    那部分账还没算。DMA 把两笔账一起接走了。")
print()

rate = 4 << 20
print(f"  场景B：持续数据流 {rate / 1024 / 1024:.0f} MiB/s（中等 ADC 阵列 / 小分辨率摄像头）")
for label, block in (("逐字节中断搬", 1),
                     ("16 字节 FIFO 中断搬", 16),
                     ("DMA 每 4 KiB 一块", 4096)):
    per_s = irqs(rate, block)
    pct = per_s * IRQ_US / 1e6 * 100
    flag = "   ← 一颗核全接中断都不够！" if pct > 100 else ""
    print(f"      {wpad(label, 22)}中断/秒 {per_s:>10,}   CPU 中断开销 ≈ {pct:>8.3f}%{flag}")

# ================================================================
# 实验2：双缓冲流水线
# ================================================================
print()
print(LINE)
print("实验2：双缓冲流水线 —— '搬'与'算'的赛跑（真实计时）")
print(LINE)

BLOCKS = 12
RUNS = 3


def serial(t_fill, t_proc, blocks):
    t0 = time.perf_counter()
    for _ in range(blocks):
        time.sleep(t_fill)   # 自己搬：这段时间 CPU 被搬运占着
        time.sleep(t_proc)   # 搬完再算：两段谁也帮不了谁
    return time.perf_counter() - t0


def pipeline(t_fill, t_proc, blocks):
    q = queue.Queue(maxsize=1)   # 只有两块缓冲：一块在装、一块在算
    t0 = time.perf_counter()

    def dma_engine():
        for _ in range(blocks):
            time.sleep(t_fill)   # DMA 搬运：不占 CPU，只花墙上时间
            q.put(True)          # 装满一块 → 通知 CPU（相当于一次中断）
        q.put(None)

    th = threading.Thread(target=dma_engine)
    th.start()
    while q.get() is not None:
        time.sleep(t_proc)       # CPU 处理刚装好的那一块
    t = time.perf_counter() - t0
    th.join()
    return t


def best(fn, *args):
    return min(fn(*args) for _ in range(RUNS))


print(f"  （每项取 {RUNS} 次运行里最快的一次，消灭系统抖动）")
configs = [
    ("搬运慢 / 处理快（数据流受限）", 0.020, 0.015),
    ("搬运快 / 处理慢（算力受限）", 0.010, 0.025),
]
for name, tf, tp in configs:
    s = best(serial, tf, tp, BLOCKS)
    p = best(pipeline, tf, tp, BLOCKS)
    s_th = BLOCKS * (tf + tp)
    p_th = tf + BLOCKS * max(tf, tp)
    print()
    print(f"  配置：{name}  （每块：搬运 {tf * 1000:.0f} ms，处理 {tp * 1000:.0f} ms）")
    print(f"    串行搬运（CPU 亲自搬）：理论 {s_th * 1000:>6.1f} ms   实测 {s * 1000:>6.1f} ms")
    print(f"    双缓冲流水线（DMA 搬）：理论 {p_th * 1000:>6.1f} ms   实测 {p * 1000:>6.1f} ms")
    slow = "搬运" if tf > tp else "处理"
    print(f"    → 提速 {s / p:>4.2f}×，节拍由「{slow}」决定，另一环被彻底藏进影子里")

# ================================================================
# 实验3：Cache 一致性
# ================================================================
print()
print(LINE)
print("实验3：Cache 一致性现场 —— '手边记事本'与'主存仓库'对不上账")
print(LINE)


class Cpu:
    """CPU 视角：写先落缓存（write-back），读先查缓存"""

    def __init__(self, ram):
        self.ram = ram
        self.cache = {}

    def write(self, addr, value):
        self.cache[addr] = value                  # 写进手边记事本

    def read(self, addr):
        if addr not in self.cache:
            self.cache[addr] = self.ram[addr]     # 未命中 → 去仓库取一趟
        return self.cache[addr]

    def flush(self, addr):
        self.ram[addr] = self.cache[addr]         # clean：记事本内容抄回仓库

    def invalidate(self, addr):
        self.cache.pop(addr, None)                # invalidate：撕掉过期页，下次重读


ram = {"buf": "上一轮的旧数据"}
cpu = Cpu(ram)

print("  场景1：CPU 备好数据 → DMA 往外搬")
cpu.write("buf", "CPU 刚算好的新帧")
print("    ① CPU 写好结果（先落在自己的缓存里，仓库还没更新）")
print(f"       此刻主存 buf = {ram['buf']!r}   ← DMA 只能看到这里")
print("    ② DMA 引擎不知道缓存的存在，它只读主存 → 搬走的还是旧数据 ✗")
print()
cpu.flush("buf")
print("    ③ 正确姿势：搬之前 clean（flush）这一行缓存")
print(f"       再让 DMA 看主存 buf = {ram['buf']!r}  → 搬走的就是新数据 ✓")
print()

ram["buf"] = "上一轮的旧数据"
cpu2 = Cpu(ram)
cpu2.read("buf")                              # CPU 先读了旧值，装进缓存
ram["buf"] = "传感器刚收到的新数据"           # DMA 直接写主存，不经过 CPU 缓存
print("  场景2：DMA 收好数据 → CPU 去读")
print(f"    DMA 已把新数据写进主存：buf = {ram['buf']!r}")
print(f"    但 CPU 再读 buf = {cpu2.read('buf')!r}   ← 命中的是旧缓存页，读了个寂寞 ✗")
cpu2.invalidate("buf")
print(f"    CPU 撕掉过期缓存页（invalidate）后再读 = {cpu2.read('buf')!r}  ✓")
print()
print("  一句话：DMA 只认主存，不认缓存。")
print("  搬之前 clean（把 CPU 的更新落库），搬之后 invalidate（把过期页撕掉）——")
print("  volatile 管不了这件事，它只管'编译器别自作聪明'（上次已经聊过）。")
```

```text
    串行搬运（CPU 亲自搬）：理论  420.0 ms   实测  430.1 ms
    双缓冲流水线（DMA 搬）：理论  310.0 ms   实测  315.0 ms
    → 提速 1.37×，节拍由「处理」决定，另一环被彻底藏进影子里

==================================================================
实验3：Cache 一致性现场 —— '手边记事本'与'主存仓库'对不上账
==================================================================
  场景1：CPU 备好数据 → DMA 往外搬
    ① CPU 写好结果（先落在自己的缓存里，仓库还没更新）
       此刻主存 buf = '上一轮的旧数据'   ← DMA 只能看到这里
    ② DMA 引擎不知道缓存的存在，它只读主存 → 搬走的还是旧数据 ✗

    ③ 正确姿势：搬之前 clean（flush）这一行缓存
       再让 DMA 看主存 buf = 'CPU 刚算好的新帧'  → 搬走的就是新数据 ✓

  场景2：DMA 收好数据 → CPU 去读
    DMA 已把新数据写进主存：buf = '传感器刚收到的新数据'
    但 CPU 再读 buf = '上一轮的旧数据'   ← 命中的是旧缓存页，读了个寂寞 ✗
    CPU 撕掉过期缓存页（invalidate）后再读 = '传感器刚收到的新数据'  ✓

  一句话：DMA 只认主存，不认缓存。
  搬之前 clean（把 CPU 的更新落库），搬之后 invalidate（把过期页撕掉）——
  volatile 管不了这件事，它只管'编译器别自作聪明'（上次已经聊过）。
```

**今天收获清单：**

- **所有活分两类：算和搬。** DMA 把"搬"外包给硬件搬运工：CPU 只填一张任务单（描述符——源、目的、长度、触发），搬运全程不花一条指令，搬完一整批才敲一次门。
- **中断账单差三个数量级。** 搬 1 MiB：逐字节中断被叫醒 100 多万次（光中断开销 ≈1049 ms），DMA 每 4 KiB 一块只叫 256 次（0.26 ms）；4 MiB/s 持续流下，逐字节方案中断开销 419%（一颗核接不完），DMA 方案只要 0.1%。
- **双缓冲让"搬"和"算"重叠。** 节拍由较慢的一环决定：搬运慢时总时长 ≈ 搬一块的时间×块数（提速 1.66×），处理慢时 ≈ 算一块的时间×块数（1.37×）。电机控制、音频、图像全是这个舞步。
- **Cache 一致性协议：送出去之前 clean，收进来之后 invalidate。** 两个方向各有各的翻车方式；volatile 管不了这件事——工具用错，症状是"时好时坏"，最难查。
- **三条工程铁律：** 对齐（防 invalidate 误伤共享缓存行里的邻居）、长度上限与描述符链、生命周期（搬运期间缓冲区不许挪走、复用、释放）。
- **判据：** 偶尔一次的小数据不值得外包（配描述符的手续费比搬运本身贵）；持续、高频、大块（串口、ADC、音频、图像）才是甜点区。另外记牢：DMA 不创造带宽，总线上搬运工和 CPU 会抢路，优先级要设计。

## ✨ 今日一句

> 计算机体系结构里最古老也最常青的一条分工智慧：让搬的只管搬，让算的只管算。DMA 不是多了一台设备，是把"分工"两个字刻进了硬件里——把最贵的资源，从最便宜的活里解放出来。

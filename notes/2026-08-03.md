## 💭 技术随想：不要过早优化，但要一直想着优化

Donald Knuth 说"过早优化是万恶之源"。但这不意味着你完全不考虑性能。

**正确的做法：** 写代码的时候保持"性能意识"，但不立刻动手优化。

```
阶段1：先把功能写对（能跑就行）
阶段2：用 profiler 找到真正的瓶颈（不是你以为的）
阶段3：只优化瓶颈，优化完立刻测（别猜）
```

大多数时候你以为慢的地方，profiler 会告诉你完全不慢。真正慢的地方往往是你没想到的——一个循环里的字符串拼接、一次不必要的数据库查询、一个忘了加索引的字段。

**工具推荐：**
- Python：`cProfile` + `snakeviz`（可视化）
- Node.js：`node --prof` + `clinic`
- Go：`pprof`

## 🧩 今日代码片段：Python 性能分析一行搞定

```python
import cProfile
import pstats
import io

def profile(func, *args, **kwargs):
    """装饰器：自动给函数做性能分析"""
    pr = cProfile.Profile()
    pr.enable()
    result = func(*args, **kwargs)
    pr.disable()
    s = io.StringIO()
    ps = pstats.Stats(pr, stream=s).sort_stats('cumulative')
    ps.print_stats(10)  # 只打印最慢的10个
    print(s.getvalue())
    return result

# 用法
@profile
def slow_function():
    # 你的代码
    pass
```

## 💭 技术随想

今天想聊一个 Python 里「花几分钟学会，一辈子受用」的技巧——**`functools.lru_cache` 与 `cache` 装饰器**。

写代码时经常遇到这种情况：一个纯函数（输入固定、输出固定、无副作用）被反复调用，每次都要重新计算。递归的斐波那契、数据解析的繁重变换、API 响应的反复处理……只要函数是**确定性的**（同样的输入永远返回同样的输出），就有资格加缓存。

Python 3.9+ 提供了 **`functools.cache`**（比 `lru_cache` 更简洁，没有大小限制的简单场景用这个），而 Python 3.2+ 就有 **`functools.lru_cache(maxsize=128)`**（适合你需要控制内存的场景，设置 `maxsize=None` 就变成无限缓存）。加一行 `@cache` 就能把 O(2ⁿ) 的暴力递归变成 O(n) 的动态规划，效率提升是天文数字级的。

还有一个容易被忽略的点：**`lru_cache` 也能给类的方法加**，但要注意 `self` 参数会被计入缓存键，如果实例生命周期短、实例多，反而浪费内存。在这种场景下，更推荐手动构造缓存或把核心逻辑提取为独立的纯函数再加缓存。

## 🧩 今日代码片段

展示一下用 `@cache` 实现带缓存的斐波那契，以及一个更有实用价值的场景：**动态规划版「编辑距离」（Levenshtein Distance）——文本比对、拼写纠错的核心算法**。

```python
from functools import cache

# ---- 示例 1：经典斐波那契，加一行缓存 = 指数级变线性 ----
@cache
def fib(n: int) -> int:
    """返回第 n 个斐波那契数（n >= 0）"""
    if n < 2:
        return n
    return fib(n - 1) + fib(n - 2)

print(fib(100))   # 354224848179261915075 —— 瞬间出结果
print(fib.cache_info())  # CacheInfo(hits=98, misses=101, ...)


# ---- 示例 2：编辑距离（Levenshtein Distance）—— 文本相似度 ----
@cache
def edit_distance(s: str, t: str, i: int = 0, j: int = 0) -> int:
    """计算 s[i:] 和 t[j:] 的编辑距离（插入/删除/替换）"""
    if i == len(s):
        return len(t) - j       # 全部插入剩余字符
    if j == len(t):
        return len(s) - i       # 全部删除剩余字符
    if s[i] == t[j]:
        return edit_distance(s, t, i + 1, j + 1)
    # 分别对应：删除s[i]、插入t[j]、替换s[i]为t[j]
    return 1 + min(
        edit_distance(s, t, i + 1, j),      # 删除
        edit_distance(s, t, i, j + 1),      # 插入
        edit_distance(s, t, i + 1, j + 1),  # 替换
    )

# 测试
print(edit_distance("sunday", "saturday"))   # 3
# 缓存信息
print(edit_distance.cache_info())
# CacheInfo(hits=222, misses=85, maxsize=None, currsize=85)
```

**小贴士**：在 Python 3.13+ 中，`@cache` 和 `@lru_cache` 支持 `typed=True` 参数，会区分 `1` 和 `1.0` 为不同的缓存键（默认它们是同一个键，因为 `int` 和 `float` 的 `==` 比较为 True）。做数值计算时留意这个行为差异。

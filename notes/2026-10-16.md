## 💭 技术随想：从复位到 main()——你写的第一个函数，其实是最后一个被叫醒的

按下复位键（或者给板子上电）的那一瞬间，芯片里没有任何"你的程序"在跑。RAM 是一整片随机数，时钟还是慢吞吞的内部 RC，你定义过的所有变量都没有值，栈指针没指向任何地方。几毫秒之后，`main()` 的第一行开始执行——一切都"理所当然"了：变量生来带初值、全局变量生来是 0、函数能跑、延时是准的。

这中间的几毫秒里发生了什么？答案是**启动代码（startup code）**——C 运行时的"入场服务"。它不在你写的任何 `.c` 文件里，但每次上电，它都在不声不响地干活。你在工程目录里瞥见过的 `startup_xxx.s`、`crt0.o`，就是它。

### 硬件做的，其实只有两件事

Cortex-M 复位时，硬件干的事少得可怜：从 flash 的最开头读两个 4 字节——**第一个字装进 SP（栈指针），第二个字当地址，跳过去**。就这两件事，做完就"撒手不管"了。

这就是"向量表"的来历：它不是软件之间的约定，而是**硬编码进芯片的加电动作**。所以复位后执行的第一行代码不是 `main`，而是启动文件里的 `Reset_Handler`。（顺带一个冷知识：那个入口地址的最低一位通常是 1，比如 `0x08000145`——这不是笔误，Cortex-M 只跑 Thumb 指令，最低位=1 是"这里住的是 Thumb 代码"的标记，硬件跳转时会自动处理。）

### Reset_Handler 的四件事

**一、搬 `.data`——给带初值的变量"搬家"。** 你写 `int counter = 42;` 的时候，42 存在哪儿？——flash 里（因为它得掉电不丢）；但这个变量运行时住在 RAM 里（因为它要能被改写）。于是启动代码每次上电都要把初值从 flash 逐字搬进 RAM。这就是链接脚本里 **LMA 和 VMA** 的含义：初值的住址（flash）和变量的住址（RAM）压根不是同一个。

**二、清 `.bss`——把"没初值的变量"擦成 0。** 没写初值的全局/静态变量（`int log_count;`）被汇总进 `.bss` 段。它没有初值，但 C 标准承诺它"生来是 0"。这个 0 不是免费的：RAM 上电是一片随机垃圾，是启动代码每次上电把整段 `.bss` 一格格写 0，C 标准的承诺才作数——**合同是启动代码一笔一划写出来的**。

**三、调时钟（SystemInit）。** 复位后芯片跑在内部慢速 RC 时钟（几 MHz 量级），启动阶段把它切换到 PLL 外接晶振的高速时钟。"换块板子延时就不准""串口莫名乱码"这类问题的根子，常常就在这段时钟切换里。

**四、收尾，然后叫醒 main。** C++ 全局对象的构造函数在这时运行（`__libc_init_array`），之后才轮到 `main()`。

而"搬到哪、搬多长、清哪里"这些参数，都不是手写的——链接器按链接脚本摆好段布局、生成一张表，启动代码照着表干活。想看原始形态，就去翻启动文件里那个 `.word` 列表和搬运循环。

### 三个反直觉的点

**一、"未初始化"和"初始化为 0"殊途同归，但局部变量不享受这个待遇。** 全局变量的 0 是"芯片开机前帮你打扫好的房间"——一次性批量服务，上电清一次、整个生命周期有效，成本极低。而栈上每个局部变量是"随手拿的草稿纸"，每次函数调用都换一间房，没人会为它清场。所以 C 语言里那句默契才成立：**全局未初始化 = 0 是合同，局部未初始化 = 垃圾是常态**。

**二、函数不用搬，变量才要搬。** 代码是只读的，可以留在 flash 里原地执行（XIP）；变量要读写，必须有 RAM 的可写身位。要不要"搬家"的分界线就一条——**你写不写它**。

**三、"忘清零"的 bug 最阴。** 它不是"必翻车"，而是"这块板子对、那块板子错"：如果漏掉 `.bss` 清零，那个 `calibrated` 标志位读出来就是随机垃圾——恰好非 0 时，`main` 就相信"已经校准过"，直接拽电机跑；恰好是 0 时，一切正常。**"十次对九次"的 bug 比每次都错的难查十倍**——因为你第一次怀疑不到"启动代码"头上。今天的实验里，这坨垃圾是 `-476112912`，main 当场走错了分支。

### 放远一点看

启动代码这种"没人看的代码"，错了以后症状会出现在你查三天的地方（内存对齐那篇聊过的段布局、DMA 那篇聊过的搬运，今天终于在启动代码这里合上了：它们都在同一张"内存地图"上）。Linux 侧的对照一句话：PC 上程序的"C 运行时入场"换了形式（动态链接器、`__libc_start_main`），启动链也更长（bootloader → kernel → init），但精神完全一样——**先把世界铺平，再叫 main**。

## 🧩 今日代码片段：启动实验室——三个场景看"上电垃圾"

真板子上没法"跳过启动代码"（就算能，也不舍得把板子拆出三种崩法），所以写了个确定性模拟器：把 flash、RAM 都建成字节数组，RAM 上电内容用固定种子的伪随机数假装"垃圾"，再让"启动代码"按顺序干活——只拧两个开关：**拷不拷 `.data`、清不清 `.bss`**。每个场景打印：上电瞬间的 RAM → 芯片复位动作 → 启动后的 RAM → `main()` 看到的变量 → 错误分支现场。

纯标准库，本机 Python 3.11.15 真实运行；输出为真实运行结果。

```python
# -*- coding: utf-8 -*-
"""MCU 启动实验室：从复位到 main() —— 上电后，RAM 里发生了什么？

纯标准库、确定性模拟（每次运行一字不差）。
模拟一颗 Cortex-M 风格 MCU 的上电流程：
  flash 里躺着：向量表（开头两个字）+ 有初值变量的初始值（.data 的"始发站"）
  RAM 上电后：一整片随机垃圾
  启动代码做的事：① 硬件读向量表 ② 把 .data 从 flash 搬进 RAM ③ 把 .bss 清零 ④ 跳 main()
三个场景：正确的启动 / 忘拷 .data / 忘清 .bss —— 看看哪一个会当场翻车。
"""
import struct
import sys

try:
    sys.stdout.reconfigure(encoding="utf-8")
except Exception:
    pass

LINE = "=" * 66

SP_INIT = 0x20001000        # 初始栈顶（RAM 最高处，栈往下长）
RESET_HANDLER = 0x08000145  # Reset_Handler 入口；最低位 1 是 Cortex-M 的 Thumb 标记

DATA_SIZE = 8   # .data：banner[4] + counter(int32)
BSS_SIZE = 8    # .bss ：log_count(int32) + calibrated(int32)


def garbage_bytes(seed, n):
    """确定性的'上电垃圾'：真实 SRAM 上电内容是随机的，这里用 LCG 假装随机"""
    out, x = bytearray(), seed
    for _ in range(n):
        x = (x * 1103515245 + 12345) & 0xFFFFFFFF
        out.append((x >> 16) & 0xFF)
    return out


def make_flash():
    """造一张 flash 镜像：向量表 + .data 的初值 +（占位的代码区）"""
    flash = bytearray(0x1010)
    struct.pack_into("<I", flash, 0x000, SP_INIT)        # 第 1 个字：初始 SP
    struct.pack_into("<I", flash, 0x004, RESET_HANDLER)  # 第 2 个字：复位后跳这里
    flash[0x1000:0x1004] = b"ROBO"                       # .data 初值：banner = "ROBO"
    struct.pack_into("<i", flash, 0x1004, 42)            # .data 初值：counter = 42
    return flash


def reset(flash):
    """芯片上电：硬件只做两件事——从向量表取 SP 和 PC"""
    ram = garbage_bytes(0xC0FFEE, DATA_SIZE + BSS_SIZE)  # RAM 上电 = 随机垃圾
    sp = struct.unpack_from("<I", flash, 0)[0]
    pc = struct.unpack_from("<I", flash, 4)[0]
    return ram, sp, pc


def startup(flash, ram, copy_data=True, zero_bss=True):
    """Reset_Handler：启动代码的活。两个开关模拟'这段没写'的样子"""
    if copy_data:   # .data：初值从 flash（LMA）搬到 RAM（VMA）
        ram[0:DATA_SIZE] = flash[0x1000:0x1000 + DATA_SIZE]
    if zero_bss:    # .bss：整片清零
        ram[DATA_SIZE:DATA_SIZE + BSS_SIZE] = bytes(BSS_SIZE)


def to_main(ram):
    """进 main() 之后，程序看到的世界"""
    banner = bytes(ram[0:4])
    counter = struct.unpack_from("<i", ram, 4)[0]
    log_count = struct.unpack_from("<i", ram, 8)[0]
    calibrated = struct.unpack_from("<i", ram, 12)[0]
    return banner, counter, log_count, calibrated


def dump_ram(tag, ram):
    a = " ".join(f"{b:02X}" for b in ram[:8])
    b = " ".join(f"{b:02X}" for b in ram[8:])
    print(f"  {tag} RAM[0x20000000] : {a} | {b}")


def scenario(no, title, copy_data, zero_bss, note):
    print(LINE)
    print(f"场景{no}：{title}")
    print(LINE)
    flash = make_flash()
    ram, sp, pc = reset(flash)
    dump_ram("上电瞬间", ram)
    print(f"  ① 硬件读向量表：SP ← 0x{sp:08X}，PC ← 0x{pc:08X}（复位后的第一行代码从这里开始）")
    if copy_data:
        print("  ② .data 搬家：已执行（flash 0x08001000 → RAM 0x20000000，8 字节）")
    else:
        print("  ② .data 搬家：—— 被跳过！（启动代码里根本没写这一段）")
    if zero_bss:
        print("  ③ .bss 清零： 已执行（RAM 0x20000008 起 8 字节，全部写 0）")
    else:
        print("  ③ .bss 清零： —— 被跳过！")
    startup(flash, ram, copy_data, zero_bss)
    dump_ram("进 main 前", ram)
    banner, counter, log_count, calibrated = to_main(ram)
    print()
    print("  main() 看到的变量：")
    print(f"    banner     期望 b'ROBO'   实际 {banner!r}   {'✓' if banner == b'ROBO' else '✗'}")
    print(f"    counter    期望 42        实际 {counter}   {'✓' if counter == 42 else '✗'}")
    print(f"    log_count  期望 0         实际 {log_count}   {'✓' if log_count == 0 else '✗'}")
    print(f"    calibrated 期望 0         实际 {calibrated}   {'✓' if calibrated == 0 else '✗'}")
    if calibrated != 0:
        print("    [main] 读到 calibrated != 0 → “嗯，已经校准过了” → 直接拽电机跑 ✗（用的全是上电垃圾！）")
    else:
        print("    [main] 读到 calibrated == 0 → “没校准过，先跑校准流程” ✓")
    print(f"    → {note}")


print(LINE)
print("MCU 启动实验室：从复位到 main()，芯片一共就做这么几步")
print(LINE)
flash = make_flash()
print("  flash 的开头，是芯片复位时唯一会'主动看'的地方：")
print(f"    flash[0x08000000] = 0x{struct.unpack_from('<I', flash, 0)[0]:08X}   ← 初始栈顶 SP")
print(f"    flash[0x08000004] = 0x{struct.unpack_from('<I', flash, 4)[0]:08X}   ← Reset_Handler 入口（最低位=1：Thumb 标记）")
print()

scenario(1, "一切正常：拷 .data、清 .bss，然后叫醒 main", True, True,
         "有初值的、没初值的，各就各位——这就是'初始化'三个字的全部分量。")
scenario(2, "忘拷 .data：带初值的全局变量，读到的是上电垃圾", False, True,
         "banner、counter 全错。变量住在 RAM，'初值'却躺在 flash——没人搬，它就一直是垃圾。")
scenario(3, "忘清 .bss：'没初始化'不等于'值是 0'", True, False,
         "校准标志位是随机垃圾 → main 走错分支。最阴的是：这块板子垃圾恰好为 0，那块板子不为 0——'十次对九次'。")

print()
print(LINE)
print("一张便签：谁在管什么内存")
print(LINE)
print("  函数（.text）       住 flash，只读 → 不用搬，原地执行（XIP）")
print("  有初值变量（.data） 初值躺 flash，变量住 RAM → 启动时搬一次")
print("  无初值变量（.bss）  只住 RAM → 启动时清零（C 标准才敢承诺'全局默认 0'）")
print("  局部变量（栈）      谁用谁管 → 没人清零，未初始化就是垃圾")
print()
print("  一句话：main() 不是第一个跑的东西——在它之前，启动代码已经把")
print("  '变量们'从 flash 抬进 RAM、把该清零的清零，然后才叫醒它。")
```

**今天收获清单：**

- **复位后硬件只做两件事：** 从向量表取 SP（第一个字）、跳 Reset_Handler（第二个字）。`main` 之前还有一整套"入场服务"：搬 .data、清 .bss、配时钟、跑构造函数。
- **`.data` 的初值在 flash 里"睡觉"**（LMA），变量运行时住 RAM（VMA），启动时搬一次；**`.bss` 只有"身位"没有初值**，启动时清零——C 标准承诺的"全局默认 0"，是启动代码一格格写出来的。
- **栈上的局部变量没人清零：** 全局未初始化 = 0 是合同，局部未初始化 = 垃圾是默契。
- **要不要搬家的一条线：** 只读的（函数、常量）留在 flash 原地执行（XIP）；要写的（变量）必须进 RAM。
- **"忘清零"的典型症状是"这块板子对、那块板子错"：** 实验里漏掉 .bss 清零，calibrated 标志位读出 -476112912，main 当场走错分支——上电垃圾恰好为 0 的板子则一切正常，这就是它难查的原因。
- **三个可以继续深挖的入口：** 启动文件（`startup_xxx.s` / `crt0`）、链接脚本（段布局与 LMA/VMA）、`SystemInit`（时钟切换）。

## ✨ 今日一句

> 每个程序的故事都不是从 `main()` 开始的。在你的第一行代码登场之前，已经有人替你把世界收拾干净：变量从 flash 搬了家、该清零的清了零、时钟调好了速度——做得足够好的"入场服务"，就是让你永远感觉不到它存在过。

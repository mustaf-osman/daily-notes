28|## 📑 10 章速读
29|
30|### 第一章 · Agent 基础知识
31|
32|**核心问题：什么是 Agent？**
33|
34|Agent 跟普通聊天机器人的本质区别：它不是"你问一句它答一句"，而是**能自主规划步骤、调用工具、根据结果调整策略**的智能系统。
35|
36|引入 ReAct 循环（思考 → 行动 → 观察 → 再思考），这是所有 Agent 的底层运行逻辑。
37|
38|三种学习范式：
39|- **后训练**：改模型权重（贵、慢、稳）
40|- **上下文学习**：塞示例给模型看（快、临时）
41|- **外部化学习**：把知识存到文件/知识库里（本书重点）
42|
43|---
44|
45|### 第二章 · 上下文工程（全书最重要的章节）
46|
47|**核心洞察：上下文决定 Agent 的能力上限。**
48|
49|模型再强，给的信息不够，也白搭。作者打了一个比喻：一个天才工程师加入你的团队，但你对项目架构、业务规则、技术债务只字不提——他也干不了活。
50|
51|三种必备上下文：
52|1. **代码上下文**：目录结构、模块职责、代码规范
53|2. **流程上下文**：Git 策略、Review 流程、CI/CD
54|3. **环境上下文**：配置、密钥、部署方式
55|
56|关键概念：
57|- **KV Cache**：模型怎么"记住"之前的对话（底层原理）
58|- **Agent Skills**：按需加载的提示词模块，解决上下文爆炸
59|- **上下文压缩**：用额外 LLM 调用把冗长历史"提炼"成摘要
60|- **Agent 状态栏**：把关键信息持续维护进上下文
61|
62|> 金句："AI Agent 就像一个永远的新员工——给足背景信息，它能干得很好；什么都不告诉它，再聪明也是白搭。"
63|

66|### 第三章 · 用户记忆和知识库
67|
68|**核心问题：对话结束后，Agent 怎么还"记得"你？**
69|
70|两个维度：
71|- **用户记忆**：针对个人的偏好、习惯、需求（"懂你的助手"）
72|- **知识库**：共享的领域知识（"领域专家"）
73|
74|关键技术：
75|- **RAG（检索增强生成）**：先搜索相关文档，再让模型回答
76|- **渐进式记忆策略**：从简单摘要到结构化知识图谱
77|- **Agentic RAG**：让 Agent 自主决定什么时候检索、检索什么

81|### 第四章 · 工具（MCP 协议详解）
82|
83|**核心问题：Agent 的"手脚"怎么设计？**
84|
85|五类工具分类：
86|
87|| 类型 | 例子 | 设计重点 |
88||------|------|----------|
89|| 感知工具 | 搜索、读文件 | 粒度和输出信息量 |
90|| 执行工具 | 写文件、发邮件 | **安全约束**（这个最重要） |
91|| 协作工具 | 委托子 Agent | 通信协议 |
92|| 事件触发 | 定时任务、Webhook | 异步架构 |
93|| 用户沟通 | 向用户提问 | 交互体验 |
94|
95|**MCP 协议**：统一工具互操作标准。读完这章能理解 Hermes 的 MCP 工具是怎么设计的。
96|

99|### 第五章 · Coding Agent 与代码生成
100|
101|**核心论断：通用 Agent 的架构本质 = Coding Agent + 文件系统。**
102|
103|为什么？因为代码是一种"元能力"——能在运行时动态创造新工具。
104|
105|Coding Agent 的七个核心工具：
106|1. 代码解释器（沙盒执行 Python）
107|2. Bash（命令行）
108|3. 读文件
109|4. 写文件
110|5. 编辑文件（局部修改）
111|6. Glob（按模式找文件）
112|7. Grep（搜索文件内容）
113|
114|以 **OpenClaw** 为例拆解了通用 Agent 的完整架构——这章对理解 Hermes Agent 的设计很有参考价值。

118|### 第六章 · Agent 的评估
119|
120|**核心问题：怎么科学判断一个 Agent 好不好用？**
121|
122|> "没有评估，就没有进步。"
123|
124|三层评估体系：
125|1. **评估环境**：在哪测（工具调用型 vs 人机交互型）
126|2. **评估方法**：怎么判（数据集 + LLM-as-a-Judge）
127|3. **评估驱动决策**：测了干什么（模型选型、架构优化）
128|
129|关键方法：
130|- **消融实验**：关掉某个组件看性能变化
131|- **模型替换实验**：换模型看分数涨不涨 → 判断瓶颈在模型还是 Harness

135|### 第七章 · 模型后训练
136|
137|**核心问题：怎么让模型更聪明？（不需要自己训练模型的可以跳过）**
138|
139|三段式训练流程：
140|```
141|预训练（读万卷书）→ SFT（老师手把手教）→ RL（自己下场做题）
142|```
143|
144|两条核心主线：
145|1. **SFT 记忆，RL 泛化**：SFT 记住答案，RL 学会策略
146|2. **数据和环境，比算法更重要**：仿真环境真实性 + 示范数据质量 >> 调参

150|### 第八章 · Agent 的自我进化
151|
152|**核心问题：不改模型参数，Agent 怎么持续变强？**
153|
154|> "学习不会自动发生，必须被显式设计出来。"
155|
156|两条进化路径：
157|1. **从经验中学习**：把成功经验总结成 Skill、工作流、提示词模板
158|2. **发现和创造工具**：主动找新工具、用代码创造新工具
159|
160|核心哲学：与其指望模型"记住一切"，不如在任务完成后用额外算力把经验**总结、压缩、结构化**，存到外部系统。
161|

163|
164|### 第九章 · 多模态与实时交互
165|
166|**核心问题：Agent 怎么走出"对话框"？**
167|
168|三个场景：
169|- **语音 Agent**：从串行流水线（ASR → LLM → TTS）到端到端全双工
170|- **Computer Use**：让 AI 像人一样操控电脑屏幕
171|- **机器人操作**：视觉-语言-动作模型（VLA）
172|
173|共同挑战：**实时性** + **多模态**。语音停顿 > 2 秒就让人焦躁，机器人控制的毫秒级抖动就撞墙。
174|

176|
177|### 第十章 · 多 Agent 协作
178|
179|**核心问题：一群 Agent 怎么合作？**
180|
181|两个核心维度：
182|1. **上下文共享 vs 独立**：Agent 之间能不能互相看到对方的"思考过程"
183|2. **对等 vs 管理者 vs 去中心化**：怎么组织
184|
185|关键技术：
186|- 共享文件系统（通过读写中间产物传递信息）
187|- 消息总线（异步通信，不要求同时在线）
188|- 工具调用参数（结构化数据传递）
189|
190|> "群体的智能可以高于个体。哪怕每一个 Agent 都只相当于人类专家水平，只要组织得当，整体能力可能超过所有人类专家的总和。"

194|## 🧠 这本书的独特价值
195|
196|### 1. "实践在前，命名在后"
197|
198|作者反复强调的观点：Anthropic 提出的 Skill、Harness、Loop Engineering 这些概念，不是他们"发明"的——是大量 Agent 开发者**先这么做了**，他们才提炼成术语的。
199|
200|**启示：别等概念火了再跟进。** 你自己做 Agent 时遇到的坑和解决方案，可能就是下一个被命名的"模式"。
201|
202|### 2. 用造 Pine AI 的真实经验写书
203|
204|Pine 是第一个能**独立处理涉及金钱的长流程任务**的通用 Agent——替用户打电话砍账单、跟商家交涉退款，全程无需人工接管。这些高风险场景逼出来的架构原则，比纸上谈兵有说服力得多。
205|
206|### 3. 全开源 + 88 个实验
207|
208|不是"看完了就忘了"的书。每章有配套代码，70+ 个项目可以直接跑。作者强烈建议动手跑实验——"AI Agent 的直觉，是在调试中建立的。"

# 📅 2026年08月07日 日报

## 💭 技术随想：git bisect——二分法找 bug，机器干活你喝茶

调试中最痛苦的场景之一：某个功能明明昨天还好好的，今天突然崩了，但中间有 50 个 commit。你开始凭直觉猜——"应该是那个重构吧？""不对，可能是依赖升级……"然后一个个 checkout、测试、排除，半小时过去了。

**`git bisect` 用二分查找算法自动定位引入 bug 的 commit。** 你告诉它一个"好"的 commit 和一个"坏"的 commit，它用 O(log₂N) 次 checkout 就能找到罪魁祸首。50 个 commit？最多 6 步定位。

为什么这个工具严重被低估？三个原因：
1. 很多人没听说过它
2. 听说过的人觉得"手动二分也很快"（但实际上 50 个 commit 手动二分要反复记边界，极易出错）
3. 不知道可以配合 `git bisect run` 全自动化

**全自动模式是真正的杀手锏。** 写一个脚本判断当前版本有没有 bug（跑测试、curl 接口、grep 日志都行），然后一行 `git bisect run ./test.sh`，去倒杯咖啡回来，Git 已经告诉你第一个坏的 commit 是哪个。这和你手动翻 commit 完全是两个时代的工作方式。

```bash
# 手动模式：适合无法自动判断 bug 的场景（比如 UI 表现异常）
git bisect start
git bisect bad HEAD
git bisect good abc1234

# Git 会自动 checkout 到中间的 commit
# 你手动验证后告诉它结论
git bisect good    # 或 git bisect bad

# 重复直到定位 → 最后收尾
git bisect reset   # 回到原来的分支
```

```bash
# 全自动模式：适合任何能写脚本判断的场景
git bisect start HEAD abc1234
git bisect run ./scripts/check_bug.sh

# check_bug.sh 的退出码约定：
#   0  → 这个 commit 是好的  (good)
#   1~127 → 这个 commit 是坏的 (bad)，但排除 125
#   125 → 无法判断，跳过这个 commit

git bisect reset
```

**实战案例**：之前项目中有一个性能回退——某次 API 调用的延迟从 200ms 飙升到了 2s。中间 40 个 commit，不知道谁引入的。写了一个脚本 `curl -o /dev/null -s -w '%{time_total}' http://localhost:8080/api/test`，阈值 > 1s 返回 1。`git bisect run` 6 步定位到一个"无害的" ORM 查询修改，原来是漏了 `.select_related()`。从开始到定位，3 分钟。

## 🧩 今日代码片段：全自动 git bisect 脚本模板

```bash
#!/usr/bin/env bash
# check_performance_regression.sh — 配合 git bisect run 使用
# 用法: git bisect run ./check_performance_regression.sh
set -euo pipefail

# 1. 编译/构建项目（如果需要）
make build > /dev/null 2>&1 || exit 125  # 构建失败 → 跳过此 commit

# 2. 启动服务
./start_server.sh &
SERVER_PID=$!
sleep 2  # 等待服务就绪

# 3. 运行你的验证逻辑
RESPONSE_TIME=$(curl -o /dev/null -s -w '%{time_total}' http://localhost:3000/api/health)

# 4. 清理
kill "$SERVER_PID" 2>/dev/null || true
wait "$SERVER_PID" 2>/dev/null || true

# 5. 判断：大于阈值 → bad (exit 1)，否则 → good (exit 0)
THRESHOLD=1.0
if (( $(echo "$RESPONSE_TIME > $THRESHOLD" | bc -l) )); then
    echo "❌ 延迟 $RESPONSE_TIME 秒 > $THRESHOLD — BAD"
    exit 1
else
    echo "✅ 延迟 $RESPONSE_TIME 秒 — GOOD"
    exit 0
fi
```

**关键点：**
- 退出码 `125` 告诉 git bisect 这个 commit 无法测试，自动跳过——构建失败、依赖缺失时用它
- 脚本里一定要清理后台进程（`kill` + `wait`），否则僵尸进程会越积越多
- 可以在脚本里加 `set -x` 调试，bisect 结束后关掉

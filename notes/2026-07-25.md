## 💭 技术随想

今天聊一个超级实用但很多人没认真学过的命令——**`jq`：命令行 JSON 处理利器**。

后端开发、API 调试、DevOps 脚本，几乎每天都要跟 JSON 打交道。`curl` 返回一大坨未格式化的 JSON，你还在复制到在线工具里格式化？或者写 Python 脚本 `json.loads()` 再过滤字段？这些都能理解，但 `jq` 能让你在终端里**一条命令搞定**：格式化、过滤、变换、聚合，一气呵成。

`jq` 最震撼的一点是它的**声明式查询语法**——和 SQL 一样，你描述「要什么」，而不是「怎么做」。`.key` 取字段，`.[]` 遍历数组，`select` 过滤，`group_by` 分组聚合，链式管道和 Unix 哲学如出一辙。而且 `jq` 几乎所有 Linux 发行版和 macOS 都有预装或可安装，Windows 也有二进制版本，跨平台无压力。

**我的建议**：花 15 分钟读完 `jq` 的 man page 前两节（`man jq`），你就能省下未来无数个小时。配合 `curl`、`xargs`，可以写出非常强大的单行数据流水线。

## 🧩 今日代码片段

下面是一个实战例子：**用 `jq` 从 GitHub API 中提取信息，一行命令完成多步操作**。

```bash
#!/usr/bin/env bash
# 工具：jq 实战三部曲

# 1. 基础：格式化 + 选取字段
# 取某个 GitHub repo 最近 3 个 commit 的 SHA、作者、时间
curl -s "https://api.github.com/repos/nousresearch/hermes-agent/commits?per_page=3" \
  | jq '.[] | {sha: .sha[:7], author: .commit.author.name, date: .commit.author.date}'

# 2. 过滤 + 条件判断（select）
# 找出最近 5 个 issue 中所有 label 为 "bug" 的 issue
curl -s "https://api.github.com/repos/nousresearch/hermes-agent/issues?per_page=5" \
  | jq '.[] | select(.labels[].name == "bug") | {number, title, state}'

# 3. 聚合统计（group_by + length）
# 统计某个用户的 repo 按语言分类的数量
curl -s "https://api.github.com/users/nousresearch/repos?per_page=100" \
  | jq 'group_by(.language) | map({language: .[0].language, count: length}) | sort_by(-.count)'
```

**小贴士**：把 `jq` 常用的 filter 写成 snippet 存到 `~/.jq` 文件里，然后用 `jq -f ~/.jq` 引用，重复使用的查询就不必每次都手打了。

## ✨ 今日一句

> **"The most dangerous phrase in the language is: 'We've always done it this way.'"**
> — Grace Hopper (计算机科学家、COBOL 语言发明者、美国海军少将)
>
> 语言中最危险的一句话是：「我们一直都是这么做的」。
>
> 每次听到这句话，都值得停下来想想：是习惯在驱动你，还是理性在驱动你？从 `os.path` 换到 `pathlib`，从 `grep` 换成 `ripgrep`，从手写 `json.loads` 换成 `jq`——很多「一直都是这么做的」事情，其实有更好的做法，只是你没有去看一眼而已。

## 💭 技术随想：两根方波，怎么同时说清"转了多少"和"往哪转"

给关节接上编码器，手慢慢转轮子，串口里的位置读数却纹丝不动。第一反应是线接错了、A/B 反了、供电没上——查了一圈都没问题。最后发现：主循环 1kHz 读一次，编码器却在以 4000 counts/s 的速度出数——每 1ms 正好走完一整个四状态循环，每次采样看到的都是同一个状态。**轮子在转，采样点却每次都踩在同一格上，看起来就像停了。**

这件事让我重新捋了一遍正交编码器的原理。它只有两根线，都是方波，没有一根叫"方向"——方向藏在两路方波的**相位关系**里。而"转了多少"藏在**边沿的个数**里。两件事共用两根线，靠的是一张只有四个状态的小表。

### 一、四个状态，一条只许走一步的环

把 A、B 两相拼成一个两位二进制数，一共只有四种可能：

| 状态 | A | B | 正转下一步 | 反转下一步 |
|---|---|---|---|---|
| 0 | 0 | 0 | 10（A 先变） | 01（B 先变） |
| 1 | 1 | 0 | 11（B 先变） | 00（A 先变） |
| 2 | 1 | 1 | 01（A 先变） | 10（B 先变） |
| 3 | 0 | 1 | 00（B 先变） | 11（A 先变） |

正转时状态按 `00 → 10 → 11 → 01 → 00` 循环，反转就倒着走。这张表有两个性质，缺一不可：

1. **每一步只有一位变化**（格雷码）。所以任一时刻，只要看"哪一位刚变、变成什么"，就能判断方向，不需要知道绝对相位。
2. **两相相差 90°**。如果相差 180°，A、B 会同时跳变，"谁先变"这个信息就没了——这也是为什么正交编码器宁可牺牲一半的边沿间隔，也要把相位错开四分之一周期。

解码的本质就是一张状态转移表：记住上一个状态，跟当前状态比，前进一步记 +1，后退一步记 -1，原地不动记 0。**这也解释了为什么 A 是高电平不代表正转**——高电平只是四个状态里的两个，方向在"从哪个状态来、往哪个状态去"里。

### 二、x1 / x2 / x4：分辨率是乘上去的，误差也是

同一段运动，可以只数 A 的上升沿（x1）、数 A 的两个边沿（x2）、或者四个状态全解（x4）：

- 1000 线编码器，x1 = 1000 counts/转，x2 = 2000，x4 = 4000；
- 减速比 1:50 时，输出轴 200000 counts/转，账面上每计数 **0.0018°**；
- 实验里 375 个正交周期，三种解法分别数出 375 / 750 / 1500——倍数关系一分不差。

但"分辨率"和"精度"是两件事。x4 把理论分辨率乘了 4，也把**抖动**乘了 4：静止时 A 线上一个毛刺，在 x4 眼里就是一次完整的正反步进。而真实的误差来源根本不在计数方式：

- 码盘偏心、安装不同心——转一圈的计数不均匀；
- 齿轮间隙——换向时电机转了、输出轴还没动，编码器却已经在数；
- 联轴器打滑、皮带弹性——电机端和负载端根本不是同一个角度。

所以 0.0018° 是"能分辨的最小刻度"，不是"能测准的最小误差"。**刻度再细，尺子本身弯了也没用。**

### 三、采样太慢：轮子在转，读数却像停了

这是今天实验里最有意思的一段。同一段 4000 counts/s 的运动，换不同采样率去读：

- **1 kHz**：每 1ms 正好 4 个计数 = 一整个状态循环，每次看到的都是 00 → 读到 **0**；
- **500 Hz**：每步 8 个计数 = 两个循环，还是 00 → 也读到 **0**；
- **2 kHz**：每步 2 个计数，状态每次跨两步 → 全部判为非法跳变，计数仍是 **0**；
- **700 Hz**：每步 5.71 个计数，状态乱跳 → 只数到 100（真实的 5%），还夹着 250 次非法跳变；
- **4 kHz 及以上**：每步 ≤1 个计数，读数 2000/2000，完全正确。

1kHz 读不到，不是"精度不够"，是**混叠**：采样频率和信号频率形成了整数倍关系，每次都采在同一个相位上。现实里更阴险的是 700Hz 那种情况——它不报错，只是给你一个看起来很合理、但小了 20 倍的速度值，PID 拿着这个速度去闭环，越调越歪。

工程上的结论很干脆：**边沿计数必须交给硬件**。STM32 的定时器有 encoder mode，ESP32 有 PCNT，专用芯片有正交解码器——它们在几十 MHz 的时钟上数边沿，CPU 只需要定期读计数寄存器、做个减法。软件轮询不是"慢一点"，是"在特定速度下会完全瞎掉"，而且失效是静默的。

### 四、毛刺、漏边沿、上电失忆

**毛刺。** 静止时 A 线上来一个 100µs 的毛刺，状态走 `00 → 10 → 00`：带方向的状态机先 +1 再 -1，净计数 0，自己把自己抵消了；而"状态变了就 +1"的野路子留下 +2 的永久偏移。方向信息不只用来算方向，它还免费提供了一次**自校验**。

**非法跳变。** 如果 A、B 同时抖一下，状态从 `00` 直接到 `11`，一次跨了两个状态。正常转动绝不会这样——中间那个状态一定被漏掉了（采样太慢、线太长、干扰）。这时的正确反应是**报错**（丢边沿/接线异常），而不是猜一个方向继续数。实验里状态机记下 2 次非法跳变、计数保持 0；只数变化的写法则乐呵呵地加了 2。

当然，非法跳变不总是干扰：如果采样窗口内真的"正转半步又倒回来"，也会得到 delta = 2。**它能告诉你"有事情不对"，但不能替你判断是什么不对**——这就是为什么它适合当诊断计数器，而不是当纠错机制。

**上电失忆。** 增量式编码器只记变化量，上电时它不知道自己在哪。断电期间轴被手动拧过、被重力拽过，这些位移全部丢失。所以机器人关节每次上电都要回零：要么找 Z 相索引脉冲，要么碰限位开关，要么用绝对式/多圈绝对值编码器（带电池或机械齿轮记忆）。**"我知道转了多少"和"我知道现在在哪"，是两种完全不同的能力。**

顺带一个固件坑：16 位计数器在 200000 counts/s 下，每 **0.33 秒**就溢出一次。读计数还必须原子——先读高字节、被中断打断、再读低字节，拼出来就是一个错误的数。要么用 32 位定时器，要么关中断读，要么让硬件锁存。

### 五、三个反直觉的点

**一、方向不在电平里，在"谁先变"里。** 把 A、B 两根线对调，电机正转就会读成反转——不是坏了，是相位关系的定义反了。这也是为什么编码器接线不能"随便插"。

**二、x4 不是免费的精度。** 它把分辨率和抖动一起乘 4。低速、高振动、长线缆的场合，x2 甚至 x1 反而更稳；更稳妥的做法是保留 x4 计数，但用"完整四状态序列"做校验，把非法跳变单独计数。

**三、最贵的不是编码器，是"怎么数"。** 一个几百块的编码器，接上软件轮询可能只能发挥十分之一；一个几十块的编码器，接上硬件解码反而稳如老狗。**传感链路里，采样方式常常比传感器本身更决定成败。**

### 六、放远一点

- **伺服驱动器**内部用的是 17~24 位绝对编码器，一圈上百万个刻度，通信走串行协议而不是 A/B 方波；A/B 正交更多出现在步进、直流电机、云台和低成本关节上。
- **测速**有三种经典做法：M 法（固定时间内数脉冲，高速准）、T 法（测两个边沿之间的时间，低速准）、M-T 法（两者结合，全速域都还行）。低速时 M 法一个周期只数到一两个脉冲，量化误差巨大——这也是为什么慢速爬行时速度环容易抖。
- **双编码器**（电机端 + 输出端）能测出齿轮间隙：两端角度差在换向时会画出一个回环，回环宽度就是背隙。高端机器人关节用它做间隙补偿。
- 鼠标滚轮、打印机进纸、电梯门机、云台——所有"要知道转了多少"的地方，拆开几乎都是一个码盘加两路方波。

## 🧩 今日代码片段：正交编码器实验室——四个状态、三档解码、两种翻车

把两条物理规则写成了一个小模拟器：状态就是 `(A,B)` 两位，位置每走一个 x4 计数就前进一个状态。四个实验：

- **A 三档解码**：x1 / x2 / x4，再加一个"只数变化"的反面教材；
- **B 方向反转**：正转 2000 个计数再反转 500 个，净计数该是多少；
- **C 采样混叠**：同一段运动，从 500Hz 到 20kHz 各读一次；
- **D 毛刺与非法跳变**：谁会自愈，谁会把错记一辈子。

纯标准库，本机 Python 3.11.15 真实运行；下面的输出是真实运行结果。

```python
# -*- coding: utf-8 -*-
"""正交编码器实验室：四个状态、三档解码、两种翻车

纯标准库、确定性模拟（每次运行一字不差）。
一个 1000 线增量编码器，A/B 两相相差 90°：
  正转状态序列 00 -> 10 -> 11 -> 01 -> 00（A 领先 B）
  反转就是倒着走这条环
实验：
  A. x1 / x2 / x4 三档解码，同一段运动数出几个数
  B. 方向反转：净计数该往回收
  C. 采样太慢：轮子在转，读数却像停了（混叠）
  D. 毛刺与非法跳变：谁会自愈，谁会把错记一辈子
"""
import math
import sys
import unicodedata

try:
    sys.stdout.reconfigure(encoding="utf-8")
except Exception:
    pass

LINE = "=" * 74

# 状态编号 = (A, B) 两位二进制；正转沿 00 -> 10 -> 11 -> 01 循环
PINS = [(0, 0), (1, 0), (1, 1), (0, 1)]


def pad(s, width):
    w = sum(2 if unicodedata.east_asian_width(c) in "WF" else 1 for c in s)
    return s + " " * max(0, width - w)


class Decoder:
    """三种正经解码 + 一种"只数变化"的野路子"""

    def __init__(self, mode):
        self.mode = mode          # x1 / x2 / x4 / pulse
        self.count = 0            # 有符号计数
        self.invalid = 0          # 非法跳变（一次跨了两个状态）
        self.prev = None
        self.prev_a = None

    def feed(self, state):
        a, b = PINS[state]
        if self.prev is None:
            self.prev, self.prev_a = state, a
            return

        if self.mode == "x4":
            d = (state - self.prev) % 4
            if d == 1:
                self.count += 1
            elif d == 3:
                self.count -= 1
            elif d == 2:
                # 00 -> 11 这种跳变不该发生：中间那个状态被漏掉了
                self.invalid += 1
            # d == 0：没动，不计数

        elif self.mode in ("x1", "x2"):
            rise = self.prev_a == 0 and a == 1
            fall = self.prev_a == 1 and a == 0
            hit = rise if self.mode == "x1" else (rise or fall)
            if hit:
                # A 变的时候看 B：A、B 不同说明 A 领先（正转），相同说明 B 领先
                self.count += 1 if a != b else -1

        elif self.mode == "pulse":
            # 最朴素的写法：状态变了就 +1，不问方向
            if state != self.prev:
                self.count += 1

        self.prev, self.prev_a = state, a


# ------------------------------------------------------------------ 运动剧本
def pos_at(t):
    """x4 计数单位下的真实位置：0.5s 正转 4000 counts/s，之后反转 1000 counts/s"""
    if t < 0.5:
        return 4000.0 * t
    return 2000.0 - 1000.0 * (t - 0.5)


def state_at(t):
    return int(math.floor(pos_at(t))) % 4


def run(dt, duration, mode):
    d = Decoder(mode)
    n = int(round(duration / dt))
    for i in range(n + 1):
        d.feed(state_at(i * dt))
    return d


print(LINE)
print("正交编码器实验室：1000 线编码器，x4 后 4000 counts/转")
print(LINE)
print("  正转：00 -> 10 -> 11 -> 01 -> 00（A 领先 B 90°）")
print("  反转：倒着走同一条环。方向不写在电平里，写在\"谁先变\"里。")
print()

# ---------------------------------------------------------------- 实验 A
print(LINE)
print("实验 A：同一段运动，x1 / x2 / x4 各数出多少")
print(LINE)
print("  剧本：0.5 秒正转（4000 counts/s）+ 0.5 秒反转（1000 counts/s）")
truth = int(round(pos_at(1.0)))          # 1500
print(f"  真实净位移：{truth} 个 x4 计数 = {truth / 4:.1f} 个正交周期")
print()
print("  " + pad("解码方式", 22) + pad("计数", 10) + pad("相当于 x4 的", 14) + "说明")
for mode, name, note in [
    ("x1", "x1（A 上升沿）", "1 个周期 1 个数"),
    ("x2", "x2（A 双边沿）", "1 个周期 2 个数"),
    ("x4", "x4（四状态）", "1 个周期 4 个数"),
    ("pulse", "只数变化（不分方向）", "反转也当正转加"),
]:
    d = run(1 / 20000, 1.0, mode)
    ratio = d.count / truth if truth else 0
    print("  " + pad(name, 22) + pad(str(d.count), 10)
          + pad(f"{ratio:.2f}x", 14) + note)
print()

# ---------------------------------------------------------------- 实验 B
print(LINE)
print("实验 B：方向反转——净计数要跟着往回收")
print(LINE)
d = run(1 / 20000, 1.0, "x4")
half = run(1 / 20000, 0.5, "x4")
print(f"  前半段（纯正转）：{half.count} 个计数（理论 2000）")
print(f"  整段（后半段反转）：{d.count} 个计数（理论 {truth}）")
print(f"  反转让计数从 2000 退回到 {d.count}，退了 {2000 - d.count} 个")
print("  → 增量式编码器只记\"变化量\"，方向对了，减法才对；方向错了，越走越远。")
print()

# ---------------------------------------------------------------- 实验 C
print(LINE)
print("实验 C：采样太慢——轮子明明在转，读数却像停了")
print(LINE)
print("  取前 0.5 秒（真实 2000 个 x4 计数、1 转/秒），换不同采样率用 x4 解码：")
print()
print("  " + pad("采样率", 10) + pad("读到计数", 11) + pad("占真实", 9)
      + pad("非法跳变", 10) + "看到的运动")
for fs in (500, 700, 1000, 2000, 4000, 8000, 20000):
    d = run(1 / fs, 0.5, "x4")
    pct = d.count / 2000 * 100
    if d.invalid > 0 and d.count == 0:
        look = "假静止：每步跨 2 个状态，全被拒"
    elif d.count == 0:
        look = "完全静止（每步正好整周期）"
    elif abs(d.count) < 1900:
        look = "严重少计，还夹着跳变"
    elif abs(d.count) < 1990:
        look = "接近，但有漏计"
    else:
        look = "正常"
    print("  " + pad(f"{fs} Hz", 10) + pad(str(d.count), 11)
          + pad(f"{pct:.0f}%", 9) + pad(str(d.invalid), 10) + look)
print()
print("  1 kHz 采样、编码器 4000 counts/s：每 1ms 正好走 4 个计数 = 一整圈状态，")
print("  每次看到的都是同一个状态 00 —— 混叠把它变成了\"纹丝不动\"。")
print("  这不是编码器坏了，是采样定理在方波上又演了一遍。")
print()

# ---------------------------------------------------------------- 实验 D
print(LINE)
print("实验 D：一个毛刺，谁自愈，谁记一辈子")
print(LINE)
print("  轮子静止在 00 状态。A 线上来了一个 100µs 的毛刺：00 -> 10 -> 00")
print()
for mode, name in [("x4", "x4 状态机（带方向）"), ("pulse", "只数变化（不分方向）")]:
    d = Decoder(mode)
    for s in (0, 1, 0, 0, 0):
        d.feed(s)
    print(f"  {pad(name, 22)} 净计数 {d.count:+d}")
print("  → 状态机先 +1 再 -1，自己把自己抵消了；只数边沿的写法留下永久偏移。")
print()
print("  更糟的：A、B 同时抖一下，00 -> 11，一次跨了两个状态")
d = Decoder("x4")
for s in (0, 2, 0):
    d.feed(s)
print(f"  x4 状态机：计数 {d.count:+d}，非法跳变 {d.invalid} 次"
      f" → 它知道\"中间有边沿没看到\"，可以报错而不是瞎猜方向")
d = Decoder("pulse")
for s in (0, 2, 0):
    d.feed(s)
print(f"  只数变化：计数 {d.count:+d} 次，还以为是正常的两次边沿")
print()

# ---------------------------------------------------------------- 分辨率
print(LINE)
print("附：分辨率是怎么乘上去的")
print(LINE)
cpr = 1000
for gear in (1, 10, 50):
    per_out = cpr * 4 * gear
    deg = 360.0 / per_out
    print(f"  {cpr} 线 × 4 = {cpr * 4} counts/转，减速比 1:{gear:<3}"
          f" → 输出轴 {per_out:>7} counts/转，每计数 {deg:.6f}°")
print()
print("  3000 rpm 的电机：4000 counts/转 × 50 转/秒 = 200000 counts/s，")
print("  也就是每 5µs 一个计数——软件轮询根本追不上，必须让定时器硬件去数。")
print()
print(LINE)
print("一句话：编码器不告诉你\"在哪\"，只告诉你\"刚刚动了多少、往哪边\"。")
print(LINE)
```

**今天收获清单：**

- **正交编码器的全部信息，就在一张四状态表里：** `00 → 10 → 11 → 01`，每一步只变一位（格雷码）。方向 = 沿环走的方向，位移 = 走了几步。
- **两相必须差 90°，不是差 180°。** 差 180° 时两路同时跳变，"谁先变"消失，方向就没了。
- **x1 / x2 / x4 是 1:2:4。** 实验里 375 个正交周期，分别数出 375 / 750 / 1500；不分方向的"只数变化"数出 2500——把反转的 500 个边沿也加进去了。
- **方向反转必须能减。** 正转 2000 再反转 500，x4 净计数 1500；只会加不会减的计数器，走回头路时账越记越大。
- **采样太慢会静默失效：** 4000 counts/s 用 1kHz 读，每步正好一个状态循环，读到 0（看起来静止）；2kHz 每步跨两个状态，全部非法；700Hz 只读到 5%。边沿计数要交给定时器硬件（STM32 encoder mode / ESP32 PCNT），CPU 只读寄存器差值。
- **带方向的状态机自带毛刺免疫：** 一个 `00→10→00` 的毛刺净计数 0；只数边沿的写法留下 +2 永久偏移。
- **`00→11` 的非法跳变是诊断信号：** 说明中间有边沿被漏掉（采样太慢/干扰/接线），应该报错，而不是猜个方向继续数。但它分不清"漏边沿"和"采样窗口内真的正反各走半步"。
- **分辨率 ≠ 精度：** 1000 线 ×4 ×50 = 200000 counts/转，账面 0.0018°/计数；码盘偏心、齿轮背隙、联轴器打滑才是误差大头。
- **增量式编码器上电不知道自己在哪：** 断电期间的位移全丢，必须靠 Z 相索引、限位开关或绝对式编码器回零。
- **16 位计数器会溢出：** 200000 counts/s 时每 0.33 秒一圈；读计数还要原子，别让中断把高低字节拆开。

## ✨ 今日一句

> 编码器从不告诉你"现在在哪"，它只记得自己刚走过多少格、朝哪边。所以机器人每次上电，都得先找一个确定的地方碰一下——有了参照，相对的变化才变成绝对的位置。

## 💭 技术随想：优先级反转——把火星探测器逼到反复重启的"排队问题"

1997 年 7 月 4 日，探路者号在火星着陆，人类第一辆火星车开始工作。几天后，地球上的工程师注意到一件怪事：探测器开始整机重启，一次、又一次，每次重启，当天采集的数据全部归零。没有硬件故障，没有宇宙射线——探测器正"按程序运行"，只是运行着运行着，把自己重启了。

后来查明，病根是一个**排队问题**：三个任务、一把锁，最着急的那个，被最不相关的人卡住了。这个 bug 从此写进了每一本实时系统教材，名字叫**优先级反转（priority inversion）**。

### 先立三个前提

**前提一：任务是分级的，而且高级可以随时"插队"。** 实时系统里，每个任务头上都标着优先级——"1 毫秒必须跑完一圈"的控制回路是高级，"晚一秒也无所谓"的日志归档是低级。调度器的铁律：**只要有更高级的任务想吃 CPU，正在跑的低级任务立刻让位**。这是"实时"二字的来源。

**前提二：共享的东西要上锁。** 两个任务碰同一块数据，就得防"读到一半被改了"：谁用谁上锁（互斥量），用完放锁。

**前提三：世界上不只有两个任务。** 还有一大堆不高不低的中优先级任务——它们不碰那把锁，但它们能吃 CPU。

三样凑齐，陷阱自动成型。

### 钥匙的故事

低优先级的 **L** 拿着唯一的钥匙进屋办事，说好"我很快"；高优先级的 **H** 来了，急事，要钥匙——没有，只能站门口等。本来 L 马上就能办完、把钥匙交出来，可这时候中优先级的 **M** 晃过来了：它不需要钥匙、也不关心 H 在等，它只知道调度器的一条规矩——"我比 L 高，我该先跑"——于是 L 被从 CPU 上换下来，M 慢慢办起自己的一大摊事。

场面就此定格：**H 在门口等钥匙，钥匙在 L 手里，L 在等 CPU，CPU 被 M 占着。**

H 是全场优先级最高的，可它的等待时间取决于 **M 有多磨蹭**——M 拖多久，H 就等多久；再晃过来一个中优先级 N，H 再等一截；来十个，等十截。这就是"反转"两个字的分量：名义顺序是 H > M > L，实际执行顺序变成了 **M > L > H**——优先级最高的那个，被压到了最后。

比"被插队"更折磨人的，是另一个词：**无界（unbounded）**。H 等锁的时间没有上界——任何冒出来的中优先级任务，都能往它的等待里加码。对实时系统来说，"最坏情况没有上界"就等于"实时性不存在"；对探测器来说，等于看门狗一看"主控这么久没动静，肯定是死了"——重启！

### 火星上到底发生了什么

低优先级的仪器任务握着信息总线的锁（那段时间它正在慢慢搬一段数据）；高优先级的『总线分发』任务被挡在门外；而图像采集、通信这些中优先级任务照常抢占 CPU。平时一点毛病没有——只有少数几条活动凑到一起，那个"最坏交错"才会出现；一出现，就是看门狗超时、整机重启、数据清零。地面团队先把它复现了（诊断的关键一笔：把某些数据流跑起来，它就开始按时重启；一停，就好了），最后定位到那把锁——**建锁的时候，没有启用『优先级继承』这个选项**。修法就是把开关打开，从地球遥控完成，不用返厂。这个故事最著名的讲述，是团队工程师事后写的《What Really Happened on Mars?》。

### 解法：优先级继承

高优先级的 H 被 L 手里的锁挡住时，L **临时"升职"**——在调度器眼里，它就跟 H 一个级别。中优先级的 M 再晃过来也抢不动 L；L 顺顺当当办完手里的事、放锁、头衔还回去，H 上位。一句话：**谁拿着钥匙而门口有人在等，谁就暂时穿上等着的人的头衔。**

另一族方案叫**优先级天花板（priority ceiling）**：建锁时就声明"这把锁可能被哪一档的任务用到"，谁拿这把锁，谁直接升到那个天花板级别。两族思路都是"临时借级别"——一个撞上了再借，一个提前借好，上世纪 90 年代初就写进了实时系统的经典论文，如今是各大 RTOS 的标准配件（真实系统里锁还能嵌套，继承会沿着等待链往上传递；这一课只用一把锁，一层就够说明问题）。

### 两个反直觉的点

**一、继承不生产时间，只是重新排队。** 实验里两两对比，总完工时刻一模一样（t=17 对 t=17、t=23 对 t=23）——H 省下来的等待，是从中优先级任务那里挪过来的。它换掉的是"顺序"，不是"工作量"。

**二、有界和无界的区别，就是"能不能算出来"。** 开了继承，H 最多等"L 把手头临界区做完"——这个数字在系统设计时就能算出来、写进实时性论证；不开继承，H 等多久取决于"全世界所有中优先级任务有多忙"，谁也说不准。

于是就有了下面这场四回合的实验——同一个故事，只拧『优先级继承』一个开关。

## 🧩 今日代码片段：优先级反转实验室——四场 tick 级模拟

这次没用多线程——要看的正是"调度器的选择"本身，所以写了个 tick 级的确定性模拟器：不用线程、不用 sleep，一格一格推进，每次运行的输出一字不差（谁对谁错一目了然，不赌运行时运气）。同一套任务——L 先拿锁、H 来拿锁被挡、M（外加 N）来凑热闹——跑四种组合：①无继承 ②有继承 ③无继承+第二个中优先级 ④有继承+第二个中优先级。每场都打印"谁在跑"的时间轴、事件清单，以及 H 的成绩单。

纯标准库，本机 Python 3.11.15 真实运行；输出为真实运行结果。

```python
# -*- coding: utf-8 -*-
"""优先级反转实验室：四个场景，tick 一格一格看调度器怎么选人。

纯标准库、确定性模拟（每次运行一字不差）——要看的正是"调度决定"本身。
角色：L 低优先级(1) 先拿锁；H 高优先级(3) 来拿锁被挡；M/N 中优先级(2) 凑热闹。
对比：无优先级继承 vs 有优先级继承（一样的事件，只差一个开关）。
"""
import sys

try:
    sys.stdout.reconfigure(encoding="utf-8")
except Exception:
    pass

LINE = "=" * 66


class Task:
    def __init__(self, name, prio, ops, arrive=0):
        self.name = name
        self.prio = prio          # 基础优先级：数大者先跑
        self.ops = ops            # 任务流：("cpu", n) / ("lock",) / ("unlock",)
        self.arrive = arrive      # 到达时刻（tick）
        self.pc = 0               # 程序计数器
        self.rem = 0              # 当前 cpu 操作还差几个 tick
        self.done = False
        self.blocked_on = None    # 被挡在谁持有的锁上（None = 没被挡）
        self.block_from = None
        self.block_ticks = 0      # 累计"被锁挡住"的 tick 数
        self.finish = None


def eff(t, owner, waiting, inheritance):
    """有效优先级 = 基础 + 继承：持有锁的人，临时提升到等待者中的最高级"""
    p = t.prio
    if inheritance and t is owner:
        for w in waiting:
            p = max(p, w.prio)
    return p


def simulate(tasks, inheritance, horizon=80):
    owner = None            # 锁的持有者（这一课只用一把锁）
    waiting = []            # 被挡在这把锁上的任务
    timeline = {}           # tick -> 跑了谁（None = 没人可跑）
    events = []
    prev = None             # 上一格在跑的任务（同优先级不来回抢，贴近真实 RTOS）
    t = -1
    while t < horizon:
        t += 1
        if all(x.done for x in tasks):
            break
        for x in tasks:
            if x.arrive == t and x.arrive > 0:
                events.append((t, f"{x.name} 到达（优先级 {x.prio}）"))
        ran = None
        while True:
            runnable = [x for x in tasks if x.arrive <= t and not x.done and x.blocked_on is None]
            if not runnable:
                break
            best = max(eff(x, owner, waiting, inheritance) for x in runnable)
            cands = [x for x in runnable if eff(x, owner, waiting, inheritance) == best]
            cur = prev if prev in cands else min(cands, key=lambda x: x.name)
            if cur.rem == 0:
                if cur.pc >= len(cur.ops):
                    cur.done = True
                    cur.finish = t
                    events.append((t, f"{cur.name} 全部做完"))
                    continue
                op = cur.ops[cur.pc]
                if op[0] == "lock":
                    if owner is None:
                        owner = cur
                        events.append((t, f"{cur.name} 拿到锁，进入临界区"))
                        cur.pc += 1
                    else:
                        cur.blocked_on = owner
                        cur.block_from = t
                        waiting.append(cur)
                        events.append((t, f"{cur.name} 想拿锁 → 被挡（锁在 {owner.name} 手里）"))
                    continue
                if op[0] == "unlock":
                    owner = None
                    events.append((t, f"{cur.name} 放锁"))
                    for w in waiting:
                        w.block_ticks += t - w.block_from
                        w.blocked_on = None
                    waiting.clear()
                    cur.pc += 1
                    continue
                cur.rem = op[1]
                cur.pc += 1
                continue
            cur.rem -= 1             # 真正消耗一个 tick
            ran = cur
            prev = cur
            if cur.rem == 0 and cur.pc >= len(cur.ops):
                cur.done = True
                cur.finish = t
                events.append((t, f"{cur.name} 全部做完"))
            break
        timeline[t] = ran
    return {"timeline": timeline, "events": sorted(events, key=lambda e: e[0])}


def ops_str(ops):
    txt = []
    for o in ops:
        txt.append(f"算{o[1]}" if o[0] == "cpu" else ("拿锁" if o[0] == "lock" else "放锁"))
    return "→".join(txt)


def make_tasks(with_n=False):
    ts = [
        Task("L", 1, [("lock",), ("cpu", 3), ("unlock",), ("cpu", 2)], arrive=0),
        Task("H", 3, [("cpu", 1), ("lock",), ("cpu", 4), ("unlock",)], arrive=1),
        Task("M", 2, [("cpu", 8)], arrive=2),
    ]
    if with_n:
        ts.append(Task("N", 2, [("cpu", 6)], arrive=3))
    return ts


def pad(s, width):
    import unicodedata
    w = sum(2 if unicodedata.east_asian_width(c) in "WF" else 1 for c in s)
    return s + " " * max(0, width - w)


def show_chart(timeline):
    n = max(timeline) + 1
    ruler = "".join((str(x // 10) if x % 10 == 0 else " ") + " " for x in range(n))
    row = "".join((timeline[x].name if timeline.get(x) else ".") + " " for x in range(n))
    print("  tick:   " + ruler)
    print("  谁在跑: " + row)


RESULTS = []


def scenario(no, title, inheritance, with_n, note):
    print(LINE)
    print(f"场景{no}：{title}")
    print(LINE)
    print("  锁的策略：" + ("优先级继承 ON —— 拿锁的人被更高优先级等着时，临时升到对方的级别"
                          if inheritance else "优先级继承 OFF —— 拿着锁的人，还是自己原来的优先级"))
    tasks = make_tasks(with_n)
    for x in tasks:
        print(f"    {x.name}  优先级 {x.prio}  到达 t={x.arrive}  任务流：{ops_str(x.ops)}")
    res = simulate(tasks, inheritance)
    print()
    show_chart(res["timeline"])
    print()
    for t, msg in res["events"]:
        print(f"    t={t:02d}  {msg}")
    hi = next(x for x in tasks if x.name == "H")
    tl = res["timeline"]
    med = sum(1 for tt in range(hi.block_from, hi.block_from + hi.block_ticks)
              if tt in tl and tl[tt] and tl[tt].name in ("M", "N"))
    print()
    print(f"  H 的成绩单：到达 t={hi.arrive} → 完成 t={hi.finish}（端到端 {hi.finish - hi.arrive} tick）")
    print(f"    被锁挡住 {hi.block_ticks} tick；挡门期间，中优先级任务跑了 {med} tick。{note}")
    RESULTS.append((f"场景{no}", hi.finish, hi.block_ticks, med))


print(LINE)
print("优先级反转实验室：H（优先级 3）要被挡多久，才能拿到锁？")
print(LINE)
print("  背景：L 先拿到锁；H 来拿锁被挡；M / N 是不碰锁、但能抢 CPU 的中优先级任务。")
print("  同一套任务、两种锁策略——只差『优先级继承』一个开关。")
print()

scenario(1, "无继承：M 插队，H 干等（经典反转现场）", inheritance=False, with_n=False,
         note="H 等的不只是 L，还有排在前面的所有人。")
scenario(2, "有继承：L 临时升到 3 级，没人插得进来", inheritance=True, with_n=False,
         note="正好等于 L 临界区剩下的长度——等待重新变得『有界』。")
scenario(3, "无继承 + 再晃过来一个中优先级 N：堵得更久", inheritance=False, with_n=True,
         note="中优先级任务每多一个，H 就多堵一截：这就是『无界』的意思。")
scenario(4, "有继承 + 再晃过来一个中优先级 N：一点没变", inheritance=True, with_n=True,
         note="M、N 再多再忙，也动不了 H 的等待。")

print()
print(LINE)
print("总成绩单：H（高优先级任务）的等待时间")
print(LINE)
print("  " + pad("场景", 10) + pad("H 完成于", 14) + pad("被挡 tick", 14) + pad("挡门期间中优先级跑了", 28))
for name, fin, blk, med in RESULTS:
    print("  " + pad(name, 10) + pad(f"t={fin}", 14) + pad(str(blk), 14) + pad(f"{med} tick", 28))
print()
print("  一句话：开了继承，H 的等待值只由『L 临界区还剩多长』决定（有界）；")
print("  不开继承，H 的等待值由『所有中优先级任务有多忙』决定（无界，谁也说不准）。")
```

```text
总成绩单：H（高优先级任务）的等待时间
==================================================================
  场景      H 完成于      被挡 tick     挡门期间中优先级跑了
  场景1     t=16          10            8 tick
  场景2     t=8           2             0 tick
  场景3     t=22          16            14 tick
  场景4     t=8           2             0 tick

  一句话：开了继承，H 的等待值只由『L 临界区还剩多长』决定（有界）；
  不开继承，H 的等待值由『所有中优先级任务有多忙』决定（无界，谁也说不准）。
```

**今天收获清单：**

- **反转的三要素：** ① 高优先级任务被低优先级手里的锁挡住；② 存在能抢占 CPU 的中优先级任务；③ 阻塞时间无上界（每一个无关任务都能加码）。缺一个都不成局。
- **最危险的从来不是"要等"，是"等多久说不准"。** 实验里：无继承时 H 被挡 10 tick，再冒一个 N 涨到 16；有继承时两场都是 2 tick——正好是 L 临界区剩下的活，能算、能写进设计里。
- **优先级继承一句话：** 拿锁者临时升到等待者中的最高级，放锁即归还——把"无界等待"压回"有界等待"。
- **继承不生产时间，只重新排队：** 两两对比总完工时刻完全相同（t=17 对 t=17、t=23 对 t=23），H 省下的等待是从中优先级任务那里挪过来的。
- **火星探路者 1997：** 仪器任务持锁、总线任务被挡、中优先级插队、看门狗反复重启；修法是把那把锁的优先级继承开关打开——从地球遥控完成。故事详情见《What Really Happened on Mars?》。
- **落地检查单：** 互斥量要用"带继承的那种"——FreeRTOS 里 xSemaphoreCreateMutex 有优先级继承、xSemaphoreCreateBinary 没有（二进制信号量没有"主人"，没法继承，别拿它当锁用）；POSIX 用 pthread_mutexattr_setprotocol(PTHREAD_PRIO_INHERIT)；Linux 上 pthread 互斥量同样支持（配实时调度策略才有完整意义）。
- **设计层面：** 临界区剪短；高优先级路径（控制回路、中断）少碰共享锁；能无锁就无锁（单生产者单消费者环缓冲是标准答案之一）；真要用共享状态，先把"谁会被谁挡"画出来算一遍。
- **看门狗是保险丝，不是方案：** 它救活了探测器，但每次重启丢一天数据——根因还得回到锁上找。

## ✨ 今日一句

> 优先级写在任务头上，"谁先走"却是在现场被一条看不见的队规决定的。优先级反转的教训：一条没人注意的队规，能悄悄改掉所有人纸面上的地位；修正它，有时候也只需要把规则改对一处——让拿钥匙的人，临时借一下等在门外的人的头衔。

## 💭 技术随想：按键消抖——"按一下"是怎么变成"按七下"的

手指按下一个按键，"咔哒"一声，动作干净利落。但在电路这一侧看完全不是这么回事：金属触点碰上的那一瞬间，其实是在反复弹跳——碰上、弹开、再碰上，像乒乓球落在桌面上，几毫秒里来回好几次，最后才安稳贴合。这段时间里信号是"疯"的：0-1-0-1 地抽搐。这就是机械触点与生俱来的天性——**触点抖动（bounce）**。典型按键抖 1~10ms，老化的、进灰的、质量差的能抖到 20ms 以上。

麻烦出在程序这头。要是代码老实巴交"来一个上升沿，算一次按下"，那手指只按了一下，程序可能被喂了七八次"按下"：菜单点一下翻三页、游戏按一次跳三下、计数器点一次加七。更阴的是这种 bug 时好时坏——换个按键就好了、温度一变又冒出来，因为它取决于"你这一下按得有多干脆"。

消抖（debounce）的思路一句话：**你说变就变，但我不马上信；等你稳住一段时间，我才认账**。大白话讲就是给信号一个"冷静期"：连续若干次采样都是同一个值，才承认电平真的变了；中间那些翻来覆去的毛刺，一律当没看见。

工程上有三条路线：硬件派（RC 低通 + 施密特触发器，或专用消抖芯片——零 CPU 占用，但料表花钱、参数焊死）；软件"延时确认"派（发现变化后隔 10~20ms 再看一眼，一致才认——简单，但容易写成 `sleep` 阻塞）；软件"定时采样"派（定时器每个 tick 采一次，连续 N 次一致才确认——不阻塞、参数可调，还能顺手量按住时长、识别长按）。嵌入式里第三条是主流，今天的演示也是它。

一个常被忽略的细节：正确顺序是**先消抖、再做边沿检测**。反过来的话，边沿检测吐出的"按下/松开"事件流本身就是脏的，后面再补救就晚了。另一个细节：消抖窗口不是越大越保险——太小防不住劣质按键，太大会把快速连点吞掉、甚至把两次按键合并成一次（详见实验 3）。

按键抖动一般 ≤10ms，而人类"快速连点"的间隔普遍在 50~80ms 以上，所以 10~20ms 是那个"刚刚好"的窗口：稳稳盖住抖动，又不挡人手速。你每天摸的键盘、手柄、电梯按钮、遥控器，背后都是这段 10~20ms 的耐心在兜底。

## 🧩 今日代码片段：同一段按键波形，三种处理方式的对照实验

构造一段毫秒级的"真实"触点波形：1000ms 按下、1300ms 松开；1400ms 再按下、2300ms 才松开（模拟一次长按）。然后做三个实验：① 裸信号直接数上升沿；② 20ms 窗口消抖；③ 5 / 20 / 120ms 三档窗口对比——亲眼看看"窗口开太大"会出什么事。

```python
# -*- coding: utf-8 -*-
"""按键消抖演示：同一段机械触点波形，三种处理方式的结果对比（真实可运行）"""
import sys
try:
    sys.stdout.reconfigure(encoding="utf-8")
except Exception:
    pass

T = 2600  # 采样总长 2600ms，每 1ms 采一个点

# 一段"真实"的机械触点波形：手指 1000ms 按下、1300ms 松开；
# 1400ms 又按下、2300ms 才松开。括号里的数字是电平翻转时刻(ms)
EDGES = [
    (1000, 1), (1002, 0), (1003, 1), (1005, 0), (1006, 1), (1008, 0), (1009, 1),  # 按下：弹跳 9ms
    (1300, 0), (1301, 1), (1303, 0), (1304, 1), (1305, 0), (1307, 1), (1309, 0),  # 松开：同样不老实
    (1400, 1), (1401, 0), (1403, 1), (1404, 0), (1406, 1), (1407, 0), (1410, 1),  # 第 2 次按下（要长按）
    (2300, 0), (2302, 1), (2303, 0), (2305, 1), (2306, 0), (2308, 1), (2310, 0),  # 松开
]


def build_raw():
    raw, v, i = [0] * T, 0, 0
    for t in range(T):
        while i < len(EDGES) and EDGES[i][0] <= t:
            v, i = EDGES[i][1], i + 1
        raw[t] = v
    return raw


def rising(sig):
    return [t for t in range(1, len(sig)) if sig[t] == 1 and sig[t - 1] == 0]


def debounce(raw, need):
    """连续 need 个采样值一致才认账；返回(消抖后波形, 电平变化点)"""
    stable = cand = raw[0]
    cnt = 1
    changes = []
    trace = [raw[0]] * T
    for t in range(1, T):
        v = raw[t]
        if v == cand:
            cnt += 1
        else:
            cand, cnt = v, 1
        if cnt >= need and cand != stable:
            stable = cand
            changes.append((t, stable))
        trace[t] = stable
    return trace, changes


def as_events(changes):
    ev, down = [], None
    for t, lv in changes:
        if lv == 1:
            down = t
        elif down is not None:
            ev.append((down, t))
            down = None
    return ev


raw = build_raw()

print("=" * 58)
print("实验 1：裸信号直接数上升沿（不做任何保护）")
print("=" * 58)
re = rising(raw)
print(f"2600ms 内一共数出 {len(re)} 个上升沿：")
print(f"  第 1 次物理按下(1000ms)：{'、'.join(map(str, re[:7]))}")
print(f"  第 2 次物理按下(1400ms)：{'、'.join(map(str, re[7:]))}")
print(f"→ 手指只按了 2 下，裸数法却数出 {len(re)} 次“按下”——多出来的全是触点结巴。")

print()
print("=" * 58)
print("实验 2：消抖——连续 20 个采样一致(=20ms 窗口)才认账")
print("=" * 58)
trace, ch = debounce(raw, 20)
for t, lv in ch:
    print(f"  {t:5d}ms  电平 {'0 → 1 （按下）' if lv else '1 → 0 （松开）'}")
ev = as_events(ch)
print("→ 检测到 2 次按键：")
for i, (a, b) in enumerate(ev, 1):
    tag = "长按·按住不放" if b - a >= 500 else "短按·点一下"
    print(f"     第 {i} 次：{a} → {b}ms，按住 {b - a}ms，判定【{tag}】")

print()
print("=" * 58)
print("实验 3：窗口不是越大越保险——5 / 20 / 120ms 对比")
print("=" * 58)
for need in (5, 20, 120):
    _, ch3 = debounce(raw, need)
    ev3 = as_events(ch3)
    lat = f"+{ev3[0][0] - 1000}ms" if ev3 else "—"
    d = " + ".join(f"{b - a}ms" for a, b in ev3)
    extra = "（两次按键被吞并！）" if len(ev3) < 2 else ""
    print(f"  窗口 {need:>3}ms：数出 {len(ev3)} 次 | 首键延迟 {lat} | 时长 {d}{extra}")

print()
print("=" * 58)
print("特写：第 1 次按下的前前后后（每格 = 1ms，995ms → 1044ms）")
print("=" * 58)
lo, hi = 995, 1045
bar = lambda x: "█" if x else "·"
print("        " + "".join("┃" if t % 10 == 0 else " " for t in range(lo, hi)) + "   ← 每 10ms 刻度")
print("裸信号：" + "".join(bar(v) for v in raw[lo:hi]))
print("消抖后：" + "".join(bar(v) for v in trace[lo:hi]))
print("        " + " " * 5 + "↑1000ms 接触" + " " * 16 + "↑1028ms 才被确认")
```

**说明：**

- 实验 1 里注意：7 个上升沿不全是"按下"时抖出来的——一次完整按压，弹跳出现在按下和松开**两个**瞬间（按下 4 个 + 松开 3 个），按两下就是 14 次。只防按下、不防松开，照样数出双份。
- 实验 2：20ms 窗口下得到 4 个干净的电平变化，每个都比物理动作晚 28~29ms——这就是消抖的"代价"。但按住时长 300ms / 900ms 与物理完全一致：**两端各平移同样的确认延迟，差值不变**。所以想用按住时长判"短按 / 长按"，消抖一点都不吃亏。
- 特写图：裸信号在 1000~1009ms 之间像心电图一样抽了六七个来回；消抖后直到 1028ms 才干净利落地翻一次。这就是"20ms 冷静期"的形状——不是看不见毛刺，是假装看不见。
- 实验 3 是今天的教训担当：窗口开到 120ms，另外两档都数对的 2 次按键只剩 1 次——松开只被"疑似"了 91ms（1309→1400）没等来确认，第二次按下已经开始抖动，于是两次按键被并成一次 1301ms 的"超长按"。再看首键延迟：+13ms → +28ms → +128ms，窗口越大越迟钝。**窗口必须明显小于两次真实按键之间的最小间隔。**
- 参数换算：窗口 = 连续一致采样数 × 采样周期。这里是 1ms × 20 = 20ms；换成 5ms 的定时器 tick，4 次一致就是同样的 20ms 窗口——别只盯着 N。
- 演示里"按下 = 1"是为了好看；真实电路多是上拉电阻 + 按下接地（低电平有效），逻辑刚好反过来，消抖方法一字不改。
- 落地建议：MCU 里跑 1ms 定时器调用计数逻辑（像 demo 这样非阻塞），或按键中断只负责"置标志"、由定时器任务去确认；千万**不要在中断服务函数里 `sleep` 等抖动结束**——那是拿整个系统的实时性给一个按键陪葬。还有一种"运气消抖"：有人从不写消抖也没出过事，可能只是主循环恰好跑得比抖动慢、毛刺被动"漏采"了——一旦换快 MCU 或优化循环速度，幽灵立刻现身。别把运气当设计。

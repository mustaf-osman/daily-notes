# 📅 2026年10月23日 日报

## 💭 技术随想：你发的是消息，网线上跑的是字节

发送端：

```python
sock.sendall(b'{"cmd":"forward"}\n')
sock.sendall(b'{"cmd":"stop"}\n')
```

接收端：

```python
data = sock.recv(1024)      # 看起来像"收一条消息"
```

这两段代码放在一起，几乎所有人第一眼都觉得没问题。我在回环上连续发了 50 条，也确实一条不少、顺序还对。于是这种东西就这么上了线，然后在某次网络抖动、某次负载升高、某台配置不同的机器上，突然开始"偶尔少一条指令"。

今天把这件事拆开量了一遍，结论只有一句：**`send` 的次数和 `recv` 的次数没有任何关系，一次都没有。**

### 一、50 次 send，对端 recv 到几次不由你决定

同一段发送代码、同一台机器、同一个回环，连跑 10 轮：

| 场景 | send 次数 | recv 次数 | 单次最大 | 说明 |
|---|---|---|---|---|
| 突发 50 帧 × 40 B，recv(4096) | 50 | **44~50**（10 轮） | 200 B ≈ 5 帧 | 10 轮里有 5 轮出现"一次收多帧" |
| 每帧后 sleep 2 ms，recv(4096) | 50 | 50 | 40 B | 看起来完美，因为节奏慢了 |
| 突发 50 帧，recv(64) | 50 | 50 | 40 B | 巧合：64 > 40，一帧刚好装下 |
| 突发 50 帧，recv(1) | 50 | **2000** | 1 B | 1950 个边界落在帧中间 |

第二行是最有欺骗性的：只要每帧之间停 2 毫秒，它就变成漂亮的"一发一收"。第三行也一样，只要缓冲区比帧大一点点，边界就"恰好"对上了。它们没做对任何事，只是没赶上坏运气。

反过来，一条消息比 `recv` 的缓冲大，就一定会被切开。同一个回环上发一条 5000 字节的消息：

| 接收方式 | recv 次数 | 每次收到 |
|---|---|---|
| `recv(1024)` | 5 | 1024, 1024, 1024, 1024, 904 |
| `recv(8192)` | 1 | 5000 |

注意这不是"网络拆包"，是我自己把接收缓冲设成了 1024。**消息的长度由发送方决定，`recv` 一次能拿多少由接收方决定，两者之间没有任何约定。**

TCP 保证的只有三件事：连接没断的时候，字节按顺序到、不重复、不缺失。它从来没保证"你 send 一次，对面 recv 一次"。内核的收发缓冲是两个水池，`send` 是往里倒水，`recv` 是从另一个池子里舀水——舀多少，看你的瓢有多大、池子里当时有多少水。

### 二、它不报错，只是把 25.5 变成 0.5

最典型的写法是这样，我自己也写过很多次：

```python
chunk = conn.recv(4096)
for line in chunk.split(b"\n")[:-1]:      # 最后一段丢掉，以为是下一条的开头
    handle(line)
```

发送端把 `TEMP 25` 和 `.5\n` 分两次发出来（这在真实链路里太常见了）。三种接收写法，实测结果：

| 写法 | 收到的两块 | 解析出的内容 |
|---|---|---|
| 逐块 `split`（错误） | `[24, 9]` | `'POS 12.5 0.0 3.2'`、`'.5'`、`'ERR 0'` |
| 留尾部缓冲（正确） | `[24, 9]` | `'POS 12.5 0.0 3.2'`、`'TEMP 25.5'`、`'ERR 0'` |
| `socket.makefile('rb')` | `[24, 9]` | 同上，三行全对 |

第一行不是"少了一条数据"这么简单：它把 `TEMP 25.5` 劈成了 `TEMP 25`（被丢掉）和 `.5`（被当成一条完整消息交上去）。温度从 25.5 度变成 0.5 度，格式合法、数值荒谬、没有任何异常。

如果下游是位置控制，电机不会报错，它只会转错。**分帧 bug 的危险不在于崩溃，而在于它长得像正常数据。**

正确写法其实只有三行：

```python
buf += chunk
while b"\n" in buf:
    line, buf = buf.split(b"\n", 1)
    handle(line)
```

或者直接用 `sock.makefile("rb")` 逐行读——标准库的缓冲已经替你留了尾部。但要注意一个坑：`makefile` 有自己的缓冲层，**混用 `conn.recv()` 和 `f.readline()` 会互相偷数据**，一个协议里选一种读法。

### 三、三种分帧方案，各自的死法

| 方案 | 开销 | 适合 | 什么时候死 |
|---|---|---|---|
| 定长 | 0 字节 | 固定结构（寄存器读、老式传感器） | 字段一改、长度可变 → 整条流永久错位 |
| 分隔符 | 1 字节/帧 | 文本、日志、AT 指令 | payload 里出现分隔符 → 假帧 |
| 长度前缀 | 1/2/4 字节/帧 | 二进制、变长结构 | 长度字段被拆开；长度字段会撒谎 |

**分隔符方案的湿滑地面。** 10000 帧 40 字节的随机二进制（固定种子）里，`0x0A` 出现了多少？

| 指标 | 数值 |
|---|---|
| 含 `0x0A`（换行）的帧 | 1481 帧（14.81%） |
| 含 `0xC0`（SLIP 的 END）的帧 | 1424 帧（14.24%） |
| 含 `0xDB`（SLIP 的 ESC）的帧 | 1433 帧（14.33%） |
| SLIP 需要转义的帧 | 2665 帧（26.65%） |
| 转义后字节 | 400000 → 403091（+0.77%） |

也就是说，**每 7 帧就有 1 帧带着换行符**。用换行分隔裸二进制结构体，等于每隔几帧往解析器里扔一颗雷。

值得注意的另一点：SLIP 转义的带宽代价只有 0.77%（100 Hz × 40 B 的链路，每秒多 30.9 字节，一分钟 1.8 KB）。**转义在带宽上几乎是免费的，贵的是两端都要实现正确的转义/反转义、每条消息都要逐字节扫描，以及这些代码的 bug 面积。** 对遥控链路来说，这个交换往往是划算的：带宽不值钱，错了要命。

**长度前缀的坑不在长度，在"前缀"。** 1 字节缓冲下收 50 帧，`recv` 被调用了 **1264 次**（头部 200 次 + 载荷 1064 次）；4096 缓冲下是 100 次。真实代码当然不会用 1 字节缓冲，但 `read_exact` 那个循环在真实链路上一定会转不止一圈——**头部本身也会被拆开，这件事必须写在代码里，而不是写在注释里。**

还有长度字段会撒谎：

```text
对端声明长度 0xFFFFFFFF = 4294967295 字节，解码器上限 1048576 字节 → 接受=False
实际为这条"帧"缓冲的字节：0（头部读完就断开，没有跟着声明长度去申请内存）
若不设上限：会尝试读满 4294967295 字节 ≈ 4.0 GiB
```

一个上线的服务，收到 4 个字节的头部就能让进程申请 4 GiB，这不是"异常输入"，这是**协议没写上限**。

四种方案的开销（纯算术）：

| payload | 换行分隔 +1 B | 长度 1 B | 长度 2 B | 长度 4 B |
|---|---|---|---|---|
| 8 B | +12.5% | +12.5% | +25.0% | +50.0% |
| 40 B | +2.5% | +2.5% | +5.0% | +10.0% |
| 256 B | +0.4% | +0.4% | +0.8% | +1.6% |
| 1024 B | +0.1% | +0.1% | +0.2% | +0.4% |

小消息用 4 字节长度前缀，开销能到 50%。2 字节（单帧上限 64 KB）在绝大多数控制协议里都够用，还省一半。

### 四、错位之后：能不能"重新对上"

上面都是"怎么切"。更狠的问题是：**流里丢了一个字节，切错了，你怎么知道？**

5 帧 × 24 字节，在第 2 帧 payload 中间删掉 3 个字节（串口丢字节、DMA 缓冲溢出都长这样）：

| 解码器 | 结果 |
|---|---|
| 纯长度前缀（无魔数、无校验） | 解出 2 帧，停在第 56 字节；长度字段读成 407061315（约 388 MiB），只能断开 |
| 魔数 + 长度 + CRC32 | 解出 4/5 帧，CRC 失败 1 次，丢弃垃圾 28 字节，缓冲区残留 0 |

纯长度前缀那一行要注意：它**没有在出问题的地方报错**。它先交出第一帧（对的），再交出第二帧（错的——那 24 字节里混进了下一帧头部的 3 个字节），然后才读到 407061315 这个天文数字。**一条错误数据已经安安静静地进了业务逻辑，错误报告在两步之后才来。**

魔数 + CRC 的版本没有变聪明，它只是多了两个检查点：魔数负责"从哪个字节开始"，CRC 负责"这 24 个字节对不对"。对不上就丢掉一个字节重新找魔数——所以它牺牲了坏掉的那一帧，但后面三帧全部活了下来。

一句话：**长度前缀只解决"怎么切"，不解决"切错了怎么办"。** 二进制协议里，`魔数 + 长度 + CRC` 是三个一起用的，不是三选一。

顺带说一句 UDP：数据报天生有边界，不需要分帧，但它自带的是"要么整条到，要么不到"；超过 MTU 的长包会被 IP 分片，丢一片整条报废。**分帧的复杂度不会消失，只会换个地方出现。**

### 五、缓冲区纪律

1. `recv` 返回 0 是**对端关闭**，不是"暂时没数据"。此时未完成的半帧必须丢弃并计数，不能留在缓冲里等下一轮。
2. 一次 `recv` 之后要**循环解析到不能再解析**，而不是"一次 recv 解析一次"。粘包就是靠这个循环消化的。
3. 解码器要**状态化**：`buffer` 是对象的成员，不是函数里的局部变量。
4. 三个上限缺一不可：单帧长度上限、单连接缓冲上限、半帧等待超时。缺哪个，哪个就是远端可以打爆你的点。
5. **读超时不是消息边界。** 超时只说明"现在没有"，不代表"这一条结束了"。
6. 别在收包线程里做重活。解析完就丢队列——收得慢会让内核缓冲填满，进而阻塞发送端，控制延迟从 2 ms 变成 200 ms，而现象看起来像"网络问题"。
7. 用 `makefile` 就别再直接 `recv`，缓冲层会互相偷数据。
8. 打点四个数：坏帧数、垃圾字节数、每帧重组了几次、单次 `recv` 最大值。这四个数比一千行日志有用。
9. 测试用例至少三条：**把一条消息拆成两次 send、把两条消息合成一次 send、在流中间删几个字节**。这三条能抓住九成的分帧 bug。回环上"一次发一次收"跑通了，什么都不能证明。

### 六、能抄走的部分

1. 协议文档第一句就写清楚**怎么分帧**，别让人从代码里反推。
2. 二进制：`魔数(2) + 长度(2) + CRC32(4) + payload`，读长度后**先比上限再分配**。
3. 文本：一行一条 JSON，用标准序列化器（它会把控制字符转义，所以 payload 里的换行不会变成真换行——这就是 JSON Lines 安全的原因），别手拼字符串，别裸 `split('\n')`。
4. 解码器写成一个类：`feed(bytes) -> list[frame]`，内部持有 buffer 和统计；EOF 时返回"还剩多少字节没成帧"。
5. 上限三件套：帧长、缓冲、超时。
6. 用故障注入测，别等线上教。

最后一句判断：我们自己的 rp_server 里，UDP 9000 那条口令链路天生有边界，而头部舵机的 AT 文本通道是纯字节流——同一个项目里两种完全不同的纪律。**UDP 那条错了丢一帧，串口这条错了会一直错下去**，因为字节流没有"重新同步"这个概念，除非协议自己给了魔数。

## 🧩 今日代码片段：分帧实验室

这个脚本不模拟，全部是真的：真开 TCP 回环、真的 `send`、真的被内核合并或切开、真的在流中间删 3 个字节再喂给两个解码器。

- **实验 A**：50 次 send 到底变成几次 recv（突发 / 加间隔 / 小缓冲 / 1 字节缓冲，各跑一遍），外加"一条消息大于接收缓冲"的必然切分；
- **实验 B**：半行被拆成两次 send，逐块 `split` / 留尾部 / `makefile` 三种写法的真实解析结果；
- **实验 C**：10000 帧随机二进制里，`0x0A`、`0xC0`、`0xDB` 的出现率，以及 SLIP 转义的真实字节开销；
- **实验 D**：长度前缀下 `read_exact` 的短读次数（1 字节缓冲 1264 次），以及声明 4 GiB 的帧被上限拦下；
- **实验 E**：删掉 3 个字节后，纯长度前缀 vs `魔数+长度+CRC32` 两种解码器的恢复能力。

```python
# -*- coding: utf-8 -*-
"""分帧实验室：字节流里到底有没有“一条消息”

A 发送边界 vs 接收边界（突发 / 加间隔 / 小缓冲）
B 分隔符方案：一块一块独立 split，半行怎么变成假数据
C 二进制 payload 撞上 0x0A：分隔符方案的湿滑地面
D 长度前缀：头部也会被拆开、长度字段会撒谎
"""
import random
import socket
import struct
import sys
import threading
import time
import zlib

try:
    sys.stdout.reconfigure(encoding="utf-8")
except Exception:
    pass

LINE = "=" * 78
HOST = "127.0.0.1"
FRAME_LEN = 40
NFRAMES = 50


def serve(port_holder, handler, ready, out):
    srv = socket.socket(socket.AF_INET, socket.SOCK_STREAM)
    srv.setsockopt(socket.SOL_SOCKET, socket.SO_REUSEADDR, 1)
    srv.bind((HOST, 0))
    srv.listen(1)
    port_holder.append(srv.getsockname()[1])
    ready.set()
    conn, _ = srv.accept()
    try:
        handler(conn, out)
    except Exception as e:                                  # noqa: BLE001
        print("  [服务端异常] %r" % (e,))
    finally:
        conn.close()
        srv.close()


def run_pair(handler, client):
    port_holder, ready, out = [], threading.Event(), {}
    t = threading.Thread(target=serve, args=(port_holder, handler, ready, out), daemon=True)
    t.start()
    ready.wait(2)
    c = socket.create_connection((HOST, port_holder[0]))
    c.setsockopt(socket.IPPROTO_TCP, socket.TCP_NODELAY, 1)   # 发送端关掉 Nagle
    try:
        client(c)
    finally:
        try:
            c.shutdown(socket.SHUT_WR)
        except OSError:
            out["reset"] = True        # 对端已经先关了：这里不是实验结论，只是收尾
        t.join(3)
        c.close()
    return out


def frame(i):
    return ("F%02d|" % i).encode() + b"A" * (FRAME_LEN - 4)


def drain(sock, bufsize):
    """一直读到 EOF，只记每次收了多少字节"""
    sizes = []
    while True:
        p = sock.recv(bufsize)
        if not p:
            break
        sizes.append(len(p))
    return sizes


def analyze(sizes, frame_len):
    """统计：有多少次 recv 的结尾落在帧中间；有多少次一次收里含多条消息"""
    ends, total = [], 0
    for s in sizes:
        total += s
        ends.append(total)
    cross = sum(1 for e in ends[:-1] if e % frame_len)
    multi, start = 0, 0
    for e in ends:
        if (e - 1) // frame_len > start // frame_len:
            multi += 1
        start = e
    return cross, multi


def analyze_var(sizes, lens):
    """变长帧：recv 边界是不是正好落在某条消息的分界上"""
    bounds, total = set(), 0
    for n in lens:
        total += n
        bounds.add(total)
    ends, total = [], 0
    for s in sizes:
        total += s
        ends.append(total)
    cross = sum(1 for e in ends[:-1] if e not in bounds)     # 切在消息中间
    start, multi = 0, 0
    for e in ends:
        if any(start < b < e for b in bounds):                # 一块里装了不止一条
            multi += 1
        start = e
    return cross, multi


def a_big_message(payload_len, width):
    """一条消息比 recv 缓冲大：一次 send，必然被切成好几次 recv"""
    payload = bytes((i * 7) % 251 for i in range(payload_len))

    def handler(conn, out):
        out["sizes"] = drain(conn, width)

    def client(c):
        c.sendall(payload)

    out = run_pair(handler, client)
    return out["sizes"], payload_len


# ----------------------------------------------------------------- 实验 A
def a_burst(client_sleep, bufsize):
    def handler(conn, out):
        out["sizes"] = drain(conn, bufsize)

    def client(c):
        for i in range(NFRAMES):
            c.sendall(frame(i))
            if client_sleep:
                time.sleep(client_sleep)

    out = run_pair(handler, client)
    sizes = out["sizes"]
    cross, multi = analyze(sizes, FRAME_LEN)
    return sizes, cross, multi


def a_variable(width=4096, pace=0.0):
    """变长 JSON 消息：50 条长度都不一样，看 recv 边界会不会切在消息中间"""
    msgs = []
    for i in range(NFRAMES):
        msgs.append(('{"i":%d,"pos":[%.2f,%.2f],"state":"run"}\n'
                     % (i, i * 0.37, -i * 0.11)).encode())
    lens = [len(m) for m in msgs]

    def handler(conn, out):
        out["sizes"] = drain(conn, width)

    def client(c):
        for m in msgs:
            c.sendall(m)
            if pace:
                time.sleep(pace)

    out = run_pair(handler, client)
    cross, multi = analyze_var(out["sizes"], lens)
    return out["sizes"], lens, cross, multi


# ----------------------------------------------------------------- 实验 B
NAIVE = b"POS 12.5 0.0 3.2\nTEMP 25"


def b_naive():
    def handler(conn, out):
        chunks = []
        while True:
            p = conn.recv(4096)
            if not p:
                break
            chunks.append(p)
        lines = []
        for ch in chunks:
            lines.extend(x.decode("utf-8", "replace") for x in ch.split(b"\n")[:-1])
        out["lines"] = lines
        out["chunks"] = [len(c) for c in chunks]

    def client(c):
        c.sendall(NAIVE)
        time.sleep(0.05)
        c.sendall(b".5\nERR 0\n")

    return run_pair(handler, client)


def b_buffered():
    def handler(conn, out):
        buf = b""
        lines = []
        chunks = []
        while True:
            p = conn.recv(4096)
            if not p:
                break
            chunks.append(len(p))
            buf += p
            while b"\n" in buf:
                line, buf = buf.split(b"\n", 1)
                lines.append(line.decode("utf-8", "replace"))
        out["lines"] = lines
        out["chunks"] = chunks

    def client(c):
        c.sendall(NAIVE)
        time.sleep(0.05)
        c.sendall(b".5\nERR 0\n")

    return run_pair(handler, client)


def b_makefile():
    """标准库自带的缓冲：socket.makefile 的 readline 已经帮你留尾部了"""
    def handler(conn, out):
        f = conn.makefile("rb")
        out["lines"] = [l.decode("utf-8", "replace").rstrip("\r\n") for l in f]
        f.close()

    def client(c):
        c.sendall(NAIVE)
        time.sleep(0.05)
        c.sendall(b".5\nERR 0\n")

    return run_pair(handler, client)


# ----------------------------------------------------------------- 实验 C
END, ESC = 0xC0, 0xDB


def slip_escape(payload):
    out = bytearray()
    extra = 0
    for b in payload:
        if b == END:
            out += bytes((ESC, 0xDC))
            extra += 1
        elif b == ESC:
            out += bytes((ESC, 0xDD))
            extra += 1
        else:
            out.append(b)
    return bytes(out), extra


def c_delimiter_vs_binary():
    rng = random.Random(20261023)
    frames = [rng.randbytes(FRAME_LEN) for _ in range(10000)]
    hit_lf = sum(1 for f in frames if b"\n" in f)          # 换行分隔的假帧
    hit_end = sum(1 for f in frames if END in f)
    hit_esc = sum(1 for f in frames if ESC in f)
    escaped, extra = 0, 0
    for f in frames:
        _, e = slip_escape(f)
        extra += e
        escaped += 1 if e else 0
    total_before = FRAME_LEN * len(frames)
    return {
        "n": len(frames),
        "hit_lf": hit_lf,
        "hit_end": hit_end,
        "hit_esc": hit_esc,
        "escaped": escaped,
        "extra": extra,
        "before": total_before,
        "after": total_before + extra,
    }

def recv_exact(sock, n, chunk):
    buf = bytearray()
    calls = 0
    while len(buf) < n:
        p = sock.recv(min(chunk, n - len(buf)))
        calls += 1
        if not p:
            raise EOFError("对端在收满 %d 字节前关闭" % n)
        buf += p
    return bytes(buf), calls


def d_length_prefix(payloads, chunk):
    def handler(conn, out):
        got, hcalls, pcalls = [], 0, 0
        for _ in range(len(payloads)):
            head, n1 = recv_exact(conn, 4, chunk)
            (ln,) = struct.unpack(">I", head)
            body, n2 = recv_exact(conn, ln, chunk)
            got.append(body)
            hcalls += n1
            pcalls += n2
        out.update(got=got, hcalls=hcalls, pcalls=pcalls)

    def client(c):
        for p in payloads:
            c.sendall(struct.pack(">I", len(p)) + p)

    return run_pair(handler, client)


def d_oversize():
    def handler(conn, out):
        head, _ = recv_exact(conn, 4, 4096)
        (ln,) = struct.unpack(">I", head)
        limit = 1 << 20
        out["declared"] = ln
        out["limit"] = limit
        out["accepted"] = ln <= limit
        out["buffered_after_header"] = 0
        if ln > limit:
            return                       # 直接断开，不再按声明长度读
        recv_exact(conn, ln, 4096)

    def client(c):
        c.sendall(struct.pack(">I", 0xFFFFFFFF) + b"B" * 100)

    return run_pair(handler, client)

MAGIC = b"\xA5\x5A"


def encode_frame(payload):
    return MAGIC + struct.pack(">HI", len(payload), zlib.crc32(payload)) + payload


class MagicDecoder:
    """魔数 + 长度 + CRC32：丢字节之后还能重新对上"""

    def __init__(self, limit=1 << 20):
        self.buf = bytearray()
        self.limit = limit
        self.frames = []
        self.junk = 0
        self.crc_err = 0

    def feed(self, data):
        self.buf += data
        while True:
            i = self.buf.find(MAGIC)
            if i < 0:
                keep = 1 if self.buf.endswith(MAGIC[:1]) else 0
                self.junk += len(self.buf) - keep
                del self.buf[:len(self.buf) - keep]
                return
            if i:
                self.junk += i
                del self.buf[:i]
            if len(self.buf) < 8:
                return
            ln, crc = struct.unpack(">HI", self.buf[2:8])
            if ln > self.limit:
                self.crc_err += 1
                del self.buf[:1]          # 假魔数，往后挪一个字节重新找
                continue
            if len(self.buf) < 8 + ln:
                return
            body = bytes(self.buf[8:8 + ln])
            if zlib.crc32(body) != crc:
                self.crc_err += 1
                del self.buf[:1]
                continue
            self.frames.append(body)
            del self.buf[:8 + ln]


def plain_decode(stream, limit=1 << 20):
    """只有 4 字节长度、没有魔数和校验：一旦错位就再也回不来"""
    frames, i = [], 0
    while i + 4 <= len(stream):
        (ln,) = struct.unpack(">I", stream[i:i + 4])
        if ln > limit:
            return frames, i, "长度字段读成 %d，超过上限，只能断开" % ln
        if i + 4 + ln > len(stream):
            return frames, i, ("长度字段读成 %d，需要 %d 字节，流里只剩 %d —— 它开始等一个永远不会来的帧"
                               % (ln, 4 + ln, len(stream) - i))
        frames.append(stream[i + 4:i + 4 + ln])
        i += 4 + ln
    return frames, i, "流结束"


def e_resync():
    payloads = [bytes([0x41 + i]) * 24 for i in range(5)]
    plain = b"".join(struct.pack(">I", len(p)) + p for p in payloads)
    magic = b"".join(encode_frame(p) for p in payloads)
    # 第二帧 payload 中间删掉 3 个字节
    cut_plain = 28 + 4 + 5
    cut_magic = 28 + 8 + 5
    broken_plain = plain[:cut_plain] + plain[cut_plain + 3:]
    broken_magic = magic[:cut_magic] + magic[cut_magic + 3:]

    d = MagicDecoder()
    for i in range(0, len(broken_magic), 7):        # 每次只喂 7 字节，模拟串口的碎块
        d.feed(broken_magic[i:i + 7])
    return plain_decode(broken_plain), d, len(payloads)
```

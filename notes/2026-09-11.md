## 💭 技术随想：PID 闭环控制——P 踩油门、D 带刹车、I 补欠账

机器人关节要"转到 45° 就停在 45°"，无人机要悬得住，温控箱要"保持 25℃ 就是 25℃"——这些事背后站着同一个东西：**PID**。别被这个名字吓到，它不是什么高深算法，拆开看就是老司机开车的三个习惯。

先说说为什么非要闭环。开环就是"指令发出去，就当做到了"——可现实里负载在变、摩擦在变、电压在掉，电机收到的电压和它实际转出的角度之间，永远隔着一堆变数。闭环只有一句话：**干完活回头量，量完了再修**。PID 就是"怎么修"的三个答案：

- **P（比例）——踩油门**：现在差 10°，就给和 10° 成正比的劲，差得越多踩得越狠。它就是"误差放大器"。毛病有两个：恒定阻力下，必须留一点偏差才能顶得住（稳态误差）；油门踩太狠，冲过头、来回晃（超调振荡）。
- **D（微分）——提前带刹车**：它不看你偏了多少，只看你"正以多快的速度往回走"——快到了就提前收油，防止冲过头。开车进站那脚提前的点刹，就是 D。
- **I（积分）——补欠账**：差 1° 记 1°，差着就一直记；只要还差一点，I 的输出就还在长大，直到把最后那点差磨平——它的任务只有一个：把稳态误差熬到零。

性格配比决定手感：光有 P，快而不准；P+D，又快又稳，但总差一口气；三兄弟凑齐，才叫"指哪打哪"。而且 I 的脾气最犟：起步时误差大，它疯狂记账，到站了还得慢慢"还账"，一不留神就冲过头——所以工程上必须给积分限幅（anti-windup），这不是优化，是标配。咱们给电机下发的是"目标位置/速度"，真正把目标一层层逼近的，就是驱动固件里跑着的这三位。

## 🧩 今日代码片段：PID 三兄弟同台——同一台电机转 90°，三种调法

模拟一台带恒定负载的电机从 0° 转到 90°：① 保守 P（Kp=1）、② 激进 P（Kp=5）、③ PID（同样的 Kp=5，补上 I 和 D）。输出是每 100ms 采样的角度——重点看 ② 怎么"冲过头再晃回来"，③ 怎么"贴脸停车"。

```python
# ── PID 三兄弟:同一台带负载的电机转到 90°,三种调法 ──
# 模型: J·θ'' = u − b·θ' − τ_load   (u=控制器输出, τ_load=恒定负载力矩)

def simulate(kp, ki, kd, t_end=2.0, dt=0.001):
    J, b, tau = 0.02, 0.25, 5.0           # 惯量 / 阻尼 / 负载力矩(归一化单位)
    th, w, integ, prev_e = 0.0, 0.0, 0.0, 90.0
    hist = []
    for i in range(int(t_end / dt)):
        e = 90.0 - th                      # 离目标还差多少
        integ += e * dt                    # I:把"欠账"一点点记下来
        de = (e - prev_e) / dt             # D:误差在缩小还是扩大
        u = kp * e + ki * integ + kd * de  # P、I、D 三路加起来
        w += (u - b * w - tau) / J * dt    # 电机动力学
        th += w * dt
        prev_e = e
        hist.append((i * dt, th))
    return hist

A = simulate(1.0, 0, 0)      # ① 保守 P:只想慢慢来
B = simulate(5.0, 0, 0)      # ② 激进 P:P 开到最大,不要 I、不要 D
C = simulate(5.0, 0.5, 0.3)  # ③ PID:P 同样大,补上 I 和 D

print("  t(s)    ①Kp=1    ②Kp=5     ③PID")
for t_ms in range(0, 1201, 100):           # 每 100ms 打一行
    i = t_ms // 1
    v = [A[i][1], B[i][1], C[i][1]]
    print(f"  {t_ms/1000:4.1f}  " + "  ".join(f"{x:7.2f}" for x in v))

print()
names = [("①", A, "Kp=1"), ("②", B, "Kp=5"), ("③", C, "Kp=5 Ki=0.5 Kd=0.3")]
for tag, H, k in names:
    ths = [v for _, v in H]
    peak, fin = max(ths), sum(ths[-200:]) / 200
    print(f"{tag} {k:20s} 峰值 {peak:6.2f}°   2秒后落点 {fin:6.2f}°")
```

**说明：**

- 看 ① 列：一路稳稳地爬升，但最终停在 85.00°——永远差 5°。这不是代码写错了，是 P 的宿命：恒定负载 5 个单位拽着它，只有垫着 5° 的误差，`u = Kp·e` 才凑得出顶住负载的力。**光靠 P，永远"欠着一点"。**
- 看 ② 列：0.2s 上下冲到 111.9°（超调约 22°），然后 111→99→83.9→90.1→88.8 来回晃——P 开大反应是真快，但没有任何人负责"提前收油"，最后停在 89.00°，跳得最猛，照样差 1°。
- 看 ③ 列：峰值只有 90.29°（超调 0.29°）——D 项在飞速逼近时自动提前收油，几乎没冲过头；0.7s 后就一直钉在 90.00°，一分不差——I 项把那最后零点几度的欠账慢慢结清了。
- 公平性：② 和 ③ 的 Kp 完全相同（都是 5）——唯一的区别是 ③ 多了 D 和 I 两件工具。所以不是"PID 运气好"，是同样的马力下，多了一双预判的眼睛和一本不赖账的账簿。
- 工程要点：① D 项对噪声极其敏感——它算的是 `(e − prev_e)/dt`，编码器抖一下，微分项就爆表，实际代码里要先低通滤波再微分（或对测量值微分，而不是对误差微分）；② I 项必须防"积分饱和"——起步阶段误差大、积分越攒越多，到站后要还很久的债，实际要么给积分限幅，要么误差大时暂时关积分（积分分离）；③ 调参口诀：**先 P（决定多快）→ 再加 D（压住冲劲）→ 最后加 I（抹平残差）**，每次只动一个参数、动完看曲线；④ 控制周期 dt 要稳——dt 一抖，D 项跟着抖，硬件定时器定周期是有道理的。
